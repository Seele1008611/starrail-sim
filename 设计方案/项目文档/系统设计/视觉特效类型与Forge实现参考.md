# 视觉特效类型与 Forge 实现参考

本文是后续设计与技术选型的参考清单，不代表表中效果已全部实现，也不等于已承诺纳入某个版本。项目目标环境为 Minecraft 1.20.1、Forge；落地前须按当前映射、渲染阶段和整合包环境复核 API。

## 效果类型与常见实现

难度为相对估计：低（常用 API、范围清楚），中（需要自定义客户端渲染或同步），高（涉及帧缓冲、全屏管线、深度或复杂性能/兼容边界）。

| 类型 | 常见用途 / 例子 | Forge 1.20.1 常见实现方向 | 难度 |
|---|---|---|---|
| 粒子 | 火花、尘屑、治疗光点、命中碎片 | 客户端 `Particle` / `ParticleProvider` 渲染；`ParticleType` 与 `ParticleOptions` 表达类型和参数；服务端按需向附近客户端发送事件。粒子有生命周期、运动、碰撞/淡出等。 | 低–中 |
| 拖尾 / 轨迹 | 飞行物尾焰、挥砍弧、能量丝带 | 按连续时间采样位置，生成有宽度的带状网格或粒子串；处理断点、衰减、相机朝向与实体锚点。 | 中 |
| 自定义网格 / 程序化几何 | 光环、箭矢阵、盾面、波纹、符文 | `PoseStack`、顶点缓冲、`VertexConsumer` / `RenderType` 在世界渲染阶段提交三角形或四边形；深度测试、透明排序、顶点数需明确。 | 中 |
| Shader 材质 | 流动纹理、溶解、边缘亮线、噪声、热浪表面 | 自定义顶点/片元着色器与 `RenderType`，使用时间、UV、颜色等 uniform；优先提供无 shader 或加载失败回退。 | 中–高 |
| 泛光（Bloom） | 明亮网格外溢出的柔和光晕 | 将选定发光内容绘入独立目标，模糊后叠回画面；控制分辨率、模糊次数、强度和叠加事件数。它是屏幕图像处理。 | 高 |
| 屏幕后处理 | 局部折射、冲击扭曲、色散、短暂像素化、色调变化 | 帧缓冲/后处理 pass 采样场景颜色；需要深度或事件投影来约束作用范围，并处理窗口尺寸变化、资源重载、HUD/菜单边界与回退。 | 高 |
| 形变 | 生物呼吸/受击变形、能量团鼓胀、局部扭曲 | 在模型动画或自定义网格顶点阶段按时间/事件权重改变顶点或骨骼；避免改动服务器实体位置、碰撞箱或玩法判定。 | 中–高 |
| 模型 / 骨骼动画 | 生物待机、攻击招式、机关展开、武器动作 | 模型部件旋转/位移或自定义骨骼时间线；动画与服务器状态/动作事件同步，需考虑插值、取消、死亡和区块卸载。 | 中 |
| 贴花 / 表面标记 | 命中裂纹、地面法阵、短时污渍 | 在表面附近绘制带透明纹理的平面/网格，使用表面法线确定朝向；处理深度冲突（z-fighting）、墙面/斜面、透明排序、存活时间和清理。 | 中–高 |
| 环境特效 | 生物群落雾、飘雪/萤火、空间尘埃、环境光束 | 粒子/实体锚定网格与客户端环境渲染组合；按玩家附近范围、区块可见性和画质选项限量。改变全局天空、雾或光照时还需考虑其他模组覆盖。 | 中–高 |
| 物理模拟 | 抛射碎片、布带/链条摆动、液滴、弹性冲击 | 客户端轻量积分、弹簧或粒子系统近似运动；明确碰撞、固定步长、休眠与数量上限。视觉模拟不作为命中或服务器状态依据。 | 中–高 |
| 动态光照 | 手持/爆发光源照亮邻近方块、实体并随距离衰减 | 原版 `packedLight` / 光照贴图主要读取既有世界光照；真正随效果移动的局部动态灯光通常需要额外光照/渲染方案，须核查 Forge 1.20.1 兼容性、阴影和性能。 | 高 |

## 易混淆的光效概念

- **自发光材质**：物体本身画得更亮，或不受普通场景明暗影响；不会自动照亮邻近方块。
- **泛光 / Bloom**：画面中高亮部分向外模糊扩散，形成轮廓外光晕；不会自动改变世界光照或生成真实阴影。
- **动态光照**：局部光源影响其他表面明暗，光照可能随位置变化。通常需要灯光采样/额外渲染支持；仅把粒子画亮、调高顶点颜色或叠一层光晕都不等于动态光照。
- **屏幕染色 / 扭曲**：改动相机画面中的像素颜色或坐标，是后处理表现，不是世界中的灯光或实体。

## 当前项目的落地参照与边界

当前源码可见自定义战斗网格与 `RenderType`（`StarRailCombatMesh`）、材质 shader 注册与回退（`StarRailCombatShaders`）、战斗后处理目标（`StarRailCombatPost`），动物/构造体模型也有自定义顶点输出；源码同时使用原版粒子类型。它们可作为后续效果工作的本地参照，不应据此推断其他表格项已经接入。

Forge 官方粒子文档说明了类型/参数的双端定义与客户端 Provider 的职责划分；网络效果应让服务端事件携带必要参数，由客户端负责绘制。Photon 页面列出的编辑/表现方向可作为效果类型灵感来源；Photon 自身功能和 API 不自动适用于本项目，实际实现必须按 Forge 1.20.1 核对。

## 设计与验证要点

1. 先写清触发事件、世界锚点、动作阶段（蓄势/爆发/余波）、持续时间、取消条件，以及普通/强化版差异；移动目标跟随目标，实体消失后用事件位置回退。
2. 将玩法事实与客户端外观分开：服务器负责命中、伤害和权威状态；客户端负责粒子、动画、网格和屏幕表现。需要多人可见时明确广播范围、频率和事件过期处理。
3. 分别验证单人和多人、第一/第三人称、目标移动与墙体遮挡、粒子画质档、窗口缩放、暂停/恢复、资源重载、切维度及退出重进。检查空闲时资源释放、效果叠加、低端画质回退、帧率/绘制成本和日志错误。
4. 对 shader/后处理检查加载失败与切换基础模式后的回退；对贴花检查表面夹角和闪烁；对物理模拟检查数量上限、帧率变化下稳定性及区块卸载清理；对动态光照单独检查光照传播和阴影表现。
5. 记录状态时分开写“方案”“代码接入”“编译/静态检查”“游戏内视觉验收”“多人验收”。技术可行、编译通过或预览成功均不能替代用户实机验收。
