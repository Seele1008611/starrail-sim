# 属性上限扩展与玩家状态栏方案

日期：2026-10-10。归入本地1.9.0开发范围；当前正式版仍为1.8.0。

状态：用户同意建设方向及采用 AttributeFix 的上限；本文件及紧凑 HTML 原型已更新，六项自定义属性上限已修改注册代码；五项原版属性扩展、游戏HUD和新防御公式尚未接入。此前九命途平衡调整独立保留。

## 一、依据与全部原版属性核对

直接核对 AttributeFix **1.20.1 分支**的 [AttributeConfig.java](https://github.com/Darkhax-Minecraft/AttributeFix/blob/1.20.1/common/src/main/java/net/darkhax/attributefix/config/AttributeConfig.java)。其默认覆盖表只包含下列五项，其他范围属性登记到配置时保留原声明上下限；不能将“属性修复”理解成全部属性默认统一百万。

原版数值从项目已有 Forge 1.20.1-47.4.10 的映射缓存中 Attributes 字节码核对，无新增依赖。

| 原版属性 | 原版范围 | 本模组默认范围 | 处理理由 |
| --- | --- | --- | --- |
| 最大生命值 | 1～1024 | 1～1,000,000 | 对齐 AttributeFix |
| 护甲值 | 0～30 | 0～1,000,000 | 对齐 AttributeFix |
| 护甲韧性 | 0～20 | 0～1,000,000 | 对齐 AttributeFix |
| 攻击力 | 0～2048 | 0～1,000,000 | 对齐 AttributeFix |
| 攻击击退 | 0～5 | 0～1,000,000 | 对齐 AttributeFix；提高容许上限不增加基础击退 |
| 移动速度 | 0～1024 | 保留 | 已充足；不提高玩家基础速度 |
| 飞行速度 | 0～1024 | 保留 | 已充足 |
| 攻击速度 | 0～1024 | 保留 | 已充足；受攻击冷却及游戏tick实际约束 |
| 击退抗性 | 0～1 | 保留 | 比例属性，1代表100% |
| 幸运 | -1024～1024 | 保留 | 与 AttributeFix 默认一致 |
| 索敌范围 | 0～2048 | 保留 | 生物属性，无玩家后期成长需求 |
| 僵尸增援概率 | 0～1 | 保留 | 概率属性，不能当成普通成长数值 |
| 马匹跳跃力量 | 0～2 | 保留 | 坐骑专属属性，与玩家成长分开 |

最低值、基础值及现有修正类型不变。百万是可存储的合法上限，不是成长目标，不授予任何属性或践行度。

### 本模组自定义属性

按用户2026-10-10最新指定，覆盖先前保留自定义属性范围的方案：

| 自定义属性 | 修改前代码上限 | 已接入的新上限 | 内部比例值 |
| --- | --- | --- | --- |
| 暴击率 | 100% | 100%，超出不转换 | 1.0 |
| 效果命中 | 1000% | 100%，超出不转换 | 1.0 |
| 效果抵抗 | 1000% | 100%，超出不转换 | 1.0 |
| 暴击伤害 | 1000% | 1,000,000% | 10,000.0 |
| 击破特攻 | 1000% | 1,000,000% | 10,000.0 |
| 治疗效果（效果治疗） | 1000% | 1,000,000% | 10,000.0 |

三项100%上限的属性按最终合成值限制在1.0，不把超出部分转换为其他属性。三项百万百分比属性的内部值为10,000，而非1,000,000；显示时比例乘100转换为百分数。基本属性、现有装备修正和常驻成长额度不变。这些自定义上限是用户指定扩展，独立于AttributeFix的五项原版覆盖，即使同时安装AttributeFix也应应用。

### 不是 Attribute 的状态

- 饱食度：原版0～20，保留。
- 饱和度：原版正常进食结算时不超过饱食度，保留；原型分别显示当前值和当前饱食度上限。
- 伤害吸收：1.20.1 使用实体吸收生命状态，不属于上述五项范围属性。读实际吸收生命，不杜撰一个固定“最大吸收值”。当前命途护盾额度仍按其能力规则计算。
- 氧气、经验、药水时间、命途层数：各自有独立规则，不参与百万属性扩展。

## 二、属性扩展的实现安排

1. 扩展原有 RangedAttribute 对象的最大值，保留注册ID、修正UUID及原版同步路径。原版注册属性范围共享于实体，五项放宽对拥有这些属性的生物也有效。
2. 在实体属性实例投入运行之前完成修改，并在客户端与服务端一致加载；服务端为实际结算权威。不以 HUD 显示值代替属性真实值。
3. 建立按注册ID的配置表，默认只覆盖上述五项。额外属性可以明确配置；不扫描后无差别修改所有第三方属性。
4. 与同时安装 AttributeFix 的环境协调：检测其存在后，交由 AttributeFix 管理范围，本模组不再次覆盖其自定义上限；HUD正常使用最终属性值。未安装时使用内置扩展，无强制新增依赖。
5. 实现前检查已有 Forge 的 Access Transformer / Mixin 能力，使用现有构建缓存；若必须新增或下载组件，按用户要求先询问。
6. 修改范围是启动阶段行为；配置需要重启生效。旧存档原有等级、装备、能力和材料数据保持正常读取。

## 三、防御收益方案（已接入，待游戏验收）

原版 CombatRules 护甲减伤最高80%；护甲范围放宽不会自动改变这条公式。设计目标：原版范围内行为保持一致，超过原上限后仍有递减收益，高护甲不能直接变为完全免伤。

建议默认仅对玩家生效，可配置切回原版。生物继续原版减伤计算，避免监守者等整体难度突然改变。以下是一版可核对的公式，不属于 AttributeFix 默认行为：

```
D = 进入护甲结算的伤害
A = 非负实际护甲；T = 非负实际韧性
A0 = min(A, 30)；T0 = min(T, 20)
R0 = clamp(A0 - D / (2 + T0 / 4), A0 * 0.2, 20) / 25
E = max(A - 30, 0) + max(T - 20, 0) * 0.5
R = E == 0 ? R0 : 0.95 - (0.95 - R0) * 80 / (80 + E)
护甲结算后的伤害 = D * (1 - R)
```

| 输入伤害 / 护甲 / 韧性 | 建议护甲减伤 | 说明 |
| --- | --- | --- |
| 20 / 20 / 8 | 60% | 与原版一致 |
| 20 / 30 / 20 | 80% | 与原版一致 |
| 20 / 60 / 20 | 84.09% | 超限护甲仍有收益 |
| 20 / 100 / 40 | 87.5% | 护甲和韧性额外收益递减 |

0.95、80和韧性权重0.5作为初始配置；95%仅为护甲这一环节的渐近上限，抗性及附魔等后续环节仍可能继续降低伤害。面板不显示一个固定“总减伤率”，因为它随入射伤害和其他状态变化。

必须在原版护甲计算位置替换一次计算，不能在 LivingHurt 中再减一次、随后仍叠加原版护甲。绕过护甲的伤害保持绕过；附魔、抗性、吸收生命、致命救援及真正生命损失的后续顺序保留，核对现有践行度凭据没有重复统计。

## 四、状态栏布局

原型：[玩家状态栏设计图](../../UI设计/1.9.0玩家状态栏原型/玩家状态栏设计图.html)。本地 HTML/CSS/JS，无外部字体、库或下载素材，沿用命途图标和已接受的九命途配色。

默认固定在经验条上方，与主快捷栏左右边界对齐；可选择左下角。文字用轻阴影保证可读性，细条保持生命绿、护盾蓝，低血转红。原型宽度等于主快捷栏（标准300px，窄画面260px），高度进一步由44px压缩为28px，采用两行浮动读数；移除整块背景与边框，不与左侧副手槽重叠。

- 仅显示玩家当前生命、吸收生命、护甲、护甲韧性、饱食度、饱和度及情境状态，移除命途图标、命途名称、阶位、技能层数和冷却行。
- 生命：当前/最大数值和独立主条，受伤时延迟残影，治疗时平滑增长。
- 护盾：真实吸收生命单独读数与生命条下沿的独立蓝色细线，不混入生命百分比；值为零时隐藏对应读数和细线。仅相对最大生命值画比例，超出时条长度封顶，读数保留完整实际值；并标明“伤害吸收”，不称为最大护盾。
- 护甲/韧性：小图标及真实数值，无没有确定上限的满条。
- 饱食度/饱和度：共用一个紧凑显示区域，饥饿条下沿附加浅绿饱和度细线，两者以20为共同绘制参考。保留各自当前数值；饱和度仍受当前饱食度上限约束，原型悬停提示显示完整解释。
- 氧气：仅水下或氧气未满时出现；骑乘时显示坐骑生命，蓄力跳跃单独显示。
- 经验/快捷栏：保留原版位置与玩法；不替换或遮盖快捷栏选择、主副手和攻击充能。
- 全程采用紧凑布局，提供经验条上方/左下角位置、75%～100%缩放及原版显示回退。缩放上限不能使状态栏高于参考区域；水下与骑乘信息放入同一底部细行，不额外向上堆行。
- 创造模式不显示无意义的生存生命/饥饿栏；旁观模式隐藏玩家状态面板；F1隐藏全部自定义HUD。
- 不隐藏原版药水图标、Boss条和其他未替换元素。新HUD关闭时完整恢复原版生命、护甲、饥饿、空气和骑乘条。

原型具备前后期预设、受击/治疗/护盾模拟、水下/骑乘/创造与旁观预览、缩放及位置调整；状态栏与玩家命途无关。所有读数为预览数据，不作为游戏数值验收结论。

## 五、客户端与网络

大部分读数取客户端已同步实体状态；护甲和韧性读取实际属性，不调用带整数截断的护甲展示接口。饱和度需要专项同步，不能依赖原版饥饿更新包总是携带真实小数值。

必要时服务端每5tick检查饱和度变化，仅发送给所属玩家；进入世界、复活、切维度时完整同步，退出时清缓存。玩家状态栏不展示命途技能信息，不在客户端触发能力或计践行度。

HUD平滑只影响视觉；低血提示、危险状态及能力门槛依据最新真实值。大量数字用千位分隔，在紧凑模式允许K/M缩写并可切精确显示；不因宽度溢出隐藏单位或截断数值。

## 六、实施顺序与验收

1. 当前阶段：原型已确认，原版范围扩展、防御公式、HUD与饱和度同步已接入，等待游戏内验收。
2. 放宽五项原版属性上限，并应用用户指定的六项自定义属性上限，补配置与兼容策略，离线编译。
3. 接入状态栏和必要同步，提供原版回退设置。
4. 在既定护甲结算位置接入防御方案；重新核对技能、护盾、救援与践行度。
5. 用户游戏内统一验收：正常成长；生命>1024、护甲>30、韧性>20、攻击>2048、击退>5的真实值；旧存档、死亡、重登、切维度；九命途/无命途；不同GUI缩放和屏幕比例；水下、骑乘、创造、旁观、F1；HUD回退；第三方AttributeFix兼容；多人权威同步。

自动测试或客户端启动只在用户提出时进行。现有1.9.0平衡调整仍需游戏内验收，两者不能混记为已通过。最终版本发布时整理统一变更说明。

## 七、状态栏减负参考（2026-10-10）

此次浏览作者项目介绍，用于提取布局思路，没有下载模组、贴图或新增依赖：

- [AppleSkin官方仓库](https://github.com/squeek502/AppleSkin)：在现有生存HUD中补充饱和度等信息。采用同区域细线补充饱和度，避免给每项信息增加独立大行。
- [Minimalist Dynamic HUD作者页面](https://www.curseforge.com/minecraft/mc-mods/minimalist-dynamic-hud)：按游戏情境减少HUD元素。采用吸收生命为零时隐藏、水下和骑乘信息按需出现；生命和饥饿信息保持显示。
- [RPG-Hud作者页面](https://www.curseforge.com/minecraft/mc-mods/rpg-hud)：参考其生命、饥饿等数值化HUD方向；本项目使用两行薄布局，不增加人物头像、等级或命途标题。

上行生命与饥饿；左下行仅放非零吸收生命、氧气和坐骑信息，右下行在饱食度条下方放护甲值及护甲韧性，与上下两组条形左右对齐。几何尺寸缩小的同时保留9px读数；移除重复标签、整块底板、分隔线及每项单独面板，减少遮挡和视觉重量。HTML已确认，游戏HUD已接入、待验收。

2026-10-10继续细化：保留28px高度和主快捷栏宽度；护甲/韧性移到右半区，左半区保留生存情境。条尾增加细亮边，读数使用等宽数字；生命受击、吸收生命受击、治疗和进食各自反馈，不整块闪光。生命≤25%时心形轻微脉动，饱食度≤6时食物提示转暖色；新增低血预览按钮。减少动画偏好时停止脉动及局部闪动。

骑乘跳跃蓄力进一步压缩为2px高、主快捷栏宽度28%（最多84px）的短条，利用经验条上方左侧既有间隙，不增加快捷栏容器高度，不顶高玩家状态栏；取消整行文字，保留悬停说明和无障碍读数。

整体收尾：数字与图标的轻阴影和颜色统一，空条取消尾端亮点；低氧气和低坐骑生命显示暖色提示，满血治疗不播放虚假的恢复闪动。骑乘跳跃短条改为交互式充能预览，初始0%，充满后归零。位置取整减少细线模糊，尺寸仍为28px；游戏内实现时按实际跳跃充能进度绘制。

## 八、游戏接入（2026-10-10）

- `StarRailPlayerStatusHud`：两行透明布局，按原版主快捷栏182 GUI单位适配；主体高度20单位，骑乘短条占用既有间隙，总高度24单位。默认经验条上方，无命途标题。生命残影、治疗/吸收变化/进食局部提示及低生命/饥饿/氧气/坐骑生命配色已接入。像素图标直接绘制，不增加图片、字体或运行依赖。
- 实际生命、伤害吸收、护甲与韧性均读取实体/属性；吸收值非零才显示独立数值及蓝色细线。水下显示剩余氧气秒数，骑乘显示坐骑当前/最大生命；两者使用同一底行，不堆高面板。跳跃读取真实充能，短条51×2单位；骑乘时保留经验条和等级。
- `PlayerStatusPacket`、`StarRailPlayerStatusSync`：饱和度每5tick检查变化，仅发送所属玩家。登录、复活、切维度发全量；客户端新世界/新玩家就绪后额外请求快照，避免初始包早于实体就绪而漏显示。请求按玩家限频，校验发送者和当前维度；退出清缓存，跨维度旧包丢弃。协议升级为10。
- `StarRailAttributeLimits`：公共初始化、创建世界前放宽现有范围；使用已核对的1.20.1字段，不替换注册对象。默认五项最大1,000,000，同时安装AttributeFix时不接管其范围配置。六项自定义属性保持本方案指定上限。
- `PlayerArmorMixin`：仅替换原版护甲结算中的CombatRules调用；超出护甲30或韧性20时对玩家启用递减收益。原版范围内、生物及关闭该配置时使用原版公式；绕过护甲、装备损耗、抗性/附魔、吸收生命和后续事件顺序保留。
- Mixin处理器使用Forge现有编译缓存，构建自动生成MCP→SRG映射及refmap；开发运行参数与发布jar清单均声明Mixin配置。未新增Gradle插件、依赖坐标或下载。

### 配置和回退

- 默认 **F8** 在模组HUD/完整原版HUD之间切换并保存，可在按键设置中重新绑定。
- `config/starrail_sim-client.toml`：`playerStatusHud` 开关；`leftCorner` 左下角；`scale` 0.75～1.0；`exactNumbers` 精确数值。默认大数K/M缩写，精确模式保留完整数值并适配宽度。
- `config/starrail_sim-common.toml`：`extendVanillaLimits` 和 `attributeMaximums` 注册ID配置表，重启生效；多人自定义上限须让两端一致。额外注册ID须显式添加，不默认放宽其他模组属性。
- 世界 `serverconfig/starrail_sim-server.toml`：`extendedPlayerDefense` 可回退原版；`armorReductionCeiling` 默认0.95，`excessArmorCurve` 默认80，`excessToughnessWeight` 默认0.5。Forge同步服务端规则。

离线 `classes` 构建通过，包含Java编译、资源处理和Mixin refmap生成；沿用已有Curios等弃用警告。尚未启动客户端验收。原型认可不等于实际游戏已通过；多人、与AttributeFix共同加载以及超限防御实战仍待用户验收。

### 游戏截图反馈后的辨识度调整

用户已开始HUD验收，尚未完成。截图反馈指出数字与图标相距过远、镂空图标不清晰、条形太细。对应修改：

- 所有读数改为紧跟各自图标左对齐；剩余宽度只用于限制长数字，不再将数字推到区域右端。氧气、坐骑与伤害吸收采用同一规则。
