# 料理台 JEI 适配

2026-11-05：朋友测试时不知道料理台及其配方，用户要求适配 JEI。此次为 1.27.0 追加发现入口与自定义配方展示，不修改料理结算、食材数量、营养或既有 UI 数值统计。

## 接入范围

- 采用 Forge 1.20.1 的 JEI 15 API，编译基准 15.20.0.106。JEI 是可选客户端依赖；插件类仅在 `client/jei` 中由 JEI 发现，模组入口和服务端不引用插件。开发运行可用 `-PenableJei=true` 加载 JEI，发行包不内嵌 JEI。
- 注册“命途料理台”分类，从客户端收到的 RecipeManager 获取全部 `starrail_sim:kitchen` 配方，包含当前 38 条炖、蒸、煎、干制、烘烤配方及旧食物接入。没有另外复制一份固定配方表；数据包更改随游戏实际配方显示。
- 每页显示六格原料及实际数量、可复用厨具、工序、每批时间、成品数量、加工时返还的容器。厨具为 CATALYST，煤仅为 RENDER_ONLY 燃料示例，不误报为固定配料或每菜消耗一块煤。
- 料理台注册为该分类的工作站，可从食物配方追查所需设备；料理台进度条区域可点击打开 JEI 料理分类。料理台、锅、煎盘各有 JEI 说明页，料理台物品悬浮提示也补充放置/交互与厨具用途。
- 现有工作台、熔炉、烟熏炉等原版类型配方交给 JEI 原有分类，不重复注册。当前为查询展示适配，按页面手动放料、选菜和开火。

## 验证与交付

- 自定义配方数据核对：38 条，炖 11、蒸 5、煎 17、干制 3、烘烤 2；11 条带加工返还物。输入最多六种，返还最多两格；中文和英文 13 个新增说明键与工序标签齐全。
- Java 17 / Gradle 8.8 离线编译通过。既有 Curios 弃用警告仍在。
- 本机原缓存没有 JEI API；仅为这次新兼容功能获取官方 common-api（117,795 字节）和 POM，缓存在工作区 `.gradle/jei-maven`，不随模组分发。未重装或下载 Java、Gradle、Forge。已有缓存可供后续离线构建。
- 测试包 `libs/starrail_sim-1.27.0-test50-kitchen-jei.jar` 已离线构建通过（30 秒），大小 22883678 字节，SHA-256 `d8267755fa8249a77ab539579491ad44166e4879cf65aed998b4963b0608c877`。ZIP 完整性、JEI 可选客户端声明、双语资源、插件类已核对。对比 test49，400 份配方文件及全部贴图/模型/声音均字节一致，只增加两个 JEI 客户端类并修改料理台提示、公开注册引用、双语文本和版本元数据。全量编译类中仅两个兼容类引用 JEI API，发行包未内嵌 JEI。JEI 游戏界面、未装 JEI 的启动和专用服运行未实机验收，不提前记录通过。

## 实机检查

1. Minecraft 1.20.1 Forge 客户端安装对应 JEI 15.x（本次编译基准 15.20.0.106），替换模组测试包，进入世界后打开背包搜索“大宇宙炒饭”或“宝石蜥肉串”。鼠标悬停按 JEI 的查看配方键（默认 R），应出现“命途料理台”分类。
2. 食物页能看到原料数量、锅/煎盘、工序、秒数和成品数量；对“热浮羊奶”确认杯×2、成品×2以及空桶/空瓶返还，厨具标注不消耗。
3. 查看料理台本身的合成和说明页，再查看料理锅/煎盘的合成。新玩家应能从一道食物反查到设备制作与使用方法。
4. 对原料按用途键（默认 U）可找到使用它的料理；锅与煎盘也能通过用途查询到对应配方。煤不应被本分类列成所有菜的固定配料。
5. 打开实际料理台，点击原料和成品间的进度区域，应进入 JEI 料理分类；返回后仍能用原下拉菜单选菜、正常连续加工。JEI 页面不是自动开火按钮。
6. 冷调食物、预制料及烤制食物在工作台/熔炉/烟熏炉分类查询，不能凭空出现重复料理台配方。
7. 联机时只在客户端安装 JEI 也应能读取服务端同步的料理配方；另测试未装 JEI 的客户端正常启动、料理台原功能可用。专用服不要求安装 JEI。

参考：[JEI 官方 API 仓库（1.20.1）](https://github.com/mezz/JustEnoughItems/tree/1.20.1/CommonApi)。按项目 `mc-compat-jei` 技能与 Minecraft MCP 接入要点核对，实际签名以下载的官方 API JAR 和编译结果为准。
