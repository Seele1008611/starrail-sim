# 1.27.0 内容一：武器/工具拖尾与测试

日期：2026-11-01。用户认可test3九命途深化；test4基础拖尾获“效果不错”反馈，但用户提供参考图，明确希望使用着色器能量刃光。当前已实现test5专用拖尾材质与泛光，构建、GPU材质检查和包核验通过，游戏视觉待验收。下文先保留test4实现基线，最新包与测试见末节。

## 实现范围

- 曜金、霞铜、曦铁、星镞、星琼、古老梦华六系列，各有剑/镐/斧/铲/锄，再加虚质裂界刃，共31件。已逐项核对31个模型文件存在。
- 在ItemRenderer的实际手持渲染链中记录实体/手别/显示上下文，在烘焙模型绘制入口取得最终物品变换；采样位置包含当前模型显示变换、动画、相机及手部运动，而不是根据玩家朝向拼出一条假定挥砍弧。
- 每种工具在现有模型归一化坐标内选两点代表工作部位：剑为刀身，镐/锄取较宽头部，斧/铲取刃面。采样两点的历史运动，连续连接成带状轨迹；模型上的具体点位和宽度仍需实机观察后调整。
- 外层浅色带、材质主色带、细亮边形成分层，裂界刃另有暗紫分裂带。六系列分别使用金、铜、银、青蓝、粉玉和紫蓝色系。当前是无光照衰减的基础色几何与半透明叠层，不宣称已实现额外HDR泛光或动态照明。
- 第一人称尾迹约0.14秒、第三人称约0.175秒，第一人称适当降低强度。粒子最少档最多7个历史点，其余档16个；记录总数上限128，按时间、动作段和位移限制采样。
- 主副手分别记录，只在游戏实际挥动的那只手上生成；普通攻击、空挥与挖掘均可有挥动轨迹，使用物品期间不额外画攻击轨迹。没有新加命中闪光或伤害事件，空挥不会伪造命中反馈。
- 换物品、死亡、传送位移异常、切视角或换维度断开轨迹；停挥后短时淡出，连续挖掘的每个挥动段不会与下一段乱连。GUI、地面掉落物和原版工具不纳入。

## 渲染与客户端边界

新 `ItemRendererTrailMixin` 只加入mixins配置的client段，复用Forge随附Mixin。通过Minecraft MCP确认1.20.1手持渲染签名，并用本地映射JAR字节码核对第三人称物品层、第一人称手持渲染均进入相同物品渲染链，及模型变换的实际应用顺序。

轨迹使用独立BufferBuilder，在当前物品绘制方法结束时提交；不切换/终止物品正在使用的共享顶点缓冲。世界历史点根据当前相机与渲染矩阵转换回当前绘制坐标，第一/第三人称分别跟随本次投影；深度测试开启，轨迹不写深度，提交后恢复shader。没有新增网络包，其他玩家轨迹依据客户端已有的玩家位置与挥动同步绘制；多人实际效果仍待验证。

关键文件：`StarRailHandTrails.java`、`ItemRendererTrailMixin.java`、`starrail_sim.mixins.json`、`StarRailStatusConfig.java`、`StarRailCombatPreviewCommands.java`及中英文语言JSON。

## 配置与指令

默认开启。客户端配置display段增加 `handTrails` 与 `handTrailStrength`，强度范围0.25–2。指令：

```text
/starrailvfx trails false
/starrailvfx trails true
/starrailvfx trailStrength 1
/starrailvfx status
```

开关拖尾会清理历史；status增加开关、强度及手部采样记录数量。该数量不是绘制面数或GPU耗时。拖尾使用基础渲染器，因此命途basic/enhanced开关不控制拖尾；用上面的独立指令对照。

## 游戏测试方法

1. 在已有Forge1.20.1实例替换旧模组JAR，先确认能进入世界。
2. 第一人称拿一把新增剑空挥、攻击，再拿镐/斧/铲/锄挖掘或攻击。轨迹应贴着实际工具头/刀身，停止挥动后迅速消散；不能仅走路、转头或站立就出现拖尾。
3. 按F5观察第三人称，左右转向、移动和连续攻击。确认轨迹没有固定在屏幕或世界某处，不穿墙出现，也没有长距离拉线。
4. 六系列各五件加裂界刃逐项看形状与颜色；重点检查镐/锄头部宽度、斧/铲刃面，以及裂界刃紫色分层。若轨迹没有贴合，反馈具体物品名与视角。
5. 切换主手左右设置再重复。副手按游戏实际可执行的挥动/交互测试，主手攻击不应让未挥动的副手凭空出现轨迹。
6. 对照trails开关与trailStrength强度。切工具、收起物品、传送、切维度、暂停恢复、F3+T以及切换第一/第三人称，检查是否有悬空残影。
7. 粒子最少/全部分别连续挖掘，观察稳定性及帧率；回归一个命途预览，确认拖尾开关没有影响命途效果。多人有环境时再检查另一位玩家的左右手与挥动同步。

内容一进入阶段验收与调整，内容二怪物模型/动作及内容三怪物战斗特效尚未开始。

## test5：着色器能量刃光（当前）

方向由用户参考图与明确指示确定：宽而渐隐的能量弧面，亮刃缘、内部流动、尾部破碎消散和外溢泛光。仍覆盖原31件并沿实际挥动采样，各系列保持自身配色，不统一改为参考图的青绿色。

### 本轮实现

- 专用 `hand_trail` GLSL150材质，以沿尾迹年龄/横跨刃面两维坐标控制柔边、流动噪声、细丝、刃缘和溶解；裂界刃使用独立的紫色分裂纹参数。材质由 `StarRailTrailShaders` 注册，加载失败回退到基础色带。
- 同动作段内采用限幅样条细分，平滑历史点之间的弧面，最大偏离线性采样6厘米；不跨动作段连接。增强版第一人称约0.19秒、第三人称约0.24秒，最少粒子档每段1片，其他档3片；历史点按寿命分配采样间隔，上限10/24点。
- 不仅用透明宽边模拟光晕：将发光弧面重绘到既有HDR目标，经降采样模糊与屏幕合成得到轮廓外泛光。世界拖尾在AFTER_LEVEL末尾集中处理，手部拖尾在GameRenderer手部绘制完成后、HUD之前集中处理；使用各自捕获的投影和相机数据。
- 复用共享后处理目标/预算，新增独立启用参数而保留原命途调用语义；每个有拖尾的视角批次增加模糊/合成3次全屏绘制，同一帧同时有世界/手部拖尾可增加6次，叠加命途则另计。没有活跃拖尾不调用这条额外合成，最多64个绘制记录、4096片发光重绘预算。游戏中的实际开销尚未测量。
- `GameRendererTrailMixin` 仅放在client段，注入点按本地1.20.1映射核对，refmap已生成。投影、shader和原管线渲染状态在提交后恢复。资源重载会重置材质与拖尾历史。

### 本轮测试

替换test4后，先开着色器拖尾，再拿星镞剑或裂界刃在稍暗与白天场景各挥动一轮，观察是否形成连续渐隐的能量弧面；刃缘应清楚，内部有流动纹和消散，泛光越出弧面边缘。

```text
/starrailvfx trails true
/starrailvfx trailShader true
/starrailvfx trailStrength 1
/starrailvfx status
```

对照回退：

```text
/starrailvfx trailShader false
/starrailvfx trailShader true
```

`trailShader` 独立于命途basic/enhanced开关；关闭时回到基础色带。共享后处理的总强度仍受现有combatEffectStrength影响，拖尾自身强度用trailStrength调整。

重点检查：第一/第三人称、主手左右设置、六系列与工具类别、移动/转身、连续挖掘、传送/换维度、F3+T、不同粒子档位，以及同时触发命途效果。HUD文字不应被处理，世界或物品不能消失、变黑或残留亮块；再观察帧率与开关差异。先确认新视觉方向与投影正确，再按反馈调整宽度、寿命和亮度。
