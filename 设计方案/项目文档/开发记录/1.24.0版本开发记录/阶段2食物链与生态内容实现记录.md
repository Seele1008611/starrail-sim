# 1.24.0 阶段 2：食物链、作物和生态方块实现记录

日期：2026-10-26。状态：**用户已复测最新测试包，确认星薯和静潮稻各阶段贴地正常、其他阶段内容无问题；阶段 2 验收通过。未运行自动化测试。**

## 本阶段内容

- 新增星薯四阶段作物、种薯、星薯和烤星薯。星薯可在星砾高地的原生地表自然生成；成熟野生植株提供作物和种源，玩家也能在耕地种植。
- 新增静潮稻八阶段作物、种子、稻谷粒和泽米。自然稻仅在湿地岸边生成，种植与野生植株都要求附近存在水体。
- 新增星辉菇方块、可食用的星辉菇和烤星辉菇。菌株可放置在命途遗境的腐殖土、泥土或石质基底，低亮度环境允许其缓慢扩繁。
- 新增迎风灌木与静潮根簇，分别加入星砾高地和静潮泽地的低密度自然生成。
- 注册晴穗肉、林泽肉、泽纹禽肉及对应熟肉，供阶段 3 接入动物掉落。当前六种肉类放在食物创造栏中，阶段 2 可独立查看配方与数值。
- 为三种植物食材和三种动物生肉各加入熔炉、烟熏炉、营火烹饪配方，共 18 条配方。
- 增加对应方块状态、方块与物品模型、战利品表、中英文名称和客户端 cutout 渲染层。

## 检查结果与边界

- Minecraft MCP 已确认项目为 Forge 1.20.1；查验 `FoodProperties.Builder.meat()`、`CropBlock.getMaxAge()` 和 `CropBlock.getBaseSeedId()` 的 1.20.1 方法摘要。
- 本地解析 `src/main/resources` 下 1,145 个 JSON 文件，解析失败 0 个；模型纹理与父模型路径交叉检查缺项 0 个。
- MCP 全项目资源扫描给出大量既有纹理警告，与本地逐路径检查不一致，因此不把它当成本阶段贴图缺失结论。MCP 项目结构检查还报告 `mods.toml` 中 `${mod_id}` 未展开；这是 `build.gradle` 的既有 `processResources` 配置负责替换的占位符，不是本阶段改动。
- 首轮编译发现两种作物方块将 `ItemLike` 导入为 `net.minecraft.world.item.ItemLike`；已按 Forge 1.20.1 API 改为 `net.minecraft.world.level.ItemLike`。
- 用户用首轮测试包启动时，日志指出星薯作物的 `AGE_3` 未加入方块状态定义，导致注册失败。现已为星薯与静潮稻分别将自定义年龄属性加入状态定义，避免同类问题。
- 用户测试前一包时报告：星脉洞窟没找到星辉菇，且星辉菇不能手动放在泥土、腐殖土和石质基底；星薯与静潮稻重种后和耕地之间有可见空隙。
- 星辉菇修复：手动放置不再受亮度限制，但自然扩繁仍限于低亮度；可用基底扩展到命途腐殖土、泥土、石头及对应原版土石方块。世界生成配置纳入泥土与腐殖土，将分布高度上限从 Y=62 调整到 Y=384、每区块尝试数从 2 调整到 6、向下搜索步数从 12 调整到 24，并把特征放入洞窟植物装饰阶段。
- 作物贴图/模型修复：第一版将星薯与静潮稻的 12 个阶段模型调整到 Y=-2..14 后，用户仍观察到部分阶段有空隙。检查阶段贴图后发现茎秆的中心接地区域延伸至第 13 行；共用模型现进一步调整到 Y=-3..13，使贴图下方两行进入耕地方块、茎秆接触耕地表面。最新包等待用户复测。
