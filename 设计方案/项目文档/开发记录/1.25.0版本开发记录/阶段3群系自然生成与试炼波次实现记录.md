日期：2026-10-29。阶段状态：**源码与资源配置实现完成；静态核对通过；首轮测试包启动崩溃后已修复模型资源；用户复测上一水域包仍未观察到水面/大型水域虚卒。本轮定位到确定拦截条件并修改水面生成谓词；最新包离线 `compileJava` 与 `reobfJar` 成功，但尚未由用户实机复测。** 水面实际生成与密度、海洋生存表现或 Boss 回归均未验收。

## 一、实现范围

- 使用 Forge/Minecraft 1.20.1。Minecraft MCP 版本目录已确认只提供 Forge `1.20.1`；官方 API 查询确认 `MobSpawnSettings#getMobs(MobCategory)` 返回加权刷怪列表、`SpawnerData` 字段为 `type / weight / minCount / maxCount`，Forge 1.20.1 使用 `SpawnPlacementRegisterEvent` 注册自定义实体生成放置。
- 七个命途遗境群系的 biome 资源直接定义 `spawners.monster`，因此改动对应 monster 数组，没有用全局事件或全局实体池替代群系范围。
- 四实体的放置注册在 `VoidrangerEntities`：使用 `SpawnPlacements.Type.NO_RESTRICTIONS` 与 `MOTION_BLOCKING_NO_LEAVES` 高度图，保留 `Monster.checkMonsterSpawnRules` 的亮度/难度限制，并附加地表谓词。干燥地面要求脚下方块上表面稳固；水面要求当前位置处于该列高度图顶端、当前位置无流体且脚下为水标签流体（源水或流动水），因此只允许在暴露水面上方出生。水面判断不筛选群系 ID，可支持七个命途遗境群系中的海洋、河流、湖泊及其它水体；水下与海床出生没有实现为已验收功能，实际刷怪仍待游戏内确认。
- 七个群系的 monster 列表仅删除 `minecraft:*` 项，再追加下表四种实体。保留其它所有 spawner 类别和原有非 `minecraft` monster 记录；原始七表当时不含其它 mod 怪物/Boss monster 记录。

## 三、遗迹试炼固定槽

`RelicTrialBattleService` 保留既有 `waveComposition` 普通候选池和 `inspectType` 的 vanilla namespace 限制。固定槽通过四个明确注册 ID 调用；不会以 `arena_allowed` 标签开放整个 mod namespace。固定类型继续检查 `Monster` 类别、Forge bosses/排除标签、创建结果与现有体型/生命阈值。

| 命途等级 | 波次 | 固定槽 |
|---|---|---|
| 1–2 | 全部 | 无改动 |
| 3–4 | 第一波 | 无改动 |
| 3–4 | 第二波 | 1 个掠夺者替换普通槽 |
| 3–4 | 第三波 | 1 个抹消者替换原远程槽 |
| 5–7 | 第一波 | 无改动 |
| 5–7 | 第二波 | 1 个掠夺者替换普通槽；1 个篡改者替换通用精英槽 |
| 5–7 | 第三波 | 1 个抹消者使用明确远程槽；1 个践踏者替换另一通用精英槽 |

高等级第三波原组合没有远程槽，因此把既有四槽中的一槽改为远程槽并由抹消者占用，另一既有精英槽由践踏者占用；没有增加槽数。第一波保持原组合；每波始终准备四只，固定新增虚卒最多两只。篡改者占用通用精英槽时保留该槽当前精英倍率；践踏者虽占精英槽，仍以基础属性生成，不乘通用精英生命/攻击倍率。

试炼生成实体仍在整波完成准备后才取得设备坐标和 session UUID 标记，设备登记该波 entity UUID；击杀事件仍须通过设备坐标、session、活动 UUID 三重核对。自然生成实体不带这些试炼标记，不会进入活动 UUID 清单或波次击杀计数。设备中止仍只清理其登记的活动实体。没有修改试炼奖励、构装守卫 Boss 绑定或复战状态逻辑。

## 七、水域放置修复补记（2026-10-29）

- **确定根因：**源水/流动水差异不是水面零生成的主要原因。`NaturalSpawner.getTopNonCollidingPos` 使用注册的 `SpawnPlacements` 高度图调用 `getHeight`，而 `MOTION_BLOCKING_NO_LEAVES` 把流体计入高度，返回水面上方第一个可用 Y；`NO_RESTRICTIONS` 的位置类型本身通过。随后放置谓词调用 `Monster.checkMonsterSpawnRules`，该方法除 Peaceful/明暗条件外还调用 `Mob.checkMobSpawnRules`。对自然生成，后者读取 `pos.below()` 并调用该水块的 `BlockState.isValidSpawn`；1.20.1 默认块属性谓词要求上表面稳固且光照发射低于 14。水不具备稳固上表面，因此所有水面候选都会被拒绝，谓词中的水面判断永远到不了通过结果。这也解释了用户复测上一包仍为零生成。Biome JSON/类别不是拦截点：七个命途遗境 biome 的 `monster` 类别都列有四种虚卒；实体均为 `MobCategory.MONSTER`，原版该类别 max-per-chunk 为 70。
- **维度与表面位置核对：**`the_path` noise settings 设 `disable_mob_generation=false`、`sea_level=63`、`default_fluid=minecraft:water`（level 0）。在该水位配置下，海面源水所在方块为 y=63，含流体的 `MOTION_BLOCKING_NO_LEAVES` 高度图返回其上方首个位置 y=64；自然生成取样也使用实体注册的该 heightmap。河流/湖泊只要地形实际有 `FluidTags.WATER` 顶层，也由同一通用谓词判断，不依赖 biome ID。七份 biome JSON 都将四种实体列入 `monster`，没有需另外注册的水生类别。维度类型 `has_skylight=true`、`natural=true`，并未关闭怪物生成；这些资源足以排除“水面没有可用候选高度/biome spawner 缺项/类别 cap 为零”作为固定根因。
- **生成链与实体空间核对：**自然生成流程先取该列 heightmap 高度，再通过 `SpawnPlacements.checkSpawnRules` 调用自定义 predicate；`NO_RESTRICTIONS` 不额外要求地面类型，之后才检查实体 AABB 的 no-collision。四种虚卒尺寸分别为掠夺者 `1.25×2.5`、篡改者 `1.125×2.5`、践踏者 `1.5×3.2`、抹消者 `2.0×3.2`。在海平面例子中，实体从 y=64 向上占高 2.5/3.2 格，水方块止于 y=64，故水位本身不侵入生成碰撞盒；开阔海面有足够垂直空间。窄河道若岸壁侵入较宽实体的 AABB，仍会被原版碰撞检查拒绝。此前水谓词已允许 `FluidTags.WATER` 源水和流动水。
- **本轮修复：**exposed-water branch 仅在生成点为空气/无流体格、脚下为水且 Y 等于 `MOTION_BLOCKING_NO_LEAVES` 顶面时，绕过 `Monster.checkMonsterSpawnRules` 内部的 `Mob.checkMobSpawnRules` 固体支撑检查，显式保留 `Difficulty != PEACEFUL` 与 `Monster.isDarkEnoughToSpawn`。陆地仍调用完整 `Monster.checkMonsterSpawnRules` 并要求上表面稳固；不允许水下气穴、海床、熔岩或其它非 `FluidTags.WATER` 流体。未改实体属性/AI、Biome 权重/群体、Spawn cap 或试炼服务。
- **光照与验收边界：**命途遗境维度 `has_skylight=true`、`monster_spawn_block_light_limit=0`、`monster_spawn_light_level` 为 0–7 随机范围。调用 `Monster.isDarkEnoughToSpawn` 保持 vanilla 规则，因此明亮白天的水面仍不会满足刷怪光照；夜间或其它足够黑暗的水面可能生成，实际概率及频率必须由用户在新包复测。出生后的寻路、浮水和生存逻辑未改，未做游戏内验收。
- **API 与包状态：**通过 Forge/Minecraft MCP 确认文档版本为 Forge `1.20.1`，并核对 `SpawnPlacementRegisterEvent.register(...)`、`NaturalSpawner.getTopNonCollidingPos(...)`、`LevelReader.getHeight(Heightmap.Types, int, int)`、`Mob.checkMobSpawnRules(...)`、`BlockStateBase.isValidSpawn(...)` 和 `Monster.isDarkEnoughToSpawn(...)` 的签名。另对项目已有本地 1.20.1 mapped jar 做只读 `javap` 检查上述调用链和默认块谓词。最新包 `build/libs/starrail_sim-1.25.0-test.jar` 为 20,736,994 字节，SHA-256 `DE2E170210E5BE20D0C105D2CB7C72F16D68EFA6119F235F034BA298D7584E7F`；离线 `compileJava` 与 `reobfJar` 已成功，但当前包未由用户实机复测。水面实际密度仍待验收。
