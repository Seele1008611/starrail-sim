# 1.8.0 战斗粒子接入记录

## 2026-10-09：巡猎与通用韧性第一批

HTML 已完成六轮细化，涵盖九命途、近战/远程、低粒子量和命途显影开关。本轮进入游戏接入，先用巡猎与韧性反馈验证公共链路，其他八命途暂未接入战斗粒子。

### 已实现

- `CombatVfxPacket`：明确限制为服务端到客户端，传递效果类型、命途、攻击类型、起点和命中位置，一次事件不逐粒子发包。
- `StarRailCombatVfx`：复用伤害管线的追猎倍率与韧性结果；源对象和同 tick 校验避免把嵌套追加伤害当成原攻击。最终伤害取消或为零时丢弃视觉事件。
- `StarRailCombatParticles`：本地分 tick 生成巡猎剑锋、箭杆、尾羽、锐芒、强化光矢及韧性反馈。使用原版 DustParticleOptions 与少量 END_ROD，没有新增美术资源或下载。
- `StarRailCombatEvents` / `StarRailToughnessService`：只传递已经计算的结果，没有改动伤害、猎意、阶位、冷却和韧性规则。
- `StarRailNetwork`：注册新消息，协议改为 5。

### 实机与 HTML 的区别

HTML 可从蓄势开始展示完整动画；游戏只在服务端确认命中后播放。远程不会从玩家位置再造一次箭飞行，而是补出目标处最后一段光矢尾迹。近战只出现剑锋和交错弧线，没有拉弓。倾天光矢为装饰，不重复结算伤害。

本轮没有接入命途图标显影，优先验证巡猎在不依靠图标时的辨识度。原版尘粒的大小、亮度和寿命需要实机调节，不能把 HTML 直接当成完全一致的游戏画面。

### 粒子预算与同步

- 命中点同维度 48 格内广播；所有附近客户端均可看见，实际多人表现待测。
- 全部/减少/最少粒子设置采样比例为 1 / 0.55 / 0.22，原版渲染器仍可进一步裁减。
- 每 tick 最多生成 220 / 100 / 45 个粒子；最多 24 个待播放事件，每事件最多 650 个计划点。
- 超出预算丢弃点，不延后命中反馈；计划超过 24 tick 丢弃。退出世界或换维度清空。

### 接入规则

- 直接攻击强化及记忆/欢愉触发采用相同伤害源的待确认事件；最终伤害为正且未取消时发送，早期监听器的效果会合并保留。欢愉强化替换同次攻击普通爆发，避免两种爆发重复播放。
- 治疗、护盾与其他自身增益在现有机制改变状态后发送；不伪造一次攻击。
- 智识追加伤害和虚无终局在原伤害返回成功后发送；光轨只连接实际受影响目标，不在客户端自行搜索敌人或重算机制。
- 虚无直接标记记录真实近战/投射物来源；扩散和终局属于已成立的机制光轨，不伪造弓箭。
- 没有更改技能伤害、冷却、条件、材料或行迹加成。

### 九命途与通用反馈一起完善

- 沿用 HTML 的九命途配色与专属轮廓；用项目已有图标轮廓补出延迟的粒子显影。显影放在主动作之后，怒火这种频繁积层只保留轻量火星。

### 离线构建补充

ForgeGradle 6.0.54 的启动环境检查会单独连接 HTTPS 验证证书，即使使用 Gradle --offline 也可能卡在 SSL 握手。本轮通过本地已缓存插件确认开关，停止仅本次编译进程后加 `-Dnet.minecraftforge.gradle.check.certs=false` 再执行离线编译。以后离线 compileJava / runClient 可同样加此参数；该开关跳过插件启动检查，不会修改 Java 全局证书或启用依赖下载。

## 第四轮：修正纹理可见面积并增强光感（2026-10-09）

用户实机反馈上一轮依然偏暗、粒子偏少。检查本地原版 client.jar 的纹理像素发现：generic_0 为 8×8，其中仅 1 个像素可见；generic_7 同尺寸有 29 个可见像素。此前全亮度光照参数只保证不被环境压暗，普通透明混合及极小纹理面积不足以形成明显光感。

- 改用现有 generic_7；增加独立的加法混合渲染批次，以彩色光晕和接近白色的亮核组成光点。仍保留深度测试，批次结束恢复混合和深度写入状态。
- 主体纹理面积及显示尺寸增大，细小命途显影点独立缩放，避免图标细节合并。两层绘制均保留原生命周期淡出。
- 主体连线采样倍率由 1.25 提升至 2.5；水平环采样翻倍，主体光点增加略微偏移、延后一 tick 的细光点，填补轨迹空隙。频繁韧性接触和怒火不增加这层。
- 单次计划上限由 900 提升至 3000，每 tick 预算为全部 1200、减少 450、最少 90。距离、并发与过载丢弃继续生效。更多粒子和双层绘制需要实机确认连续战斗下的开销。
- 只修改视觉，未改变技能、伤害或触发机制；未下载纹理或依赖。离线 compileJava 通过，本轮视觉与性能尚待用户重启客户端验收。

## 第八轮：巡猎自定义网格样板（2026-10-09）

用户同意先备份巡猎粒子实现，再以网格替换巡猎效果，验收后决定是否全面替换。已保存第七轮完整粒子调度器及五个依赖/参考文件到 开发备份/1.8.0巡猎粒子特效-20261009，附 SHA256 与最小回退说明。备份尚未删除。

### 已实现

- 新增客户端 StarRailHuntMesh：在服务端确认的 HUNT_STRIKE / HUNT_REVERSE 包到达时生成网格，复用原事件、命中坐标、投射物方向和脚下高度，不改伤害、冷却或触发。
- 巡猎技能在粒子调度入口单独转交网格，并立即返回，因此不叠加旧巡猎粒子、图标粒子、余影或装饰。旧巡猎生成方法暂保留以便最小回退。
