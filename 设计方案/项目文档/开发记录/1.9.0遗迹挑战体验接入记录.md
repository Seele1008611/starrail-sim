# 1.9.0 遗迹挑战体验接入记录

## 第一批：监守者战斗面板（2026-10-09）

已完成游戏代码接入，不制作 HTML。尚未做游戏内视觉验收。

### 本轮实现

- 屏幕上方紧凑面板显示守卫名称/命途、生命值、韧性及正常/已击破/恢复中状态；击破与恢复显示剩余秒数。
- 使用现有深蓝底色、金色边线及 1.8.0 已确认的命途主题色；生命与韧性条平滑过渡，名称过长时缩放适配。
- 仅选择登记过、仍有效且存活的遗迹守卫，范围为 48 格；最近 5 秒实际受近战或玩家投射物伤害的守卫优先，其次最近守卫。普通遗迹使用通用名称。
- 服务端每 5 tick 向附近玩家发送一次真实状态；不全服广播、不加载区块。离开或守卫结束后发送隐藏消息。
- 客户端检查维度、实体 ID 与 UUID、距离和存活状态；切换世界、玩家死亡、退出连接及时清理，超过 30 tick 没收到更新则过期。暂停单人游戏不推进显示倒计时；打开其他界面或隐藏 HUD 时不绘制。
- 韧性快照是只读查询，未初始化的守卫显示现有基础韧性，不为显示初始化战斗数据；沿用原有击破与恢复结算。
- 新包限定服务端到客户端方向，主线程处理并隔离客户端类。网络协议更新为 8；本地 Mod 版本暂维持 1.8.0，联机开发客户端/服务端必须使用同一份开发代码。

### 文件

- `src/main/java/com/starrail/sim/RuinBattlePacket.java`：战斗显示包。
- `src/main/java/com/starrail/sim/StarRailRuinBattleSync.java`：附近玩家同步、近远程目标选择与清理。
- `src/main/java/com/starrail/sim/client/StarRailRuinBattleHud.java`：紧凑 HUD。
- `StarRailRuinGuardService`：查询实际登记守卫；`StarRailToughnessService`：只读韧性快照；`StarRailNetwork`：包注册与协议；中英文语言文件：面板文案。

### 构建与后续

使用已有 Java 17.0.20、Gradle 8.8 和依赖缓存，以 `--offline -Dnet.minecraftforge.gradle.check.certs=false compileJava` 离线编译，最终 BUILD SUCCESSFUL。未下载依赖、未新增或运行自动化测试、未启动客户端。实机显示仍待用户验收。

下一步接入锚点状态、冷却倒计时与精确失败提示，再完善开始/胜利/实际材料结果通知及异常恢复。需要用户实机检查时，以巡猎遗迹先看面板显隐、近远程目标选择、生命/韧性变化、击破恢复、GUI 缩放及与现有 HUD 的遮挡；再核对九命途。多人仍需有环境后补验。

## 第二批：锚点状态与完整挑战提示（2026-10-09）

### 实现

- 新增 RuinAnchorPacket 与 StarRailRuinAnchorHud。玩家看向 5 格内的锚点时，服务端每 5 tick 同步实际状态：未绑定、首次未通关、可召唤、战斗中、冷却中、等待加载/恢复和和平难度。显示匹配钥印、缺失钥印和错误命途钥印，冷却倒计时按原有游戏时间处理。
- 锚点提示与战斗面板纵向排列，复用深蓝底、金色文字和命途主题色；暂停时倒计时停止，转移视线后隐藏，跨世界/死亡/退出或同步过期时清理。极小窗口不绘制锚点卡片，交互原因提示仍可使用。
- 服务端视线查询先检查射线经过的全部区块是否已加载，不使用客户端提交的锚点坐标，不强制加载/生成区块。客户端再次核对实际视线、方块、命途和维度。
- 错误钥印交互明确说明需要的命途及手持物品；守卫等待恢复/加载时不会再次召唤。
- 首次接近守卫显示遭遇提示，成功重复召唤显示开始通知。首次胜利提示宝箱开放；重复胜利提示 30 秒冷却，合并实际材料掉落或未掉落结果。
- 沿用每次真实守卫死亡的一次 30% 掉落判定，增加本次事件记录防止重复判定；在真实死亡确认后检查掉落事件是否最终取消、对应物品是否仍在事件集合中。不额外发材料，不声称自动入包。无掉落事件（例如关闭生物掉落）不虚构材料。
- 遗迹通知延长为 80 tick（4 秒），不被连续战斗通知无限推迟；新遗迹通知替换过时的旧遗迹通知。原普通战斗通知时长维持现状；切换世界、死亡或退出清理通知，暂停时冻结时间。
- 新锚点包和带时长的通知包限定服务端到客户端方向，处理在主线程且隔离客户端类；当前开发网络协议为 9，替代第一批协议 8。Mod 版本暂未改，联机仍须双方使用相同开发代码。

### 异常边界核对

保留玩家死亡、离开和退出时不重置全局守卫状态的处理。区块卸载/暂时查不到 UUID 只显示等待，不判胜利、不刷第二只守卫。显式非死亡 DISCARD（如和平难度清除）由已有 respawn 标记在区域加载且恢复非和平后补回守卫；不重复开放首次宝箱或发材料。真实死亡与保存相邻仍由 ServerStopping 的确认处理保障。没有把 `/kill` 当作非死亡移除，因为它属于真实死亡。

本轮复用了已有恢复逻辑，重点补充状态可见性、等待时的交互拦截与提示去重，没有引入自动清场、离线冷却或九套专属 AI。

### 当前进度

compileJava 与 processResources 已使用已有 Java 17/Gradle 8.8 缓存离线构建成功；没有下载依赖，没有运行自动化测试或启动客户端。最终显示、状态边界与奖励需用户一次性验收。统一步骤见 [1.9.0 手动验收清单](../测试验收/1.9.0手动验收清单.md)。用户通过后再进行版本号更新、发行包构建及发布准备；多人无环境时记录未验证。
