# 1.6.0 版本规划与验收记录

> 状态：已完成并通过游戏内验收；正式发行日期为 2026-10-08。九条命途的行迹树、材料、属性与被动效果均已接入。

## 版本定位

新增命途行迹成长系统，先为九种命途分别设计属性加成树和被动能力树。每棵行迹树使用对应命途图标的轮廓作为视觉构图依据，并通过各自机制体现命途特色。

## 设计与实施顺序

1. 先制作巡猎行迹设计表和 HTML 交互样稿，用户确认布局、节点内容与升级体验。
2. 以巡猎作为样板，确定其余八种命途的树形、节点数据格式和共同交互规则。
3. 九种命途的设计通过后，再实现共享行迹框架和服务端升级校验。
4. 将各命途升级材料和消耗量接入配置；具体物品由用户确定后补齐。
5. 完成客户端展示、服务端验证与多人环境验收。

## 当前设计原则

- 继续使用当前已有的九种命途、等级和属性系统，不改变现有命途晋阶试炼规则。
- 九种行迹的节点和总加成已确认，详见现有行迹设计表与 HTML 数据。巡猎全树合计：暴击率 +10%、攻击力 +50%、暴击伤害 +50%。
- 每条命途的行迹数据彼此独立；切换当前命途时保留已点亮节点，仅当前命途的行迹效果生效。
- 属性节点与被动节点在界面和效果说明中明确区分。被动效果自动触发，不要求新增主动技能操作。
- 节点升级消耗对应命途材料；阶位与前置关系沿用已确认的原型。单节点回退包含依赖节点，按实际消耗返还。
- HTML 先于游戏内实现。网页样机内的模拟点亮只用于查看视觉反馈，不代表真实物品、规则或存档数据。
- 1.4.0 HTML 原作模板和分辨率适配版保持原样；1.6.0 原型存放于独立目录。

## 玩法实现摘要

- 六个属性节点与三个被动节点组成每条命途的独立行迹树；每棵树全解锁消耗 33 个对应命途材料。
- 服务端检查当前命途、阶位、前置节点、节点状态与背包材料；重复或无效请求不会重复扣除材料。
- 单节点回退会连带撤销依赖节点并返还材料；全部重置需确认，背包无空位时返还物品会掉落在地上。
- 节点状态按命途分别保存。切换当前命途时保留进度，仅启用当前命途的行迹属性与被动。
- 行迹界面参照已确认的 HTML 样机与用户提供的九种分支线模板；支持不同窗口比例、节点详情滚动、选中/解锁/回退动效。
- 管理员测试命令 `/starrail path debug set <path>`、`prepare <path>`、`clear` 要求权限等级 2，不改变正常踏上命途流程；`prepare` 会切换到指定命途极境并补足未解锁节点所需材料，`clear` 回到未踏上命途且保留历史进度。
