# 1.23.0 版本计划：命途遗境地表生态与星穹列车枢纽

日期：2026-10-25。当前状态：**1.23.0 内容已冻结并正式发布至 [GitHub Release v1.23.0](https://github.com/Seele1008611/starrail-sim/releases/tag/v1.23.0)。阶段 0–5 已完成；用户确认单人阶段测试和列车最终结构/对称照明实机验收通过。多人测试期间反馈的问题已修复，但最终改版整包未获明确联机复测确认。正式 JAR 已通过离线构建和发布前机器检查，大小 20,392,278 字节，SHA-256 为 `448be521bca7845e0e0eb4d4e226630ced01cb40a6ea0f0f53d316128d89e069`。星砾高地、静潮泽地与高地低矮植物纳入本版；星穹列车双维度枢纽尺寸 `424×23×23`，保留原车头和两节客车，新增观景卧铺、暖木客房两节卧铺车厢。两界车站均位于 `(0,280,0)`；定制 `.litematic` 与运行时结构已归档。**

## 一、版本目标

1.23.0 延续命途遗境（The Path）的世界扩展，重点增加地表生态与地貌变化，让现有草甸、林地、海岸、海洋和地下洞窟之间出现更多可辨认的探索区域。首轮规划以两个新地表群系为目标，并新增少量服务于地形和生态的方块、植物及生成特征；同时将星穹列车规划为主世界与命途遗境之间的固定往返枢纽。

玩家可以从地表轮廓、土壤和植被辨认新区域，并找到可采集、可带回建造的本地材料。新生态用于丰富探索与建造，不改变既有高阶装备成长线，不成为命途阶位、食物或既有配方的门槛。用户后续明确要求补齐曜金和霞铜的工具/盔甲套装，以及谐振晶的红石等价铺设行为；这些资源用途作为 1.23.0 的补充范围。星穹列车将承担维度交通：玩家在两界列车内使用星轨信标双向往返，不再依赖探索完主世界 53 个群系获得列车模型。

**探索循环：**穿过现有陆地群系发现新地貌 → 辨认群系特有的地表与植物 → 采集少量本地材料 → 继续探索、建造或返回原有区域。

## 二、现有基线

- 项目面向 Minecraft 1.20.1 Forge；当前正式版本为 1.22.0。
- The Path 使用 `the_path` 噪声设置与 `multi_noise` 群系源。目前有四个地表群系：晴穹草甸 `sunmeadow`、流萤林地 `glimmerwood`、澄沙海滩 `clear_sand_beach`、星潮海域 `star_tide_ocean`；另有地下星脉洞窟 `starvein_cavern`。
- 四种地表群系在群系源中按 `depth=0` 和 `depth=1` 路由；地下洞窟使用独立的 `depth` 范围。地表表层由噪声设置里的群系条件规则覆盖。新群系须同时接入群系路由、合适的表层材料规则和群系特征，不能只添加 biome JSON。
- 现有地表已有晴穗树、流萤树、晨露莓、林息豆、晴穗花、澄沙铃花、潮汐草和星潮藻等生态资产；矿物与基础生存循环已跨现有群系建立。星脉洞窟已有流萤苔、原创晶簇洞与大型晶簇厅。
- `the_path_regions` 群系标签目前收录两种主要陆地群系，遗迹决斗场可生成群系标签引用此标签。增加适合遗迹生成的新地表群系后，需要根据采样结果更新相关群系标签、探索记录、指南和定位支持。
- 新群系只影响新生成区块；已有区块不会因升级自动重建。
- 当前星穹列车是可放置的列车模型/方块实体，旧规划曾考虑在完成主世界 53 个群系探索后发放该模型。新提案将以完整列车结构和列车内的星轨信标取代这套获取/通行方式；用户已清空旧存档，无须为旧存档迁移保留旧奖励或旧列车放置逻辑。
- `设计方案/模型资产/星穹列车.litematic` 是完整列车的原始造型参考，不可原样导入。转换脚本会保留原稿及原版车头、两节客车的相对布局，在客厅车厢尾部追加观景卧铺、暖木客房两节异内装卧铺车厢；新增客车彼此之间及其与原车之间都复用原稿双门过渡段。转换脚本生成定制归档 `星穹列车_1.23.0枢纽定制.litematic` 和运行时结构，信标由脚本在预留位置注入。

## 三、群系方向（工作名）

以下是可供原型验证的方向，不预先锁定名称、气候区间或覆盖率。阶段 0 应先确认现有地形噪声中是否有适合这些生态的稳定空间，再决定保留、调整或替换方向。

| 群系候选 | 地貌与生态 | 玩家体验 | 生成约束 |
| --- | --- | --- | --- |
| 星砾高地 | 开阔的高处草坡与裸露岩面，坡脚有稀疏碎砾和低矮耐风植被；主色延续自然岩土色，星空元素只作为少量晶点或远景细节 | 提供俯瞰周边地形的地标和高低路线变化；保留能安全通行的宽缓地段，不把高差做成连续攀爬障碍 | 先验证候选噪声区域是否与实际高地、缓坡相符；不改变深层岩层、海岸和洞穴路由 |
| 静潮泽地 | 低缓湿地、浅水洼、软土与芦苇/湿生草本组成的局部生态；需要与陆地相连，也要和开放海域、海滩保持清楚区别 | 增加可辨认的湿润低地与沿水步行路线；能采集装饰性植物，不增加口渴、氧气或强制食物系统 | 通过气候噪声与地形样本确定低地范围；不得让浅水淹没大面积通道、切断返程或覆盖既有海岸生成 |

阶段 0 可基于多种子采样调整为一个主群系加若干地貌变体，也可更换其中一个候选。只有在地形和群系选择可稳定对应、且与现有四种地表群系区分明显时，才冻结为两个独立群系。

## 四、新方块与生态资产（候选清单）

原则：新增资产少而有明确作用；优先复用现有天穹岩、坡地粗土、澄溪砂、河床砾和林地植物规则。只有现有材质/方块无法表达新生态时才新增方块。资源键和最终名称在阶段 0/2 定稿。

| 内容候选 | 用途与自然出现 | 设计边界 |
| --- | --- | --- |
| 高地碎砾（`path_ridge_scree`） | 在高地坡脚、裸岩边缘形成小片碎砾地表，可采集后用于地形装饰 | 不作为新矿物，不提供装备升级材料；先评估现有河床砾能否承担同一用途，避免重复材料 |
| 泽地腐殖土（`path_marsh_humus`） | 作为湿地浅层土壤和湿生植物基底，形成与草甸、森林土层不同的地表识别 | 需要支持合理采集与建造；是否可耕作、能否作为树苗/植物基底由阶段 0 明确，不新增强制生存规则 |
| 湿生草本/芦苇（工作名） | 在静潮泽地的浅水边和湿土上稀疏生成，作为路线与水岸的视觉提示；可采集并重新放置 | 只在合适群系与基底上生成；控制高度、碰撞和密度，不能遮蔽水面或大量堵路 |
| 高地低矮植物（用户已确认纳入） | 新增一种具有独立外观的低矮耐风草本或小型花簇，为高地提供近景辨识和可带回种植的装饰植物 | 正式纳入本版，不再作为可选项；阶段 0 确定名称、适生基底、采集与扩繁规则，控制高度和密度，保持开阔视野 |
| 星穹列车双维度枢纽 | 将完整列车改造为固定生成的维度交通站；主世界与命途遗境各在 `(0,280,0)` 放置一座，列车内部设置星轨信标并双向传送 | 参考项目内 `.litematic` 制作定制版本，不覆盖原稿；保留原版车头与两节客车，在客厅车厢尾部追加两节不同风格的卧铺房间车厢，新增车厢之间及其与原车之间沿用原稿双门过渡，补齐全列照明。结构锚点、信标坐标和乘客安全落点随最终编组复核 |

新方块须有独立的 16×16 游戏贴图，遵循[方块贴图风格规范](../方块贴图风格规范.md)，检查原尺寸与至少 4×4 连铺效果。若新增石材成为可采集的主建筑材料，应补齐对应的常用加工方块和合理配方；若只是局部自然沉积物，不强行扩充楼梯、台阶、墙等无实际需要的变体。

## 五、版本范围与边界

### 纳入 1.23.0

- 阶段 0 采样、群系方案冻结与数据包/游戏原型验证。
- 目标为两个新的地表生态群系，及与之匹配的表面材料、少量植物和自然生成特征；若采样结果不支持两个独立群系，则阶段 0 可调整清单。
- 把新群系接入 The Path 的群系路由、表面规则、适用生成特征和相关群系标签。
- 视现有系统需要更新群系探索档案、指南和管理员定位入口。
- 对现有四种地表群系、星脉洞窟、海陆交界、共享矿物、返回流程与遗迹生成做回归检查。
- 修正命途遗境的床爆炸配置，使床可正常使用。
- 加入曜金与霞铜各一套工具和盔甲（剑、镐、斧、锹、锄、头盔、胸甲、护腿、靴子），补齐合成、修理与视觉资源，不改动既有星髓及以上成长线。
- 使谐振晶能像红石粉一样放置为信号线并参与红石信号传播，延续其现有红石等价配方用途。
- 用完整星穹列车取代当前可放置的列车模型作为世界枢纽；在主世界和 The Path 各固定生成一座，列车内部设置星轨信标，实现玩家主动点击后双向传送。移除“完成主世界 53 个群系探索后领取列车模型”的奖励、解锁门槛与相关提示。
- 列车结构以 `设计方案/模型资产/星穹列车.litematic` 为改造参考，制作本项目风格化版本；重新处理方块色板、火把等突兀光源、方块实体与展示实体，并确保两维度都能稳定加载。
- **坐标方案已确认：**Minecraft 1.20.1 原版主世界建造高度上限为 Y=320（可放置方块最高 Y=319），主世界列车中心位于 `(0,280,0)`；用户后续确认 The Path 列车也降至 `(0,280,0)`，两边保持一致。结构地板在 `(0,279,0)`，玩家脚部安全落点为 `(0,280,0)`；列车信标与落点分开定义，避免传送到方块或列车碰撞体内。

### 不纳入 1.23.0

- 新的命途装备晋阶阶位、新成长矿物、新的命途晋阶/践行度系统或专属材料门槛。曜金与霞铜套装仅按用户补充要求纳入，不替换现有高阶装备阶梯。
- 重做整个 `the_path` 噪声设置、既有生存循环、海洋内容或洞穴生态；如必须改地形密度，先提交最小变更原型并对所有现有区域回归。
- 改造普通遗迹、九种命途遗迹或遗器决斗场的结构蓝图、奖励与玩法。只为保证新群系里的生成合法性和可达性调整群系标签或避让条件。
- 大型新结构、Boss、副本、复杂任务链或额外战斗系统。
- 不再把星穹列车模型作为 53 群系探索奖励；旧存档迁移不在本版范围内（用户已删除旧存档）。

## 六、实施阶段与验收

### 阶段 0：世界采样与设计冻结

- 检查多颗新种子中现有草甸、林地、海滩、海域和地下洞窟的布局、邻接、地形高度、表层方块及特征密度，建立改动前基线。
- 对照 `multi_noise` 的大陆性、湿度、侵蚀度、温度、奇异度与深度路由取样，确认高地与湿地候选能落在相符地形上，并检查新增参数不会占用洞穴深度范围或显著压缩现有群系。
- 冻结新增群系的工作名、气质、参数范围、目标分布、相邻关系和表面规则；通过小型 JSON/数据包原型先验证出现位置。
- 冻结每个新增方块/植物的获得方式、用途、基底、生成频率和方块状态；确认是否能复用现有资产。
- 明确新群系是否纳入普通遗迹/决斗场生成标签，并为探索档案与指南列出更新项。
- **阶段验收：**方案有可复现的群系样本；新增区域可辨认且可通行；旧群系、海岸和洞穴路由没有被原型明显挤压或覆盖；新增内容无生存或成长软锁。

### 阶段 1：群系路由与地貌

- 接入冻结后的新群系路由，分别配置 `depth=0` 与 `depth=1` 地表位置，并保留既有地下 `depth` 路由。
- 修改表面规则时明确测试水面、河谷、海滩、山坡与洞穴边缘，避免新土壤铺入不适合的地表或海底。
- 优先沿用当前噪声密度场；只有采样证明地形轮廓不足时才改动 `the_path` 噪声设置，并逐项记录对高度、海平面、海床、洞穴和已有结构的影响。
- **阶段验收：**新群系按预期地形出现；旧群系仍能稳定找到；海岸连续性、洞穴群系垂直选择和共享地层没有回归问题。

### 阶段 2：方块、植物与生成特征

- 实现冻结清单中的方块与植物，补齐注册、模型、掉落、采集工具、配方/标签、语言文本和指南数据。
- 接入 configured/placed feature 或其他合适的原版生成方式，给放置规则增加严格的群系、地表、流体和空间限制。
- 检查自然生成、人工放置、采集、再放置、骨粉或生长行为（如适用）、粒子/碰撞和跨群系生长边界。
- **阶段验收：**每项资产只在合适区域生成并能正常获取；生成密度构成生态斑块而非均匀铺满；现有植物与食物循环行为不变。

### 阶段 3：探索与结构兼容

- 为新群系添加群系发现记录、指南说明和必要的管理员定位入口，保持玩家可自然探索、命令用于定位与管理的既有方式。
- 按阶段 0 决议更新 `the_path_regions`、`relic_trial_arena_spawnable` 等群系标签。
- 检查普通浮空遗迹、遗器决斗场与命途寻迹目标在新增地貌中的生成高度、支撑方块、净空和可达性，不改蓝图与奖励。
- 实现星穹列车固定枢纽的坐标/结构方案；按冻结的高度在主世界与 The Path 放置完整定制列车，并确保固定位置只生成一次，区块重载或重启不会重复覆盖玩家建筑。
- 移除 53 群系完成后发放列车模型的逻辑、旧进度/奖励门槛和相关指南/语言提示；确认进入 The Path 不再要求完成全群系探索。
- 在两座列车内部放置星轨信标并实现服务器权威的双向传送；传送前检查目标区块与安全空间，两个维度的目标均为 `(0,280,0)`，并通过结构相对布局保证玩家落在可站立、无遮挡的列车内部位置。
- 将 `.litematic` 转为可维护的完整结构资源前先完成素材盘点和改造：处理尺寸/原点、无用空气边界、配色替换、火把等不协调细节，以及原稿里的方块实体和展示实体。验证结构可在两个维度正确朝向、无缺失方块实体或危险实体。
- **阶段验收：**新群系能被探索系统正确识别；结构没有悬空、埋入水下或阻塞常规通路的问题；双维度车站只生成一次，信标可以安全往返，旧的 53 群系列车奖励已完全移除。

### 阶段 4：多种子回归与世界检查

- 在多颗新种子、多个坐标和群系交界取样，检查新旧群系比例与相邻地形、海滩/海洋边界、地表高度、浅水范围、洞穴入口及表面材料。
- 在新旧区块交界检查升级后生成行为；记录哪些变化只会出现在新生成区块。
- 回归九种共享矿物在可开采岩层中的来源，确认新群系没有造成矿石露出成片、表面刷矿或某类资源难以获取。
- 检查结构避让、探索记录、定位、维度进入/返回和资源重载；确认生成数据不会在不相关维度生效。
- 检查列车在两个维度的固定位置生成且不会重复覆盖，区块卸载/重载和服务端重启后结构保持；分别通过星轨信标往返，并验证到达列车内部的安全落点、多人同时使用及服务器/客户端一致性。
- **阶段验收：**各个新群系在多个样本中可稳定找到；没有明显的群系碎片化、错层铺土、特征越界、结构失效或已有生态退化。

### 阶段 5：用户实机验收与发布

- 提供阶段测试 JAR 和简明路线，使用新世界验证两个新群系、群系间过渡、采集与建造用途、床可用性、曜金/霞铜装备配方与属性、谐振晶铺设及信号传播、两格芦苇自然生成、两界列车与星轨信标往返、光影开关两种状态下的视觉表现和既有生态回归。

## 七、主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 群系 JSON 加入后实际很难出现，或生态群系与地形不相符 | 阶段 0 先按噪声采样与原型验证；冻结参数前检查多个种子和群系边界 |
| 新气候区间压缩草甸、林地或改变洞穴选择 | 保留现有 `depth` 路由；逐步切分参数并在相同种子下对比原有群系覆盖 |
| 表面规则让新土壤进入海滩、海床或洞穴 | 分支按群系键限定，并覆盖陆地、海岸、水下、洞内和交界样本 |
| 植物跨群系生成、阻塞通路或扩散过密 | 限定放置群系、基底与流体状态，并采样生成斑块的空间密度 |
| 新地貌影响遗迹或决斗场的安全生成 | 基于验证结果更新生成标签/避让条件，保持结构内容与玩法不变 |
| 新增材料与既有方块重复 | 阶段 0 优先检查天穹岩、粗土、澄溪砂和河床砾是否能复用；每种新增材料都要有清晰的地貌用途 |
| 约 Y=280 的主世界站点高度与列车结构实际几何/地形不匹配 | 先完成结构原点、占用边界和地形净空测量；可微调约定高度附近的结构锚点，但保持 X/Z 在原点附近，并确保列车完整处于原版建造范围 |
| 超大型 `.litematic` 转换后边界错位、实体/方块实体丢失，或原稿视觉风格不合项目 | 先核对实际非空气边界和原点，逐类清点方块实体/展示实体；建立定制版本并在测试世界预览后再接入固定生成 |
| 固定世界枢纽在重载/重启后重复生成并覆盖玩家建筑 | 采用一次性、可持久化的生成状态或可靠结构放置标记；测试新区块、重载区块、重启和多人同时初始化 |
| 星轨信标跨维度传送把玩家送入方块/列车碰撞体或维度边界外 | 分开定义结构锚点、信标位置和玩家落点；对目标空间做安全检查，实机验证上下车、多人和两种光影状态 |
