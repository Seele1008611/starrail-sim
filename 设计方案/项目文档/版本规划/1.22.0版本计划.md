# 1.22.0 版本计划：九命途战斗特效表现升级

## 一、版本目标

1.22.0 聚焦九条命途在攻击、技能和韧性互动时的战斗特效与触发音效。以几何网格确定招式的世界坐标、空间轮廓和动作节奏，结合发光材质、选择性泛光、场景折射、冲击波、短时染色和镜头反馈，做出明显区别于纯网格的华丽表现；为每种特效配上辨识度合适的短音效。强化动作要有蓄势、爆发、余波三段变化，每条命途使用有辨识度的效果组合。

本版只改视觉与听觉表现，不改伤害、技能触发条件、命途效果、战斗结算和掉落。

## 二、版本状态与现有基础

- 目标模组版本：`1.22.0`；Minecraft 仍为 `1.20.1` Forge。
- 规划启动时的已发布版本为 `1.21.0`。进入发布阶段后，正式版本号已更新为 `1.22.0`；本版现已发布。
- 1.8.0 的九命途自定义网格特效已通过用户单人实机验收；本版视觉基线是 `设计方案/UI设计/1.8.0战斗特效原型/README.md` 和同目录 HTML/JS 原型。多人同步当时没有测试。
- 1.21.0 发布版战斗网格由 `StarRailCombatMesh` 在客户端生成面片，使用 Minecraft 的 `POSITION_COLOR_SHADER` 和半透明渲染类型绘制；服务端确认事件后仍通过 `CombatVfxPacket` 通知客户端。阶段 1 工作区已接入可选战斗着色器，进展见阶段记录。
- `CombatVfxPacket.Kind` 当前包含 26 种事件：九命途的 24 种路径专属动作，以及韧性受击、韧性击破两种共用反馈。
- 项目原有核心着色器用于平滑界面和列车；阶段 1 新增独立的共享战斗材质，不复用界面或列车着色器。
- 已确认的视觉资料： [1.8.0 原型说明](../../UI设计/1.8.0战斗特效原型/README.md)、[特效设计室 HTML](../../UI设计/1.8.0战斗特效原型/战斗特效设计图.html) 及同目录配置、几何脚本。HTML 用来确认造型、节奏和锚点，不代表 Minecraft 着色器或渲染兼容性已经验证。

网格继续提供招式主体和坐标依据；着色器既处理网格表面，也通过场景颜色、深度和特效专属缓冲生成泛光与空间变化。屏幕震动由相机表现层提供，并与同一视觉事件的时间轴同步。

**最新反馈：第一轮 `1.22.0-stage1` 原型未通过用户视觉审看。颜色流动变化太小，未体现足够的着色器特征。阶段 1 需要重做；原有禁止自定义帧缓冲及屏幕后处理的限制撤销。** 调研与重做细节见 [着色器特效方向修订](../开发记录/1.22.0着色器特效方向修订.md)。

## 三、视觉方向

### 1. 画面原则

- 网格负责每个招式的主体形状、轨迹、空间位置与动作节奏。
- 着色器负责可见的能量发光、外溢泛光、噪声扭曲、场景折射、冲击波和消散；根据命途加入短时染色、局部像素化、色散和空间残像。每条命途搭配不同的主效果与辅助效果。
- 像素风体现在主体轮廓与几何语言上，允许光晕、折射和运动残像。默认增强模式应有明显的华丽程度与冲击力，不能把“网格略微变亮”当作升级达标。
- 保留正常的世界深度关系；特效经过墙体或实体遮挡时应符合场景观感。
- 屏幕后处理从实际招式锚点投影生成，按作用范围、距离和时间衰减。允许强化动作短时影响视野与镜头，保留敌人轮廓和攻击方向的可读性；HUD 和菜单文字保持清晰。
- 提供基础网格回退、增强强度及独立镜头震动开关。增强模式的默认效果要明显，强度设置负责适配个人偏好。
- 着色器不可用或加载失败时，应保留可辨认的基础网格效果，不能让招式完全消失。

各途继续使用原型主色。实体网格保持开放轮廓和正常深度关系；发光层允许加法或 HDR 合成与受控亮核，泛光只从特效发光层提取，避免把整个世界一起提亮。镜头冲击与色染跟随动作包络，不能长时间填满玩家或目标身体。

原型已确认的锚点规则也要沿用：自身增益绑定玩家中心；命中轮廓和标记绑定实际目标中心；地面层单独对齐相应主体脚下；多目标光带只连接真实受到效果的目标。需要跟随移动目标的效果用实体锚点，实体不可用时在原命中位置短暂消散。远程表现使用服务端确认的攻击方向，不自行补发攻击。原型中的时间轴时长与命中时点只描述视觉动画节奏，不改技能持续时间、冷却或结算时点。

下表按当前 `CombatVfxPacket.Kind` 和服务端调用点盘点。触发条件是现有玩法行为的摘要，后续只调整客户端表现；阶段 0 冻结逐项设计时若发现代码与摘要不符，以源码核对结果为准，并在此修正文档。表内的轮廓方向是待原型确认的设计基线，不是逐个事件定稿。

| 事件 | 当前触发场景与锚点 | 表现重点 |
|---|---|---|
| `HUNT_STRIKE` | 巡猎追击加成攻击造成有效伤害，倍率大于 1 且低于 1.5；锚定受击目标 | HTML 基线的四支斜向汇聚箭与中央终结箭；远程保留横向先导贯入箭 |
| `HUNT_REVERSE` | 巡猎反击倍率达到 1.5 的有效攻击；锚定受击目标 | 八支外围箭、中央终结箭和错拍残影，沿用 HTML 已确认的逆时回卷节奏 |
| `TOUGHNESS_HIT` | 攻击结算出韧性削减但未击破；锚定实际命中点 | 四枚极小棱面碎光短促弹开，保持普通攻击反馈轻量 |
| `TOUGHNESS_BREAK` | 攻击结算造成韧性击破；锚定受击目标 | 目标轮廓先显裂，再释放透明几何壳片与脚下断裂扩散环 |
| `PRESERVATION_WALL` | 存护屏障技能成功启动；锚定玩家 | 双层中空盾面、六边形盾阵和脚下守护边界依次展开 |
| `PRESERVATION_COUNTER` | 玩家成功格挡并对攻击者造成反击伤害；从玩家指向攻击者 | 盾缘收紧后沿反击方向推出分段冲击与菱形回震 |
| `DESTRUCTION_RAGE` | 毁灭行者受到敌对伤害并进入或处于半血以下，积累怒意层数；锚定玩家 | 小型地面裂火与火冠，暗红火星上涌，强化积层保持轻量 |

| `HARMONY_AFTERGLOW` | 同谐余晖攻击加成被本次攻击消耗且有效伤害成立；锚定受击目标 | 玫粉节拍轨连接目标，命中时展开音律带、柔金音符与同谐轮廓 |
| `HARMONY_CONCERT` | 共鸣期间击杀触发同谐恢复效果；HTML 基线要求回响从击杀位置沿光带返回玩家 | 当前调用只把玩家作为来源和目标；阶段 0 应利用死亡实体已有坐标作为视觉起点、玩家作为终点，复用现有包字段，不改线格式 |

| `ABUNDANCE_MANNA` | 丰饶溢出治疗成功转为吸收护盾；锚定玩家 | 枝叶环抱玩家，光点在身体外侧合成护持轮廓，上方显现丰饶图案 |
| `ABUNDANCE_MERCY` | 七阶丰饶成功阻止一次致命伤害并完成急救；锚定玩家 | 脚下莲瓣绽放、枝叶舒展，生命光雨汇入玩家后化作微粒散开 |
| `REMEMBRANCE_RECORD` | 记忆命途首次记录本次攻击目标；锚定目标 | 冰晶环绕目标，六臂雪晶与沙漏标记依次出现，最后碎成晶点 |
| `REMEMBRANCE_ECHO` | 记忆命途在记忆窗口内再次命中同一目标；锚定目标 | 折返轨迹按两拍亮起，雪晶与记忆轮廓随回响命中绽放 |
| `REMEMBRANCE_ETERNAL` | 记忆回响升级为永恒回响并成功强化伤害；锚定目标 | 双层雪晶与折返轨迹错拍亮起，释放强化晶体碎片 |
| `ELATION_BURST` | 欢愉连击计数达到 3 的倍数并触发爆发；锚定目标 | 粉色棱面网格从命中点跳跃弹开，以短弧形成轻快节奏 |
| `ELATION_GRAND` | 欢愉连击达到 6 的倍数且判定成功触发大欢愉；锚定目标 | 两次错拍爆发与彩色方块碎光，仍以粉色为主 |

表中 26 项分为 24 种命途事件和 2 种韧性公共反馈。复合事件（例如 `DESTRUCTION_DESPERATE`）可能由不同现有场景触发，视觉必须依赖已传入的来源、目标和方向数据适配锚点，不能靠新增触发判断改变玩法。

事件组合也要保留现有语义：`REMEMBRANCE_ETERNAL` 会替代同次命中的 `REMEMBRANCE_ECHO`，`ELATION_GRAND` 会替代同次命中的 `ELATION_BURST`；虚无扩散可同时产生新目标的 `NIHILITY_MARK` 与源到目标的 `NIHILITY_SPREAD`；韧性反馈则可能与路径攻击同次出现。表现层要区分层级，不应把这些合法的并发效果误去重或互相覆盖。

### 3.1 HTML 时间轴与当前 Java 生命周期

1.8.0 HTML 配置的默认预览窗口为 3.0 秒、预览命中点为 0.57 秒。例外只有：存护反震命中点 0.77 秒、智识终局推演 0.72 秒、记忆回响 0.80 秒、永恒回响 0.99 秒；丰饶慈航预览窗口为 3.4 秒。其余事件沿用默认值。它们是原型播放器的视觉时间参考，不是技能持续时间、冷却、服务端触发延迟或伤害结算时点。

巡猎原型另有明确的箭矢内部节奏：外围箭错开约 0.04 秒起步，普通箭每支间隔约 0.10 秒、强化箭约 0.085 秒；每支外围箭起步约 0.27 秒后命中。中央箭普通版在约 0.65 秒起步、强化版约 1.05 秒起步，起步后约 0.32 秒命中。当前 Java 的巡猎起步间隔及外围/中央命中延迟与这组原型数值一致。

当前 `StarRailCombatMesh` 以客户端接收数据包后的年龄驱动动画，并在 50 个客户端 tick（2.5 秒）移除整个效果；这与 HTML 播放器的 3.0/3.4 秒预览窗口并非同一个计时定义。代码中的几何片段各自还有独立出生时间和寿命。因此这属于需在新原型中检查尾段是否被截短的时间差异，不能只因两个总窗口不同就直接认定旧网格动画有缺陷，也不能把 HTML 预览时点写成玩法触发时间。

| 智识 | 已有眼形核心、轨道、节点、扫描短线与来源至当前目标的连线 | 当前每个事件包只携带一个目标，Java 逐个目标绘制；HTML 预览可一次展示多个目标连接。保持逐个真实命中目标的语义，不凭空补画未命中的目标；终局推演 .72 秒预览命中点尚未作为独立动画节拍表达 |
| 虚无 | 已有断裂暗色轨道、碎片、侵蚀片和向内曲线；扩散/终结事件有来源至当前目标连线 | 中空主体已存在；标记、扩散、终结主要共用同一网格，终结缺少独立的 6 向终末旋转节拍，后续应按事件区分而不填实中心 |
| 同谐 | 已有双侧音律曲线、金色音符、节点与三拍脚下节奏；合拍可增加层数 | 基本签名齐全；HTML 的击杀回响从死亡位置返回玩家，当前服务端调用把玩家同时作为包的来源与目标。计划已限定用已有死亡坐标修正视觉锚点，不改包格式 |
| 丰饶 | 已有枝叶、上升曲线、生命节点与强化叶环；溢出护盾另有菱形晶片 | 丰饶治疗与慈航目前主要靠强化层数区分，Java 未单独画出 HTML 慈航的莲瓣绽放和生命光雨汇入；这两项要作为慈航专属阶段补上，不能只放大普通治疗 |
| 记忆 | 已有六臂晶形、沙漏轮廓、晶体和回声曲线；永恒回响可加晶层 | 记录、普通回响目前共用主要形状；HTML 的回响两拍折返尚无独立事件节奏。配置中的 .80/.99 秒是预览时点，需在原型中表达为视觉节奏，不更改记忆机制 |
| 欢愉 | 已有面具/卡片轮廓、棱面碎光、旋带；强化增加卡片、旋带层和第二方块 | 主题形状已覆盖；强化当前主要是数量增加，HTML 的两次错拍爆发需在动画上更明确，彩色碎光仍只作少量点缀 |
| 韧性反馈 | 受击有四枚小晶体和短线；击破有目标周边裂片、壳片与扩散地面环 | 与 HTML 的轻量受击、裂解击破方向一致；着色器增强不能把普通受击变成强爆炸，也不能遮蔽同次命途特效 |

锚点源码核对结果：有效目标实体存在时，Java 将效果跟随到目标插值位置并以目标身高约 55% 作为局部中心；脚下形状再用目标身高回到脚边。来源实体存在时也使用插值位置；实体不可用时保留包中的坐标。远程方向来自 `origin` 到 `impact` 的已确认向量。该结构总体符合 HTML 的目标跟随、实体缺失时留在命中位置及远程方向规则。智识多目标视觉必须尊重当前“一包一目标”的字段，不把原型预览中的同时展示误解成可以连向未命中实体。

### 4. 着色器实现边界

- 使用少量共享战斗材质参数化命途主色、阴影色、强调色、时间相位与强度；不为 26 个事件分别复制整套着色器。
- 表现分为网格主体、能量材质、特效后处理、镜头反馈四层，共用同一事件的目标/来源锚点和视觉年龄。允许材质噪声与顶点位移，但要保留可辨认的招式主体和攻击方向。
- 保留半透明混合、世界深度测试和“不写入深度”的渲染方式。阶段 1 使用 `POSITION_COLOR_TEX`：在原有位置和颜色外增加两个浮点数，分别传递实体局部流动坐标、材质编号与面内横向位置；不用纹理采样。增加这些数据是为了让不同命途在同一批按距离排序的面片中使用不同材质，避免按事件反复切换着色器而打断透明排序。
- 新顶点格式每顶点由 16 字节变为 24 字节；沿用 48000 面片上限时，最多增加 1536000 字节（约 1.46 MiB）顶点数据。原有基础颜色着色器可直接忽略额外坐标，回退不用重建另一套几何。此处是数据量预算，不代表 CPU/GPU 性能已经实测通过。
- 新增特效发光缓冲、场景颜色/深度输入与后处理合成，支持选择性泛光、场景扭曲、折射冲击波、短时色染与局部像素化。参考流程为：正常世界与网格 → 特效专属发光/扰动层 → 降采样模糊 → 采样场景并合成；不能只把网格 RGB 调亮来代替泛光。
- 每帧从网格使用的世界锚点和同一相机矩阵推导屏幕中心及半径。目标移动、相机转动、实体消失、切维度时，共享同一跟随/回退规则；不把所有冲击波固定在准星中心。
- 使用场景深度约束扰动与光效；目标在墙后、镜头背后或视野外时不应隔墙出现命中闪光或强制屏幕染色。镜头反馈另按可见性和距离衰减，合成时保持 HUD 清晰。
- 使用现有 Minecraft 1.20.1 / Forge 渲染能力优先实现。本轮调研不引入新的外部依赖；参考项目较新版本的功能仅作机制参考，具体 API 必须按本地 1.20.1 核实。数据包格式、技能触发和伤害结算继续保持现有语义。
- “自身发光/泛光”“场景染色”“实际照亮方块并产生动态阴影”分别记录。第一轮重做先交付真正泛光与场景冲击/折射；真实动态光照需单独核对光源、深度/法线与遮挡能力，不能用亮色光晕声称已经实现完整动态光影。
- 着色器注册、资源重载或运行异常时，将绘制切回当前基础顶点色网格；渲染结束恢复所需状态，避免影响后续世界渲染。
- 先以游戏内资源重载和强制走回退路径验证安全边界，再评估与用户实例中实际安装的渲染类模组组合；规划不预先承诺对未测试组合的兼容性。

## 七、风险与控制

- **视觉风格不统一：**以九命途视觉表和共享材质参数控制风格，先验收三类代表原型，再扩展剩余命途。
- **着色器失效导致特效消失：**基础网格必须能独立显示，着色器作为增强层接入并验证回退。
- **半透明效果遮挡或排序异常：**优先局部、低覆盖率的高光和流动层，逐事件检查深度与透明排序。
- **复杂度影响帧率：**同时控制网格、离屏缓冲与全屏采样预算，按细节降低模糊分辨率与扰动层数；通过实机记录确认成本，不预先承诺未经测量的性能改善。
- **多人同步范围不明：**本版不改现有服务端事件和数据包语义；视觉改动仍须区分单人验收与多人同步验收。

## 八、阶段记录

- 规划方向已确认：保留几何网格塑形，叠加着色器丰富局部表现。
- 初步源码盘点：现有 `CombatVfxPacket.Kind` 有 26 种事件；战斗网格目前使用基础顶点色 shader，顶点格式为 `POSITION_COLOR`，使用半透明混合、世界深度测试且不写深度；细节档位为每特效 10/16/24，活跃事件上限为 12/24，每特效最多 6000 面片、全局最多 48000 面片。项目另有界面和列车用自定义核心着色器。
- 已查阅 1.8.0 原型 README、HTML、命途配置及几何脚本；以 README 最后的迭代记录为准，其中明确写明 HTML 负责设计参考、不是渲染管线验证，因此无须重进游戏观看已验收的旧效果。
- 事件触发、锚点、并发关系与表现职责已按当前服务端调用点及 HTML 基线细化成表。发现 `HARMONY_CONCERT` 当前只以玩家作为来源和目标，而 HTML 设计要求击杀点到玩家的回响；计划用现有坐标字段修正视觉锚点，不改数据包格式或玩法结算。
- 规划已细化到事件级；精确动画参数将在混合原型中验证，颜色值沿用现有 HTML 配置，不另造一套调色板。
- 用户已实测第一轮 `1.22.0-stage1`，视觉未通过：与纯网格区别不明显，需要华丽且有命途特色的着色器表现。本轮已调研 Photon、Veil、Lodestone 的官方资料，撤销限制帧缓冲/后处理的旧边界，新增选择性泛光、场景折射、冲击、染色、局部像素化与相机反馈目标。
- 阶段 1 原型及九途视觉均已由用户验收通过。阶段 2/3 实现完成；阶段 4 新增画质档位自适应与韧性预览命令，离屏 OpenGL 检查通过，用户反馈 `libs/starrail_sim-1.22.0-stage4-quality.jar` 实机测试通过。阶段 5 最初的原版音源试听包已由用户反馈过于原版；第一版原创程序合成音效试听反馈不错，增强层次后的第二版也已获用户确认。发行复核确认从阶段 4 包到阶段 5 的视觉着色器及网格类文件未变化，增量集中在音效及对应文本。正式 `1.22.0` 已发布；单人验收通过，多人同步未验证。
