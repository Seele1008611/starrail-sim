# 1.3.0 规划草案与补充验收清单

> 状态：1.3.0 已于 2026-10-05 发布。本计划记录的九种守卫室主题、结构蓝图、客户端观察和专用服务器验收均已完成；后续奖励一致性与多人范围另行规划。

## 版本目标建议

`1.3.0` 本轮定位为“九种命途守卫室主题细化”。已通过的 `1.2.0` 验收作为设计基线；先制作并审阅可逐块参考的 HTML 视觉稿，再把确认的模型转成游戏资源并进行客户端观察验收。保持现有核心循环和熟悉的原版玩法，不叠加复杂谜题或大型新系统。

### 设计约束

- 遗迹仍共用普通母体布局；第二稿通过不同的立体梁架、拱廊、悬环及侧壁构件表达命途，原版材料配色作辅助。
- 监守者继续使用原版实体和战斗属性，不添加 buff、装备或额外技能。
- 不更改已经通过测试的命途试炼、凭证消耗和光锥叠影规则，除非验收发现确切缺陷。
- 任何新增玩法先做 HTML 视觉稿和流程说明，再决定是否实现。
- 同属 Minecraft `1.20.1` 的 Mod 版本升级不单独安排旧存档迁移验收；只有 Minecraft 基础版本跨版（如 `1.20.1` 到 `1.21.1` 或 `26.1`）时，才计划存档兼容性测试。

## 第一阶段：补充验收

这些项目曾用于确认验证范围，不等于已经确认要改代码。A、B、C 均已在 `1.2.0` 打包发布前通过，不再列为待测项；结果依据既往助手测试记录及用户确认回填。旧档兼容性按 Minecraft 基础版本跨度策略处理，不列入本阶段同属 `1.20.1` 的待测项。

| 优先级 | 检查项 | 通过条件 | 当前状态 |
| --- | --- | --- | --- |
| 已完成 | 自然生成母体的守卫状态保存（区块离开、单人存档退出重进、击败与奖励状态） | 同一守卫不重复生成；击败前状态锁定；击败后门与奖励状态保存，箱子不重复发奖 | 发布前五项检查通过（用户确认）；自然生成样本的专用服务器重启未单独验证 |
| 已完成 | 低入口下玩家与原版监守者的进出战斗 | 玩家能进入、撤退和返回；监守者保持原版行为，不被结构困死 | 发布前通过（用户确认） |
| 已完成 | 九种变体战利品 GUI 抽查 | 各箱奖励与命途凭证对应，无空箱或错绑 | 九种均通过（发布前助手实测，用户确认） |
| 待定范围 | 多人支持 | 是否把多人流程纳入 1.3.0；若纳入，再验证守卫进度、命途与寻迹状态的同步隔离 | 尚未决定，不因视觉稿改变当前多人状态 |

### 验收后的分流

1. 发现会丢存档数据、绕过奖励条件或阻断正常流程的问题：先整理为 `1.2.1` 修复范围。
2. 仅有显示、材料或说明不清的问题：纳入 `1.3.0` 的轻量打磨候选。
3. 全部通过：再冻结 `1.3.0` 的新增范围，不为凑版本而强行加功能。

## 第二阶段：主题设计与资源实现

已选定 A 进入视觉设计；B 保留为后续核对候选，不在本轮修改奖励。

### A. 九种守卫室的主题辨识度

沿用现有守卫室的战斗路径、监守者位置、门和宝箱坐标。HTML 第二稿以九种不同空间轮廓、梁架纵深、地坪纹样和高位构件区分命途；材料限于 Minecraft 1.20.1 原版方块。用户已认可主题方向和逐层参考图。

**资源与验收状态：**游戏蓝图导出器可直接读取 HTML 守卫室坐标模型；九个命途变体的 `*_guard.json.gz` 已按新模型生成，并合入原遗迹完整外壳。普通母体、自然生成、守卫逻辑、战利品和试炼逻辑沿用既有实现。九种新主题已通过客户端观察；1.3.0 发行 JAR 的普通母体及九种变体模板已通过 Forge 专用服务器读取与放置验收。

### B. 遗迹奖励与说明一致性

用一张表核对十种遗迹的宝箱类型、凭证命途、战利品表和命途指南提示。只修复明确的不一致；如要调整掉落价值或加入新物品，先列出各档奖励和获取频率，再做设计稿，不直接改现有掉落。

### 推荐范围

本轮完成 A 的视觉设计、分层蓝图、材料规格，并把九种变体模型导入游戏资源。仍复用现有入口、低位战斗空间、守卫、铁栅门、梯井和宝箱坐标。命途符号为方块化建筑意象，不宣称是官方徽标。照明使用原版固定色光；彩色玻璃不产生彩色投光。HTML 材料数量只统计守卫室，不代表整座浮空遗迹的材料量。

## 发布与清理约定

- 发布前记录版本内容、验证范围、发行 JAR 校验值和已知边界。
- GitHub Release 确认完成后，可以删除项目内 QA 测试存档和临时服务端文件。
- 保留 Gradle 缓存，避免下次构建重复下载依赖。

## 后续议题

- 九种变体奖励与命途说明的一致性，另行设计和验收，不属于 1.3.0 的改动。
- 多人连接支持范围尚未决定；决定纳入版本后再编写双客户端专用服务器验收步骤。
- 跨 Minecraft 基础版本时再安排旧档迁移测试；同属 1.20.1 的 Mod 版本更新不单独安排此项。

1.3.0 的客户端观察与专用服务器结果见[手动验收记录](1.3.0手动验收步骤.md)和[服务端验证报告](../遗迹设计/测试记录/服务端验证报告-1.3.0.md)。
