# 1.20.0 版本计划：命途遗境地下生态与洞穴探索

日期：2026-10-21。当前状态：**阶段 0 至 5 的单机验收均已完成，1.20.0 正式版已发布到 GitHub Release v1.20.0。多人服务器同步仍未测试。**

## 一、版本目标

1.17.0 建立命途遗境维度与两片陆地区域，1.18.0 完成陆地生态和基础生存成长，1.19.0 补齐星潮海域与澄沙海滩。1.20.0 建议沿垂直方向继续扩展，让地表生态之下也有可识别、可探索、能带回实际用途的洞穴区域。

本版的探索循环：**在四个地表群系中发现洞口 → 沿洞穴通道深入 → 辨认洞厅、地下水与特色生态 → 采集可持续或装饰性资源 → 记录发现并循路返回地表。** 洞穴内容应服务于探索和建造，不增加强制生存负担或装备成长门槛。

### 设计目标

- 洞穴在视觉、地形和生态上与命途遗境现有岩层有区别，同时保留自然洞穴应有的黑暗、纵深和不规则路线。
- 地下区域应与已有四个地表群系共存，让玩家能从不同地表区域进入或发现相应洞穴；洞穴本身不切断现有陆地、海岸和海洋循环。
- 让洞口、洞厅、地下水和特色生态形成能读懂的探索路线，避免只靠稀有战利品或盲目挖掘寻找内容。
- 让新增资源主要用于照明、装饰、建造或可选探索；霞铜、曦铁、曜金、谐振晶、记忆晶、星髓、星炭、星琼和古老梦华继续遵循共享成长资源原则。

## 二、现有基础与技术约束

- 命途遗境现有晴穹草甸、流萤林地、星潮海域和澄沙海滩四个地表群系；共享矿物在四个群系的地下岩层中都有配置。
- 维度噪声设置的建造范围从 Y=-64 开始、高度为 512 格，并使用原版洞穴噪声/密度节点形成地下洞穴与含水区域。
- 当前 `multi_noise` 群系源中，四个已注册群系的 `depth` 参数均覆盖 `[-1, 1]`。新增洞穴群系不能只添加一个群系 JSON；需要先设计垂直群系路由，再检查它是否影响地表群系边界。
- 当前地形共用 `the_path` 噪声设置；对密度场、洞穴入口或群系参数的调整可能影响四个地表群系、矿物宿主岩层、海底和水体。阶段 0 必须先采样，再冻结实现方案。
- 普通遗迹、命途遗迹和遗器决斗场已有独立生成与定位规则，本版延续 1.18.0/1.19.0 的边界，保留现有蓝图、材料与生成范围。

## 三、洞穴方向与初步内容构想

### 1. 地下群系

初步建议新增一种跨越多个地表区域的地下群系，工作名为“星脉洞窟”。最终名称、颜色和生成范围在阶段 0 采样后确定。让它成为同一维度地表下的自然区域，不新增第二个维度，也不为每个地表群系复制一套近似洞穴。

洞穴地形由几种尺度组成：

- 可从地表识别并安全进入的洞口或裂隙；不要求每个洞穴都直通地表，但主要探索区域应有可理解的出入口。
- 蜿蜒的窄通道连接开阔洞厅，让玩家能逐步辨认路线和深度变化。
- 少量地下水池、瀑布或含水岩层作为空间变化；避免洞水突然淹没长通道、洞厅，或打通海底造成水体异常。
- 洞壁和地面以本地石材为主，特色纹理、微光或晶簇只在有限区域出现，保持整体自然感。

洞穴面积、垂直范围、群系在四个地表区域下的分布比例和洞口频率暂不设定固定数值，须通过世界采样确定。

### 2. 洞穴生态与可收集内容

首轮范围建议控制在少量、用途清楚的新内容：

| 内容 | 初步方向 | 设计边界 |
| --- | --- | --- |
| 洞穴植物 | 优先评估现有流萤苔是否适合延伸到洞穴；若外观或生长条件不合适，再新增一种洞穴植物 | 用于局部照明、装饰或基础合成；不要求玩家为生存或装备进阶必须采集 |
| 岩壁特色 | 一种晶簇、矿脉外观或石笋类地质装饰 | 作为洞穴视觉地标和可选建筑材料；不增加新的装备矿物阶位 |
| 地下水域 | 少量水池、泉眼或落水通道 | 提供地形变化与回程参照；不加入强制氧气、口渴等新生存系统 |
| 主要探索点 | 一处稀疏的自然地质景观，例如大型晶簇厅或地下水源 | 先采用自然地貌特征，不扩成大型遗迹、副本或战斗竞技场 |

具体植物、方块、贴图、采集方式、配方和生成数量在阶段 0/2 进一步定稿；未确认的临时名称不作为正式内容承诺。

### 3. 探索与引导

- 给洞穴建立可读的空间地标，例如特色洞厅、发光植物带或独立地质景观；地标服务于方向辨认，不替代玩家自主探索。
- 评估将洞穴群系首次发现接入行旅档案，并补充指南和管理员定位入口。若同一洞穴群系跨越多个区域，档案记录方式应避免把一次首次发现误导成单一洞穴坐标。
- 玩家自然探索不依赖指令；命令用于管理、调试或找回已知区域。
- 若生成出的洞穴确实需要特殊路径提示，再考虑加入可制作的便携标记物；否则沿用原版地图、坐标和火把，不为增加系统而增加系统。

## 四、版本范围

### 纳入 1.20.0

- 洞穴群系或明确划分的地下生态区域，以及与之适配的洞穴地形生成。
- 少量本地洞穴植物、地质装饰和一个主要自然探索地标。
- 洞穴探索的指南、档案和必要的定位整合。
- 四个地表群系、海陆地形、共享矿物、返程流程和既有结构的回归检查。

### 当前不纳入

- 新装备阶位、新的稀有成长矿物，或把任何既有成长资源限制在洞穴中。
- 大型洞穴建筑群、Boss、副本、复杂任务链或额外战斗系统。
- 改造普通遗迹、命途遗迹或遗器决斗场的蓝图方块、材料、外观、奖励或既有生成配置。
- 新增口渴、氧气或其他强制生存条；改变 1.19.0 已验收的海洋/海龟和沿岸食物循环。
- 在没有采样和兼容性检查前重做整个维度地形噪声设置。

遗迹主题化换材仍留在[后续版本待办](后续版本待办.md)，不并入本计划。

## 五、阶段安排与验收

### 阶段 0：洞穴基线采样与设计冻结

- 在多个新世界和多个地表群系下采样现有洞穴，记录洞顶/洞底高度、洞厅尺寸、通道连通性、含水情况、地表开口和玩家可达性。
- 检查 `the_path` 的 `multi_noise` `depth` 选择器与现有密度路由，确定新增地下群系的实现路径；先做最小原型，不在未经验证前改动全部噪声参数。
- 选定一个洞穴群系或地下生态区域的名称、色彩方向、垂直范围、覆盖率及其与四个地表群系的关系。
- 冻结首轮植物、地质装饰、地下水域和自然探索点的最小清单；优先复用流萤苔的方块资产，确认是否值得新增独立植物，并写清用途、采集方式、再生性和资源边界。
- 明确洞口和洞厅生成是否会影响海底、岸线、既有结构、玩家建造区及共享矿物可读性。
- **阶段验收：**原型在新生成区块内稳定形成能进入、能辨认路线、能离开的地下区域；四个已有地表群系生成仍正常；不存在必须先拿高阶装备才能进入的软锁。

#### 首轮配置审查与运行采样（2026-10-20）

- `the_path` 维度使用 `multi_noise` 群系源和 `the_path` 噪声设置；四个地表群系的 `depth` 参数当前都覆盖 `[-1, 1]`。噪声路由保留了原版洞穴入口、奶酪洞、意面洞和 noodle 等密度节点；四份群系 JSON 也都启用了原版洞穴与峡谷雕刻器。因此现有地下已有洞穴地形，但还没有专属地下群系。
- 流萤苔当前放置规则使用 `MOTION_BLOCKING` 高度图和地表水深过滤，属于地表生成。若复用流萤苔方块，需要新增适用于洞壁/洞底的生成位置规则，不能直接复用当前放置配置。
- 在隔离的 1.20.1 Forge 测试世界中，以种子 `120020261020` 分别定位四个地表群系，并检查每个定位点周围的 3×3 区块，共生成 30 个维度区块。四处样本都检测到了地下空气洞穴；样本区块内洞穴空气高度范围约为 Y=-54 至 72，局部地表固体高度约为 Y=40 至 80。这里的高度范围来自四个 48×48 方块样本区，不代表单个洞厅或整个群系的平均洞穴规模。
- 在同一颗种子、四个定位点的垂直群系样本中，Y=-62 至 318 始终分别是对应的地表群系；当前配置没有产生垂直切换到地下专属群系的效果。这验证了新增洞穴群系必须同时设计 `multi_noise` 的垂直路由，不能只加群系 JSON。
- **专用服务端隔离修复状态：**`OpenLightConePassPickerPacket` 已将客户端界面调用移至独立 client 类，并通过 `DistExecutor` 限定客户端执行；之前的 `compileJava` 已通过。专用服务端运行验证尚未完成。当前 `run/eula.txt` 为 `eula=false`，本轮没有接受 EULA 或启动服务端，因此不能把这项记作实机通过。
- 用户已在隔离测试世界实机确认：地表下的自然洞穴显示 `star` 开头的候选群系；其余观察未发现异常；海床下洞穴自然含水，不属于异常进水。本轮确认了首轮路由可用，但没有覆盖第二颗种子。

#### 垂直群系路由离线原型（2026-10-20）

- 在 `开发记录/1.20.0阶段0深度路由原型/` 保存了独立数据包原型，便于复测和回退。
- 原型保留四个地表群系各自的温度、湿度、大陆性等参数，只把地表深度选择器拆为原版使用的 `0` 与 `1` 两个点，并增加一条跨气候范围的候选地下群系 `starrail_sim:starvein_cavern`，深度范围暂设为 `[0.2, 0.9]`。这是依据本地 Forge 1.20.1 `OverworldBiomeBuilder` 的参数路由形式拟出的验证起点，不代表已确定的世界 Y 高度或最终覆盖率。
- 两份 JSON 已做语法解析检查；用户随后确认游戏内洞穴已切换到候选群系。这证明首轮实际垂直选取有效，但不代表所有种子都通过。

#### 阶段 0 当前结论与待办

- 已确认的路线：保留现有四种地表群系的气候参数，以地表深度点 `0`、`1` 和候选地下范围 `[0.2,0.9]` 做 `multi_noise` 路由；首轮实机已见洞穴群系切换。阶段 1 继续检查四种地表边界与跨种子表现。
- 尚未确认的参数：地下群系最终垂直覆盖率、星脉洞窟名称/色彩、洞穴开口密度和流萤苔复用方案。海床下自然含水已通过首轮观察。
- 后续采样：用第二颗种子重复四群系取样，并记录洞口可辨认度和玩家进出路线。当前环境没有可操控的 Minecraft 客户端工具，后续运行采样继续使用隔离客户端测试世界。

### 阶段 1：垂直群系与洞穴地形

- 按阶段 0 结果接入地下群系路由和基础洞穴布局。
- 配置洞厅、通道、洞口与地下水域的地形比例；仅在需要时新增地表洞口地貌特征。
- 在多个种子、多个区域检查洞穴连通、封闭空腔、洞水溢流、海床穿透、地表塌陷和相邻群系边界。
- 对比改动前后四个地表群系、海床、地下岩层及其已有洞穴生成。
- **阶段验收：**地下群系能稳定出现；洞穴地形具有可探索的尺度变化；海陆地表、海平面和既有四群系没有退化。

#### 阶段 1 路由集成验收（2026-10-20）

- 已将首轮确认的维度 biome source 路由接入正式 `src/main/resources`，并加入 `starrail_sim:starvein_cavern` 地下群系。
- 地下群系暂时沿用已有九种共享矿物和基础敌对生物生成表；没有加入植物、晶簇或额外地质特征，待后续阶段设计与验收。
- 用户已在本地实例测试 `starrail_sim-1.20.0-phase1-test.jar`，反馈通过。多种子、四地表群系与地表洞口可达性回归仍未完成，因此阶段 1 的完整验收尚待后续回归。

### 阶段 2 首轮接入：洞穴流萤苔与原创星脉晶洞（2026-10-21）

- 复用已有全方块 `starrail_sim:glimmer_moss`，将其作为洞穴地面的低密度苔藓斑块；不改动它在流萤林地的原有地表生成规则。洞穴专属放置配置会从 `air` 和 `cave_air` 空腔向下寻找地面。
- 新增洞穴专属 configured/placed feature：仅在 `starvein_cavern` 群系内尝试，从洞穴空气向下扫描至固体地面；限制在 Y=-56 至 62 的垂直采样范围，单次斑块半径为 1–2 格，并关闭附带植被生成，避免引入未规划的原版花草或大面积覆盖。
- 用户实机观察确认：原先实现成每 36 个区块一次的普通矿脉，既不是晶簇洞，也难以在洞穴中看到；已撤销矿脉配置，按“自有晶簇替代紫水晶、生成晶簇洞、加入晶簇芽各阶段”的要求改为完整晶洞。
- 晶洞采用 Minecraft `geode` 特征机制，但内外层全部使用模组方块：`starvein_crystal` 晶簇内层、`budding_starvein_crystal` 可生长芽基座、`starvein_geode_crust` 晶洞内壳、`starvein_geode_shell` 外壳，以及小/中/大晶簇芽和成熟星脉晶簇。芽基座以 1/5 的随机刻机会尝试在相邻空气/水中生成小芽或推进同朝向芽的生长阶段；四个芽/晶簇朝向、碰撞形态、发光和水下状态由自定义方块处理。
- 晶洞只在 `starvein_cavern` 群系生成，范围 Y=-56 至 -8，放置尝试频率为每 8 个符合条件的区块一次；结构含空腔、晶簇内层、可生长基座、原创内外壳和朝洞腔的晶簇装饰。方块贴图均为独立 16×16 像素资产，原图与最终像素图归档在 `崩铁/物品/方块与材料/`，不复用原版紫水晶贴图或方块。
- 全新生成区块实机验收已通过：能发现星脉晶洞；镐子可采集晶洞材料和各阶段晶簇，基座可掉落；最大晶簇芽可被选中并有匹配模型的碰撞形状。旧世界已生成区块不会追溯补生成。独立地下水域和大型自然地标交由阶段 3 处理。

### 阶段 2：洞穴生态与采集用途

- 按阶段 0 冻结方案接入并验收洞穴植物、原创地质装饰和生成特征。若复用流萤苔，为洞穴单独配置生成位置条件，保留流萤林地现有地表生成行为。
- 确认植物生长基底、光照/含水限制、掉落和再种植行为；确认地质装饰的采集工具、掉落与用途。
- 所有特色资源在自然探索中有足量但不过量的稳定来源；不作为装备成长或生存食物的必需门槛。
- **阶段验收：**特色内容只在合适洞穴区域生成，采集与再生逻辑稳定；地标清楚而不覆盖大量洞壁或矿脉。

### 阶段 3：自然探索点与路线辨认

- 接入一个主要自然地质景观，优先复用洞穴自身地形特征，不加入大型结构模板。
- 调整洞口、洞厅、地下水和特色生态的空间关系，使玩家能从环境中判断大致方向和回程路线。
- 检查探索点与普通遗迹、决斗场及命途遗迹的间距和空间兼容；不改变现有结构内容和生成配置。
- **阶段验收：**探索点数量和分布自然，能提供可选目标；玩家可以不依赖命令找到入口并返回地表。

#### 阶段 3 首轮接入：大型星脉晶簇厅（2026-10-21）

- 新增稀有的大型星脉晶簇厅，复用星脉晶洞的原创内层、外壳、晶簇和可生长基座方块，不使用结构模板或原版紫水晶素材。
- 它仍由原版 `geode` 地质特征生成，外壁距离与生长点间距大于普通晶洞，形成更开阔的天然晶簇洞厅；仅在星脉洞窟群系、Y=-56 至 -8 之间生成，尝试频率为每 64 个候选区块一次。
- 洞厅特征安排在地下矿物与普通晶洞的生成阶段，洞穴流萤苔仍在后续植被阶段生成，可为洞厅地面提供少量辨路参照。

## 六、主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 新增地下群系改变地表群系分布 | 阶段 0 先验证 `depth` 路由；阶段 1 用多种子对照地表群系占比与边界 |
| 洞口不明显或玩家难以找到 | 在自然地形采样中确认入口可读性；需要时以少量地表入口特征引导，不把定位指令作为生存必需 |
| 洞穴面积太大或把地下挖空 | 调整地下群系范围与洞穴密度，分别观察通道和洞厅；不使用全局增大洞穴的方式追求可见度 |
| 海洋、海床或水体被地下洞穴打穿 | 专门采样海底下方洞穴和含水层；检查水体边界、海底矿物和玩家可达路径 |
| 矿物裸露比例失衡 | 以洞穴暴露面和完整岩层分别统计可见性，调宿主与特征参数，不用提高稀有度掩盖宿主错误 |
| 归档和定位显示不清 | 明确记录的是首次发现的洞穴区域还是具体入口；测试多人数据同步条件，未测试的范围如实记录 |

## 七、暂定原则

- 本版先验证一个地下生态主题，暂不扩成多套洞穴群系；是否需要第二套由阶段 0 的地形样本决定。
- 新增资源优先具有装饰、照明或建造用途，不形成装备等级和生存进度门槛。
- 洞穴探索依赖环境地标与原版生存工具；仅在必要时增加指南、归档或可选定位。
- 版本最终名称、群系覆盖率、洞穴高度、洞厅尺寸、洞口频率、植物和资源数量以阶段 0/1 的采样结果定稿。
