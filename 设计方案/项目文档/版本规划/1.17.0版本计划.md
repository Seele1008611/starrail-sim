# 1.17.0 版本计划：命途遗境（设计提案）

日期：2026-10-14。当前状态：**1.17.0 内容实现已进入本地发行候选阶段；单人新世界验收已覆盖主要玩法。最新候选还需确认角色详情玩家模型固定正面显示，之后再决定公开发布。多人服务器和多种子生成未专项验收；旧存档兼容按用户要求不作为阻断项。**

## 一、设计定位与成长优先级

新增维度“命途遗境”（英文名：**The Path**），作为命途、行迹、光锥、遗器和遗迹挑战共同发生的主舞台。维度目标不是刷齐某一套装备，而是让玩家在探索和挑战中持续推进模组的核心成长。

建议将成长优先级定为：

1. **主目标：踏上并提升命途阶位。** 玩家选择命途后，通过对应战斗行为积累践行度并完成晋阶试炼。这是模组最具辨识度的长期成长线；维度要提供持续练习和挑战的场景，但不通过一次性任务大量赠送践行度，也不绕过现有晋阶规则。阶位体系后续可继续扩展，不把七级当作最终等级上限。
2. **命途专精：解锁和升级行迹。** 行迹强化当前构筑，是命途成长的纵向专精线；对应行迹材料继续由命途主题遗迹与监守者奖励提供。
3. **构筑装备：获取光锥和遗器。** 光锥与遗器负责调整打法和补强生存/输出，与阶位成长并行。它们应该能帮助玩家推进命途挑战，但不应成为踏上或提升命途的硬性门槛。
4. **探索完成度：发现区域、遗迹和试炼。** 星轨档案提供长期探索目标和纪念性奖励，不取代前三条成长线。

因此，首版核心循环应是：**探索命途遗境 → 找到命途主题遗迹并完成初始试炼 → 通过实战提升命途阶位、挑战晋阶 → 收集行迹材料与光锥/遗器改善构筑 → 挑战更高阶内容。**

## 二、世界观提案

原作设定中，星轨连接群星间的世界，无名客乘坐星穹列车沿开拓之路继续探索。命途遗境可以作为本模组原创的“失联星轨夹层”：它不是原作已有的星球、记忆区或模拟宇宙，而是一段从航图上脱落、被不同命途的旅者遗迹与未完成线路逐渐占据的未知空间。

当玩家完成原版主世界的群系探索，星穹列车模型显现出一条未登记支线。放置并右键模型，列车便打开通往命途遗境的路线。遗迹与挑战解释这条线路为何中断；玩家的探索则让路线重新连通。

叙事通过环境、航图记录和遗迹内的短文本呈现，采用宇宙尺度、旅途感与克制留白；不直接借用原作角色经历或台词，也不宣称本模组原创剧情属于原作正史。

## 三、两个区域与新方块提案

两个区域要有明显不同的地形轮廓、空间尺度、色彩和玩法，同时共享星轨/列车视觉语言。方块名是工作名，正式命名可在贴图和游戏内效果确认后微调。

### 1. 星轨旷野

- **景观与玩法：**开阔的异星地貌、断裂地层、悬空岩台和横贯天际的废弃轨道。以深蓝、冷青为主，少量暖金信号灯作为远处导航点。保留足够大的稳定地面；危险来自断轨、落差、路线绕行和分散的原版敌对生物，不让玩家全程走钢丝。
- **新地形方块：**`星屑岩`作为主要岩层，`星尘土`作为地表，少量`星轨砂`形成沉积地带；`星脉晶簇`作为可见的天然矿晶与局部光源。
- **建造方块：**`星屑岩`及`星轨切岩`的砖、錾制、楼梯、台阶和墙变体，支持玩家把探索地貌带回建筑使用。
- **区域目标：**寻找勘测信标、补全断裂航图、发现偏离主路的遗迹和补给点。

### 2. 回响终站

- **景观与玩法：**一座废弃的星轨换乘站及其周边遗构，包含多层站台、悬空廊桥、封闭车厢、维护隧道和向下延伸的遗迹。空间紧凑、垂直且视线受限，与旷野的远距离观察形成反差。色彩以暗银、黑蓝为底，线路与站台信号使用冷青色。
- **新建筑方块：**`终站合金`、`终站合金砖`及其楼梯、台阶、墙和柱变体；`旧轨铺板`、`断轨构件`用于站台与廊桥；`导光玻璃`和`终站信号灯`负责窗口、路线指示和照明。
- **区域目标：**恢复线路节点、找到站内航图记录、辨认岔路并开启终点试炼。机关需要给出可读线索，不能以随机猜谜或迷路充当难度。

### 共用功能方块和方块集要求

- `星轨信标`作为共用功能方块：在各区域记录航图节点、标示已探索地点，并为玩家提供清楚的路线反馈；它不应该吞材料或成为命途等级的额外刷取门槛。
- 星轨中继站使用终站建筑方块，提供安全出生、行旅档案、试炼入口和返程列车。
- 每个区域至少要有可用于地形、结构、光源和玩家建造的完整基础方块组；新石材要提供常用楼梯、台阶、墙等变体与合理配方。方块要在自然生成、结构蓝图、物品模型、掉落表、采集工具和指南描述中一致。
- `星脉晶簇`可掉落少量`星轨碎片`，用于修复可选航图节点或制作装饰，不作为命途升级的必需材料；避免新增矿物把命途主成长变成挖矿门槛。
- 首版不必一次做出庞大植物/木材套装，但不能只用原版方块换色来拼出两个区域；上述地形块、建筑集、导光/信标方块是首版美术框架的一部分。

### Blockbench 建模范围与工具建议

1.17.0 **需要使用 Blockbench，但只用于少量有明确立体轮廓的资产**：星穹列车小模型是必做项，因为它既是可放置入口，也承担重要的视觉识别；星轨信标或中继站控制装置可先用方块灰盒，确认确实需要独特外形后再做模型。星屑岩、终站合金等普通方块以贴图和标准方块模型为主，地形与大型遗迹由游戏内方块组合，不需要把整片场景建成单个3D模型。

- 列车模型先确定占地、放置朝向、手持/物品栏显示和玩家交互范围，再做低多边形方块模型；`.bbmodel`作为可编辑源文件，交付时导出 Forge 1.20.1 可用的 Java 方块/物品模型 JSON 和贴图。
- Blockbench 的 Java Block/Item 格式适合最多约 `3×3×3` 方块范围的静态模型；Minecraft Java 方块 JSON 以长方体元素表达几何。若设计超出这个范围、需要动画或复杂曲面，应改为多个方块组合或专门渲染方案，不要硬塞进单个普通方块模型。[Blockbench格式能力表](https://blockbench.net/wiki/blockbench/formats/)，[Forge 1.20.1 模型文档](https://docs.minecraftforge.net/en/1.20.1/resources/client/models/)
- 工具优先考虑 [Jason Gardner 的 Blockbench MCP](https://github.com/jasonjgardner/blockbench-mcp-plugin)：它同时提供无需启动编辑器的 headless `.bbmodel` MCP 和连接桌面 Blockbench 的 MCP，能创建/编辑/校验模型、导入导出 Java 方块/物品 JSON并渲染预览；仓库还提供 Codex 配置示例和配套的建模/贴图 Skills。[headless 工具说明](https://github.com/jasonjgardner/blockbench-mcp-plugin/blob/main/headless/README.md)、[配套 Skills](https://github.com/jasonjgardner/blockbench-mcp-project/tree/main/skills)。先用 headless 做列车第一版和格式校验，再按需要用桌面 MCP 微调；`--root` 限定模型文件访问目录。
- 桌面 MCP 默认只监听本机；`risky_eval` 可执行任意 JavaScript，建模时建议关闭。headless 渲染器首次使用会在用户缓存目录下载约130 MB资源，可通过 `BB_RENDER_HOME` 改位置；若不需要 MCP 渲染，可跳过这项缓存，改在 Blockbench 中检查。[安全说明](https://github.com/jasonjgardner/blockbench-mcp-plugin#security)
- 工具安装与游戏实现分开管理，MCP/Skill 只用于开发阶段，不作为玩家运行模组的依赖；在实际建模前先确认模型尺寸、目标格式和列车参考图。作为对照，[sosadly 的 Blockbench MCP](https://github.com/sosadly/blockbench-mcp)也能直接操控编辑器和导出 Java 模型，但本项目更适合优先采用同时有 headless 工作流和 Codex 配置/Skills 的方案。

## 四、将现有遗迹与遗器决斗场迁入维度

核对当前代码后，现状需要准确区分：**普通浮空遗迹和遗器试炼决斗场使用自然生成；九种命途主题遗迹则由玩家开始“命途寻迹”后在指定坐标放置，并非九套各自随机自然生成。** 总计十种遗迹内容（普通遗迹 + 九种命途遗迹）和决斗场都应纳入 The Path。

建议迁移方式是保留玩家熟悉的获取和挑战规则，只更改生成维度并适配新地形：

- 普通浮空遗迹停止在主世界新区块生成，改在 The Path 的两个区域自然生成，继续作为探索入口、通用补给和玩法教学。
- 九种命途主题遗迹仍由玩家在命途界面开始寻迹后生成，目标位置改到 The Path；保留对应命途、宝箱、试炼凭证、初始试炼和监守者材料奖励。寻迹坐标、间距检查、保存数据和定位命令都使用 The Path 的维度数据。
- 遗器决斗场停止在主世界新区块生成，改在 The Path 自然生成；保留三波挑战、原版怪物筛选、所选套装和胜利后随机掉落1～3件遗器的现有规则。生成密度应保证它可寻找且适合快速刷取，不让遗迹/决斗场互相覆盖。
- 两种自然结构可在两个区域按权重分布；命途寻迹遗迹应优先落在安全、可达的地面或专门遗迹区，不能随机悬在虚空或埋入不可抵达处。
- 本版将普通浮空遗迹与遗器决斗场迁入 The Path，但保留现有结构蓝图的方块与外观。维度自身的新方块种类和区域内容尚需继续完善，遗迹蓝图换材不属于 1.17.0。
- 迁移只影响更新后新生成的区块。旧存档已生成的主世界遗迹和决斗场不会自动删除；更新后 The Path 的新区域按新配置生成。

## 五、进度主线与现有系统的连接

建议按“解锁旅途 → 选择命途 → 阶位成长 → 专精与装备并行”组织玩家目标：

1. **解锁旅途与命途线索：**探索完原版主世界群系后，服务端发放星穹列车模型；玩家获得模型时，同步解锁 UI 中的命途线索。模型既是进入 The Path 的入口，也成为命途系统的解锁凭证，不再要求玩家额外持有钻石。原版1.20.1对应进度是`minecraft:adventure/adventuring_time`，含53项原版群系条件。多人游戏按个人进度处理，背包满时不得吞奖励。
2. **开启命途：**获得命途线索后，沿用现有命途入口和初始试炼逻辑。玩家选择命途后，命途寻迹会在 The Path 安排对应主题遗迹；玩家前往宝箱取得对应凭证，完成初始试炼后踏上命途。进入维度和解锁线索共用列车模型这一条件，避免形成两套重复门槛。
3. **提升阶位：**踏上命途后，继续沿用现有战斗行为积累践行度和各阶晋阶试炼。区域敌对遭遇、遗迹监守者和决斗挑战为实践提供场景；不得通过大量任务奖励直接跳过既有的晋阶节奏。试炼难度可以按命途阶位提供层次，但七级不是维度故事的永久终点，后续可接入更高阶位。
4. **强化专精：**九种命途遗迹/监守者保留命途对应的行迹材料掉落，让行迹树成为提升某条命途构筑的长期支线。行迹材料的获取概率与行迹材料总需求沿用已确认规则，1.17.0不借维度迁移擅自改数值。
5. **补强构筑：**遗迹宝箱继续承担光锥与路径相关奖励；遗器决斗场负责所选套装的遗器刷取。玩家可在提升阶位的同时准备装备，但没有光锥或齐套遗器也应能开始命途、参加初阶挑战。
6. **完成探索：**星轨行旅档案记录区域发现、节点恢复、十种遗迹线索和挑战完成情况，奖励探索纪念物及适量成长补给，不与命途阶位争夺主线地位。

## 六、奖励结构

- **普通遗迹：**探索补给、通用光锥/命途线索及环境叙事；不直接给足一整条行迹所需材料。
- **命途主题遗迹：**对应命途的初始试炼凭证、行迹材料来源和与现有规则一致的宝箱奖励；保留寻迹到达、开启宝箱、挑战监守者的完整链条。
- **遗器决斗场：**延续已有快速刷取定位及1～3件随机遗器奖励，奖励由本场所选套装决定。
- **区域探索与档案：**首次发现给一次性里程碑奖励，另有少量装饰/收藏内容；不靠重复踩点取代战斗成长。
- 首版优先复用已有材料，不急于添加新货币。若以后需要统一兑换，再将其设计成可选择命途、光锥、遗器多类补给的通用系统，而不是只服务一套遗器。

## 七、危险程度与敌对内容

整体危险程度以原版下界为标尺，但压力由地形、路线和战斗组合产生，不靠秒杀伤害或高密度刷怪。星轨旷野偏路线与地形风险；回响终站偏空间限制和试炼压力。

首版不新增维度专属生物。普通敌对遭遇建议限定在经过筛选的原版敌对生物，延续决斗场的兼容方向，防止整合包任意模组怪物无约束进入。禁用不适合快速挑战的实体，并用少量环境机关补充变化。

## 八、入口、返回与兼容边界

- 星穹列车模型为可放置、可交互的功能方块/模型；主世界群系探索条件达成后发放模型，并在玩家获得模型时同步解锁 UI 中的命途线索。右键模型进入 The Path。钻石不再作为命途线索的解锁条件。维度内的列车站点提供回主世界的路线，尽量送回进入前位置；位置不可用时回到安全备用点。
- 旧存档迁移时保留已有的命途线索、当前命途、阶位、行迹和相关数据，不因新入口条件而回锁。若玩家已满足群系探索条件但尚未获得列车模型，登录后补发一次；若模型已在背包或已放置，则补齐命途线索解锁状态，不重复发放模型。背包满时使用安全的补发方式，不能丢失奖励。
- 原版`adventuring_time`进度文件本身只检查群系位置，没有显式的维度限制。若条件严格要求53种群系必须在原版主世界探索，需要由服务端按主世界维度独立记录这些条件，再发放列车模型；不能仅依赖原版进度已完成这一事实。
- 多人进度、行旅档案和奖励按玩家保存；共用的自然生成结构由世界种子决定。死亡、重进、跨维度传送、区块卸载、服务器退出均要有安全回退。
- 提供管理员定位/测试命令，支持定位中继站、普通遗迹、决斗场和寻迹遗迹；正常游玩不依赖命令找路。
- 移除 The Path 之外的自然生成配置时不删除旧区块建筑；旧存档里已生成的主世界遗迹保留，避免破坏玩家建筑或宝箱状态。

## 九、实施顺序与验收重点

1. **维度骨架：**先注册并验证 The Path、传入/传出、返回点和测试命令。
2. **区域基础：**完成两个区域的核心方块集、地形和生物群系灰盒。
3. **入口与迁移：**接入主世界群系探索、列车模型发放、命途线索同步解锁和旧存档迁移。
4. **命途寻迹：**把九种命途遗迹的选址、放置、定位和数据保存迁入 The Path。
5. **自然结构迁移：**把普通浮空遗迹与遗器决斗场迁入新维度，并处理生成密度与结构避让；维持现有蓝图方块外观。
6. **探索体验：**补齐中继站、信标、指南和行旅档案，明确阶位成长为主目标、行迹和装备构筑为支线支持。
7. **整体验收：**验证新旧存档、单人/多人、旧区块兼容、所有遗迹奖励和完整进出维度流程。

第十一节给出了各阶段的依赖、实现范围和验收门槛；实际推进时以该详细顺序为准。验收重点是玩家能否自然理解目标次序：先开拓并踏上命途，再以阶位和晋阶为主成长，以行迹专精和光锥/遗器构筑提供支持；探索档案与维度奖励扩展旅途，但不抢走命途成长的核心位置。

## 十一、1.17.0 推荐实施顺序

本版本同时涉及维度注册、地形、方块、入口、进度迁移、自然结构和既有服务端系统。按依赖分阶段实现；每阶段先编译并完成对应的小范围验证，再进入下一阶段。大型结构迁移和内容美化放在维度能稳定进出、地形能稳定生成之后，避免多类问题同时出现时难以定位。

### 阶段 0：冻结接口与兼容规则（已完成）

- 确定维度、维度类型、生物群系、方块和结构的注册 ID；确定世界高度、出生枢纽坐标、返回位置规则、时间/天空表现和两个区域的边界或分布方式。注册 ID 一经公开进入存档，不在后续小版本中随意改名。
- 同时确定列车小模型的方块占地、外观朝向、手持/物品栏展示和交互范围；确认普通 Java 方块模型足以表达设计，还是需要拆成多个方块。
- 确认 The Path 只由本模组维度入口访问；确定调试传送、区域定位、结构定位和生成重置命令，命令不得依赖玩家手动编辑世界文件。
- 固定旧存档原则：保留已有区块、建筑、箱子、命途状态、行迹、装备、遗迹守卫和玩家坐标；新生成规则只作用于尚未生成的区块。移除旧世界生成配置不执行区块清理。
- **阶段验收：**完成维度 ID、区域草图、区块生成规则、旧档迁移边界和命令清单，之后才开始改动注册资源。

#### 阶段 0 冻结决策（2026-10-14）

- **工程基线：**模组 ID 为 `starrail_sim`，目标为 Forge 1.20.1；新维度及其注册资源统一使用该命名空间。维度、维度类型和生物群系 ID 定为 `starrail_sim:the_path`、`starrail_sim:the_path`、`starrail_sim:starrail_wilderness`、`starrail_sim:echo_terminal`。这些 ID 从首个进入存档的测试构建起保持稳定。
- **维度边界：**The Path 是单一维度，包含“星轨旷野”和“回响终站”两种生物群系。使用大片连续区域的多噪声分布，初始目标约各占一半；后续用多种子采样调整，避免零碎小斑块。高度范围为最小 Y=-64、高度 512，为大型浮空遗迹和地形上方净空留出空间；昼夜与天空效果沿用主世界，坐标比例为 1.0，不使用下界式光照、床或重生锚。首版不实现独立时间流速或自定义天空渲染。
- **安全枢纽：**出生/中继站预留在方块坐标 `(0,128,0)`，平台顶面为 Y=128，玩家落点为 `(0.5,129,0.5)`。该位置在生成时保留净空并提供实体平台；任何传送都先确认目标区块已生成、落点有地面且玩家包围盒无碰撞，失败时改用目标维度安全出生点。
- **列车模型：**功能方块 ID 定为 `starrail_sim:star_rail_train`，沿列车朝向占用前后两格（每格模型仍限制在 16×16×16 像素内）；前后段使用同一方块的不同状态，不使用方块实体或自定义渲染器。放置时朝向玩家，并检查后方空间可用；破坏任一段时同步移除另一段且只掉落一个物品。物品栏与手持使用完整两格列车模型并单独校准。主世界、下界或末地右键任一段进入 The Path；在 The Path 右键则返回进入前的维度与位置，作为同一模型的双向入口。
- **往返记录：**服务端按玩家保存来源维度、坐标、朝向和俯仰角；进出逻辑只在服务器执行。返回时优先用原落点，其次在来源维度寻找最近安全落点，再使用该维度出生点；来源维度记录缺失或无效时回退至主世界出生点。死亡、断线和重启不清空记录，成功返回后才消费本次记录。
- **注册 ID 规则：**两个区域生物群系分别使用 `starrail_wilderness`、`echo_terminal`。方块 ID 使用稳定英文名：星轨旷野基础组 `star_dust_stone`、`star_dust_soil`、`star_rail_sand`、`star_vein_crystal`；回响终站基础组 `terminal_alloy`、`old_rail_platform`、`broken_rail`、`luminous_glass`、`terminal_signal_lamp`；共用功能方块为 `star_rail_beacon`。石材变体按 `_bricks`、`_slab`、`_stairs`、`_wall` 等后缀扩展。命途遗迹、普通浮空遗迹及决斗场的现有结构 ID 全部保留，只调整生成维度与目标群系。
- **调试命令：**沿用现有 `/starrail` 根节点，新增管理员命令 `/starrail dimension enter`、`/starrail dimension return` 和 `/starrail dimension locate <region|relay|ordinary_ruin|relic_trial_arena|path_ruin>`；传送、定位均报告实际维度与坐标。不会提供删除整片维度区块的重置命令，以免误删玩家建筑；需要重测自然生成时使用新测试世界，结构测试只清理明确指定的测试区域。
- **旧存档边界：**修改生成配置只影响未生成区块；已有主世界建筑、遗迹、箱子、玩家能力和坐标不迁移、不删除。结构注册 ID 与蓝图格式保持兼容。列车奖励及命途线索状态迁移按阶段 3 的一次性补发规则执行。
- **工具交接：**Blockbench MCP 已连接。列车第一版采用 Java 方块模型，源文件存放于 `设计方案/遗迹设计/模型源文件/1.17.0/star_rail_train.bbmodel`；导出的方块模型与贴图放入 `src/main/resources/assets/starrail_sim/`。普通地形和建筑方块继续使用标准方块模型与贴图。

### 阶段 1：先搭可进出的维度骨架（已通过首轮游戏内验收）

- 注册 The Path 的维度类型、维度入口和最小可运行世界生成配置；先使用临时地表与单一测试生物群系，不急着接入遗迹。
- 实现管理员传入/传出命令和列车模型的最小传送闭环：从不同维度进入，记录原维度与坐标；从中继站返回原位置。原位置不安全或不可用时使用明确的安全备用点。
- 验证死亡、重生、退出重进、服务端重启、多人同时进出和跨维度区块卸载；保存的返回记录按玩家隔离，不能串到其他玩家。
- **阶段验收：**全新存档和已有存档都能启动；维度可重复进出；发生无效坐标时不会卡在维度或掉入虚空。

**当前进度（2026-10-14）：**已加入 The Path 维度类型、双区域生物群系与地形灰盒；管理员可用 `/starrail dimension enter` 和 `/starrail dimension return` 往返。中继落点使用旧轨铺板，来源维度/坐标/朝向保存在玩家持久数据中，并在死亡重生克隆时复制。玩家报告创建新世界、区域定位、进入与返回等本轮基础验收通过。死亡、重登、服务端重启和多人验收仍留待后续整体验收。

### 阶段 2：完成方块集和两个区域的地形灰盒

- 完成并扩展两区域所需的新地形、建筑、装饰、照明和共用信标方块，包括物品形式、模型/贴图、语言、掉落、采集要求、标签和配方。目前已注册的方块族仅是首批基础内容；继续补足两区域各自的材质与用途种类，不能只靠同一方块的楼梯、台阶、墙变体充数。
- **现有方块盘点：**星轨旷野目前有星屑岩、星尘土、星轨砂、星脉晶簇、星轨切岩、星屑岩砖；回响终站目前有终站合金、终站合金砖、终站合金柱、旧轨铺板、断轨构件、导光玻璃、终站信号灯；共用星轨信标。石材已有楼梯、台阶和墙变体。这批是两区域的起始材料，不足以构成完整地貌与建筑语言。
- **新增方块目录（工作名，接入时再冻结注册 ID）：**
  - 星轨旷野：`星陨岩`用于撞击坑与断层露头，材质以深蓝岩层和少量紫灰熔蚀纹理区别于星屑岩；`星脉岩`用于含晶脉的洞壁和山体层理，表现连续矿脉而非散落矿点；`星屑砾`用于崖坡堆积、岩台边缘和碎石路肩，按可下落砾石设计；`星轨砂岩`由星轨砂压实/烧制，用于沉积台地、遗迹基座和浅色地层；`星脉晶砖`由星轨碎片与石材加工，用作可建造的晶体装饰材，并提供克制的低亮度点缀。
  - 回响终站：`终站地板板块`用于站台、车厢和廊桥的主铺面，以分区拼板区分于合金砖；`终站格栅`用于高架检修栈道与设备通风口，采用能透光的镂空模型；`站台警示板`用于站台边缘和落差提示，以少量暖金/琥珀警示条对比黑蓝地板；`终站线缆槽`用于维护通道和设备墙面，沿水平/竖直线路布置；`风化终站合金`用于暴露外壳、废弃车厢和老旧支撑，加入受侵蚀的材质层次；`终站舷窗玻璃`用于车厢隔断和观察窗，保持透明但不发光，和导光玻璃区分用途；`终站导光条`用于地面边线、门框和线路指引，提供低于信号灯的辅助照明。
- **接入优先级：**第一批先做星陨岩、星屑砾、星轨砂岩、终站地板板块、站台警示板和终站舷窗玻璃，验证地表/建筑材质组合；第二批再做星脉岩、星脉晶砖、终站格栅、终站线缆槽、风化终站合金与终站导光条，并完成对应生成或配方。目录中的非立方体/定向方块需先验证碰撞、光照和模型状态，再决定是否纳入自然生成。
- **获取方式与配方：**每种新方块在定稿前都要写明稳定、可理解的获取路线，并与用途和稀有度匹配；自然地形材料直接在对应区域生成并可正常采集，建筑材料优先使用现有方块/原版材料制作，不把装饰方块绑到低概率掉落或额外刷怪门槛上。第一批中，星陨岩、星屑砾在星轨旷野自然生成后分别用镐、铲采集；星轨砂岩既自然沉积也可用4个星轨砂合成；终站地板板块由4个终站合金合成4块；站台警示板由终站地板板块与金粒制作；终站舷窗玻璃由玻璃和铁粒制作。第二批确定路线为：星脉岩在两区域地下岩层中自然生成并用镐采集；星脉晶砖用星轨碎片与星轨切岩合成；终站格栅用铁锭和终站地板板块制作；终站线缆槽用铜锭和终站合金制作；风化终站合金矿在回响终站地下自然形成小型矿脉，挖掘矿石后熔炼为终站合金锭；9个终站合金锭合成1个终站合金块，终站合金块也可拆解回9锭；风化终站合金装饰方块用终站合金块与星屑砾合成；终站导光条用终站合金与荧石粉合成。六种方块的配方、产量和采集工具随资源一并接入。
- **透明方块连接：**舷窗玻璃使用原版玻璃方块的同类面跳过逻辑，彼此相邻时不绘制内部面；贴图不在块面边缘画金属框，四边像素保持可平铺一致，避免每格重复出现边框或接缝。它保持半透明但不发光，金属窗框应作为独立装饰/模型，不烘在玻璃平铺贴图里。
- 所有新普通方块贴图保持 Minecraft 16×16 像素风格。每次用图像生成的高分辨率原图使用中文材料名作为文件名，不追加“生成原图”等后缀，归档到 `崩铁/物品/方块/` 供用户备份；缩放并替换游戏贴图前先备份旧资源。
- 普通平铺方块贴图采用 Minecraft 原生 16×16 像素风格，并遵循区域自身配色：星轨旷野以深蓝、冷青为主，暖金用于少量信号点；回响终站以暗银、黑蓝为底，冷青用于线路与站台信号。调整明暗时保留岩石、土砂、晶体、金属、玻璃和灯具各自的材质特征，不把整套方块统一涂成白色。
- 创建星轨旷野与回响终站的生物群系和地形配置，让它们在颜色、地形轮廓、空间尺度、照明和路径风险上可明显区分；添加地表覆盖与必要的矿晶分布。
