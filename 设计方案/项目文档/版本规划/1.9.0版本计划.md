# 1.9.0 版本计划

日期：2026-10-09；最新进度：2026-10-10。状态：遗迹体验、九命途平衡、属性上限和玩家HUD已接入并完成用户单人验收；攻击力同步及防御基值保存问题复测通过，进入1.9.0发布收尾。多人和AttributeFix共同加载未验证。

## 版本定位与范围

主题：遗迹战斗提示与重复挑战体验完善。

1.8.0 已发布，九命途网格特效和韧性反馈的单人验收通过，多人同步仍未验证。本版集中完善已有遗迹挑战流程，不制作九套监守者专属战斗机制，不新增怪物、攻击技能或战斗阶段。

遗迹提示直接沿用模组已有界面、字体、命途主题色和提示样式，不额外制作遗迹提示 HTML。新加入的玩家状态栏先制作独立 HTML 原型，确认后接入游戏。遗迹实现进度见 [接入记录](../开发记录/1.9.0遗迹挑战体验接入记录.md)，版本号在最终收尾时调整。

## 已有基础

- StarRailRuinGuardService 已维护守卫 UUID、首次通关、宝箱奖励、重复挑战与冷却状态，并提供召唤失败原因提示。
- 区块卸载或暂时查不到 UUID 不等于守卫死亡；显式丢弃的守卫已有恢复逻辑，应沿用并补查异常边界。
- PathRuinAnchorBlock 已校验匹配钥印。
- StarRailToughnessService 已处理韧性削减、击破与恢复，但没有独立韧性条。
- 首次通关宝箱提供对应可重复使用钥印；重复挑战击败后冷却 30 秒；监守者每次死亡有 30% 概率掉落 1 个对应材料。这些规则及正常踏上命途流程保持现状。

## 一、完善战斗提示

### 监守者战斗面板

- 显示实际遗迹监守者名称、命途、当前/最大生命值及韧性条。
- 显示韧性处于正常、已击破或恢复中；时间与数值来自服务端真实状态，不在客户端重新结算。
- 仅在玩家接近有效遗迹守卫时显示；离开、死亡、跨维度或守卫结束后及时隐藏。范围采用统一常量，实机调整。
- 多个遗迹靠近时优先显示当前战斗目标，其次最近守卫；不叠加多个大型面板。
- 优先在屏幕上方以紧凑面板呈现，避免遮挡准星、物品栏和已有伤害数字；面板不展示代码字段或 UUID。

### 挑战与结算提示

- 成功召唤后提示挑战开始；重复点击不会重复显示开始通知。
- 首次胜利提示宝箱室开放；重复胜利提示进入 30 秒冷却。
- 材料结果必须依据实际掉落判定，区分“本次掉落对应材料”和“本次未掉落材料”，不暗示物品已自动进入背包。
- 短通知采用现有提示样式，做去重与限频；详细原因仅在交互时说明，不每 tick 发聊天消息。

## 二、完善重复挑战体验

### 锚点状态

玩家看向或交互锚点时显示状态及所需钥印：

| 状态 | 玩家看到的提示 |
| --- | --- |
| 首次尚未通关 | 先击败本遗迹监守者，按现有宝箱/钥印流程继续 |
| 可召唤 | 使用对应命途钥印开启挑战，钥印不消耗 |
| 战斗中 | 监守者仍存活，不能重复召唤 |
| 冷却中 | 显示剩余秒数，归零后可再次召唤 |
| 暂时无法确认守卫 | 等待相关区块加载，不能据此判定胜利或重新刷怪 |
| 无法召唤 | 明确说明钥印不匹配、和平难度、锚点未绑定或生成失败等实际原因 |

冷却按现有服务端游戏时间处理，不改为离线现实时间倒计时。将“没有钥印”和“拿错命途钥印”的提示区分清楚。

### 异常情况与状态恢复

- 玩家死亡、离开或退出，只清理该玩家的显示状态；只要守卫仍有效，不自动判败、清除守卫或允许再召唤，避免影响其他参与者。
- 重进游戏或相关区块重新加载后，重新关联实际守卫和锚点状态；首次宝箱奖励只结算一次。
- 区块卸载、实体暂时无法查询不能触发胜利、材料掉落或新的守卫生成。
- 沿用显式移除后的恢复机制；补查旧 UUID、加载顺序与死亡/保存相邻的情况，保证同一锚点只有一只有效守卫。
- 材料掉落与胜利提示按一次真实死亡结算，避免重登、事件重复或恢复过程重复发奖。

## 三、开发顺序

1. 梳理现有守卫、锚点、死亡和韧性状态，形成开发记录；优先复用已有正确逻辑。
2. 接入监守者血量/韧性面板及服务端状态同步，补齐显示与隐藏条件。
3. 接入锚点状态、倒计时和精确失败原因。
4. 接入挑战开始、首次/重复胜利和实际材料结果提示，完成限频与去重。
5. 完善退出、死亡、区块卸载和异常移除的恢复边界。
6. 按验收清单进行用户实机验收；确认后更新版本号、离线构建及发布记录，再经用户授权发布。

先以巡猎遗迹检查面板与流程，验证后由共用逻辑覆盖九命途。此处样板仅用于展示与流程验证，不引入巡猎专属战斗技能。

## 四、验收清单

- 首次挑战、重复召唤、正确/错误/空手钥印：提示准确，与实际状态一致。
- 战斗中多次点击锚点：不重复生成守卫，不刷屏。
- 血量、韧性削减、击破和恢复：数值与服务端一致；近战、远程及不同 GUI 缩放均清楚可见。
- 首次胜利只开放一次宝箱奖励；重复胜利显示冷却，30 秒后可再次召唤。
- 材料掉落/未掉落提示与地面实际物品一致，30% 掉率及材料命途对应不变。
- 玩家死亡、离开、退出重进、区块卸载再加载：面板正常隐藏/恢复，守卫和奖励状态不乱。
- 管理员移除守卫等异常情况：不误判胜利、不重复发奖，按既有恢复规则重新允许继续挑战。
- 九种命途名称、颜色、钥印与材料对应正确；现有命途解锁、行迹及战斗特效无回归。
- 多人环境可用时补验多玩家交互、旁观显示、死亡/离开不影响其他参与者及只结算一次；环境不可用时明确记录未验证，不宣称通过。

## 工程约束

沿用已有 Java 17、Gradle 与 Forge 缓存离线构建，不新下载依赖；确实需要下载时先征得用户同意。按现有架构集中处理九命途，不复制九套系统。不主动增加自动化测试或新测试环境；测试客户端由用户要求时启动。项目当前版本维持 1.8.0，1.9.0 在完成实现与验收后收尾。
