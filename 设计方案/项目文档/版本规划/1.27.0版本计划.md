#### 灾变：同一模组内不同环境的具体做法

已阅读作者项目页，以及 `lender544/new1.20.1` 的结构源码/JSON，来源为1.20.1工程，未在本机安装或实机游玩。公开源码分支会继续变化，以下指本轮读取到的内容。

- **诅咒金字塔：地表地标与内部纵深结合。** `Cursed_Pyramid_Structure`先按地表高度定位，分别装配上、下部片段；其中下部偏移为-39，上部偏移为+9。`necklace`与`sus`结构标记会变成带独立战利品表的可疑沙，另有不同专属驻守实体的标记。说明奖励交互可以和建筑主题结合，不只是在终点放箱子。偏移是片段锚点，不当作整栋精确高度。
- **沉没之城：水下建筑有自身的分层与敌人体系。** `Sunken_City_Structure`组合上下部、寺庙及上下宝藏片段，存在相差38格的片段锚点；数据标记放置多种Deepling与Coralssus等驻守者，并设持久化。这里核实的是结构驻守生成，不宣称它们全由隐藏刷怪笼产生。
- **Acropolis：高空结构作为独立生成场景。** 结构JSON使用高空起始高度200、独立起始模板池与拼装范围配置。`max_distance_from_center=187`是配置约束，不等于建筑实际半径；`size=33`也不解释为33个房间。作者页面明确把抵达天空中的Scylla所在地作为挑战的一部分。

来源：[灾变作者项目页](https://www.curseforge.com/minecraft/mc-mods/lendercataclysm)、[金字塔结构源码](https://github.com/lender544/new1.20.1/blob/master/src/main/java/com/github/L_Ender/cataclysm/structures/Cursed_Pyramid_Structure.java)、[沉没之城结构源码](https://github.com/lender544/new1.20.1/blob/master/src/main/java/com/github/L_Ender/cataclysm/structures/Sunken_City_Structure.java)、[Acropolis结构配置](https://github.com/lender544/new1.20.1/blob/master/src/main/resources/data/cataclysm/worldgen/structure/acropolis.json)。

#### 此轮扩展后的规划要求

1. 新建筑提案须有环境覆盖矩阵，明确地表、海面、海底、空中与地下各方向的用途；不强制五类一律同数量，但不可再仅提出地下或地面小房屋便视为完成研究。最终做几座、选哪些环境，待完整提案审阅后确定。
2. 每座从“远处发现→准备与抵达→选择入口→分区探索→应对威胁→找到奖励→撤出”串起流程，并给出总览及分层/立体连接图。海底和空中额外说明可进入、可停留和可返回的路径。
3. 使用适合场景的敌人来源：隐藏刷怪笼、结构驻守、局部遭遇与重点战斗可以组合。前轮学习刷怪笼的结论保留，但不把所有场景改成隐藏刷怪笼竞赛，更不简单照搬灾变的Boss或召唤材料链。
4. 地形适配分开核定：地表承托、海面水位与登船口、海底水深/灌水范围、高空高度/落脚连接、地下岩层/入口。共享建筑模板逻辑不能抹掉各环境的探索差异。
5. 主体建筑须有足够可探索体量和有用途的空间。规模需由区域网络、层数与实际路线支撑；不靠空壳、重复长廊或把旧方案放大来达标。刷怪笼与常规驻守数量随空间设计，不再预设整座只有几只敌人。
6. 奇物先保持获取入口的规划边界。普通箱、隐藏奖励、考古等交互是可选择参考，不因此自动新增考古系统、飞行载具、水下装备、Boss或完整奇物机制；需要的新增能力在提案中明确说明并随方案审阅。

### 10.1 撤回首轮草案中的限制

- 撤回四座小据点和5–7只固定敌人的规模基线；四个旧名称、数量、尺寸与箱数均不保留为本轮约束，也不是简单等比放大原案。
- 撤回“消灭几名指定守军即可开唯一核心箱”作为所有建筑统一模板。普通探索宝箱、隐藏箱、危险区奖励和深层奇物获取点应有不同的位置与获取风险；是否锁箱取决于具体房间，不以全建筑清怪替代探索。
- 撤回“建筑内不持续补刷”的统一限制。常规驻守可负责第一接触，刷怪笼负责持续区域压力，玩家需要找出并破坏或按明确机制解除威胁源。刷怪笼数量、附近实体限制、间隔与空间连通共同控制难度；不一次性激活整座建筑全部区域。
- 撤回从末日兽月台平整要求延伸出的“所有主要探索建筑单层平面”。大型探索建筑可有楼层、地下层、回廊、竖井与高低路线；具体交战空间仍须保证动作净空、可辨识落点和可行退路。
- 先不冻结“每座恰好一个核心箱、固定世界共享领取、所有箱不可破坏”等实现选择。先设计宝箱所在路线与风险；奇物效果、品质、掉率和个人/共享奖励机制仍暂不细化。

### 10.2 新方案必须表现出的探索内容

1. **建筑整体与内部网络同步设计。** 给出总平面、分层图、连接关系、地标和空间功能。不能仅扩大墙体、把战斗厅复制几十次或用空走廊撑体积；也不先凭空冻结一组长宽数字。总尺度应能容纳多个有实际用途的区域和连续探索过程。
2. **路线有选择与回报。** 主线、岔路、回环捷径、隐藏空间及不同入口应清楚标出；玩家会判断先搜侧室补给、绕开射界，还是冒险深入。不能把所有箱子摆在入口可直达的主通道上。
3. **隐藏刷怪笼成为探索目标。** 按房间功能设计墙后凹室、楼梯下、墓室/设备底座或可疑封板等藏点；有声音、怪物来向、破损建筑或重复装饰等可读线索。敌人的生成区域与藏点要配合，不能把笼子关进没有有效生成空间的实心墙里，也不靠不可破坏墙制造无法处理的盲刷。
4. **敌人压力有层次。** 普通驻守、侧路伏击、远近搭配、重点房间及深层精英各承担职责。按各区域同时交战量、补刷速度和累计推进压力评估，不用整座建筑固定生成几只怪的总数作难度指标。可使用原版怪与本模组怪的合适组合，不默认所有房间都塞同一套虚卒或守卫。
5. **战利品位置推动探索。** 补给位于可争取的支路，隐藏奖励需要观察线索；高价值获取点位于更深或更危险的路线。并非每房都给箱子，也不必每个箱子都靠额外上锁。具体奇物奖励池后续再定。
6. **允许Minecraft式处理。** 玩家可搭路、破墙、封门或挖出刷怪笼；应在空间与藏点上设计挑战。是否需要个别特殊保护区另论，不先给整栋不可破坏或强制全清规则。对于飞行、挖穿直达、刷怪农场与多人分路，逐座评估而非一条规则全部封死。
7. **持续威胁可被消除。** 常规刷怪笼被玩家处理后，该区域能够真正变安全；重启/区块重载不自动恢复被破坏的笼子或重新灌入宝箱奖励。常规刷怪压力与核心奖励的不可重复生成分别考虑。

## 一、版本方向

继续打磨已经接入的命途战斗特效，并扩展到更多玩法对象和世界场景。优先提升动作可读性、视觉层次和触发反馈；内容一至三的视觉升级不改变既有玩法结算；内容四新增主动技能的伤害、护盾、治疗等玩法按该内容独立确认和实现，不借此改动已有被动。内容五重置模组音效，统一声音风格、时序和混音，不借机改变伤害/动作时点。

**2026-11-01 用户确认的创作原则：特效可以放开设计、发挥想象力，只要符合设定。** 可以大胆运用空间构图、立体造型、运动轨迹、材质、泛光与后处理，不预设只能使用少量粒子或轻微改色。视觉可读性和性能通过实现、画质分级及实机调整解决，不作为在设计阶段把效果压缩成简陋版本的理由。

### 版本内容一：命途特效深化与武器/工具轨迹

**目标：** 保留九命途已有的主题造型和已通过表现，逐项找出动作节奏、命中反馈、普通/强化层级或特效衔接仍可提升之处；同时加入玩家手持武器和工具的短时拖尾/挥动轨迹。

规划对象：

1. **命途效果复核与深化**：逐项回看 26 种事件及九命途预览，记录现有效果、既有通过状态、明确缺口和复现方法。只修改有具体问题或可形成明显提升的项目，保持命途间的造型、色彩、节奏辨识度；普通与强化效果有层级，但不靠单纯增亮或全屏盖色区分。
2. **武器挥击轨迹**：为近战武器规划可辨认的挥击弧/速度残影，并区分挥动、命中与余波。轨迹跟随实际挥击方向和手持物位置，不改变攻击时点、攻击范围或伤害。
3. **工具挥动轨迹**：为采掘工具规划与动作方向一致的短轨迹；可按工具类别和实际交互结果增加轻量命中/破坏碎屑。具体触发条件在设计阶段核对客户端动作与服务端方块结果后确定，避免空挥、持续挖掘和连续破坏时生成过密效果。
4. **可扩展轨迹基础**：优先共用有限的轨迹采样、宽度衰减、淡出和事件清理逻辑；避免每件物品复制一套渲染器。第一/第三人称、主副手、快速切物品、攻击取消、暂停及维度切换均纳入验证。

#### 具体要求

**命途范围：** 覆盖九条命途以及两种共用韧性反馈，逐项核对现有 26 类事件。先依据当前玩法确认视觉触发是否完整，再确定每项需补足的层次；不要求 26 类全部推翻重做。普通触发、持续状态和强化爆发应有不同表现强度，不能所有事件都用同一个环形爆炸模板。

| 命途 | 深化重点 |
|---|---|
| 巡猎 | 箭锋、汇聚方向、速度尾迹和终结命中的节奏；普通追猎与逆时追猎清晰区分，并核对 1.26.0 调整后的实际触发机制 |
| 毁灭 | 蓄势压迫感、裂火/热浪与强爆发层次；持续怒意保持轻量，爆发时再集中表现 |
| 存护 | 盾面厚度、展开与承击反馈、反震方向；盾与攻击者的位置关系清楚 |
| 智识 | 演算线、扫描和追加攻击的连贯性；多目标反馈只落在实际受影响对象上 |
| 虚无 | 标记、侵蚀、扩散与终结的先后关系；扩散有真实来源方向，持续状态避免高频闪烁 |
| 同谐 | 光带连接、音律节拍与回流；强化效果在节奏和构图上有区别 |
| 丰饶 | 治疗枝叶、甘露晶片、慈航绽放与回收光点；保持柔和、可读，避免遮住角色 |
| 记忆 | 冰晶、记录与回响的两拍变化；局部像素化/折返围绕真实目标发生 |
| 欢愉 | 棱面、卡片/面具、错拍与强化二次爆发；彩色点缀克制且保留主色 |
| 韧性反馈 | 普通受击轻量，击破清楚；与同次命途触发叠加时仍能辨认主次 |

**武器/工具范围：** 默认覆盖本模组六系列剑、镐、斧、铲、锄及虚质裂界刃，共 31 件；实施时按当前注册逐项核对。各系列以已有物品贴图配色为依据，同类共享轨迹结构，通过颜色、宽度和少量细节体现材质区别。护甲和原版物品暂不自动扩入。

- 剑与裂界刃：挥动时出现短弧或带状残影；实际命中才产生命中点反馈，空挥不伪造命中闪光。裂界刃可有独立的紫色裂隙主题，但不能使画面持续被特效占据。
- 镐、斧、铲、锄：轨迹服从工具头部的实际运动；采掘、攻击和右键功能分开识别。持续挖掘限频，工具右键成功时可使用短促交互反馈；具体触发清单在 1.2 阶段写明。
- 轨迹从上一采样点连续连接至当前点，头部清晰、尾部逐渐变窄/淡出；转身、低帧率或移动不应造成长距离拉丝。换物品、停止挥动、死亡、传送或切维度时及时断开采样。
- 第一人称不得遮住准星和主要视野；第三人称与其他玩家看到的轨迹应贴合手部动作。左右手分别取锚点，仅对游戏实际发生的动作生成效果。
- 提供轨迹开关及适当的强度/数量限制，复用已有配置或调试入口；不为本内容强制重做 UI。

**验收要求：** 同场景可看出深化前后的变化，仍保留原命途辨识度；实际战斗与预览一致；31 件逐项检查轨迹适用情况。连续攻击、挖掘和多效果叠加时不残留、不串线、不持续刷满屏幕，并记录性能对比与实机结果。

### 版本内容五：音效重置（选型与规划）

**提出日期：2026-11-02。** 内容一至四已按用户反馈完成实现与游戏观感验收；现按用户要求规划音效重置。整版回归、发布和没有单独反馈的多人/专项性能仍是版本收尾工作，不作为“尚未实现的新增内容”。本节保留新内容草案及技术选型建议。现Small-SFX本地GPU环境及离线生成技术自检已完成，首条巡猎破风获用户认可，新增八段代表候选待用户试听；其余模型未部署，听感选型与游戏资源替换尚未完成。

**目标：** 使用可本地运行的音效生成模型与必要剪辑/分层制作，重制本模组拥有或在自有机制中显式使用的声音，统一动物自然感、怪物辨识度与九命途音色。模型是离线素材制作工具；玩家运行模组时只加载普通音频资源，不需要安装模型或联网生成。

#### 5.0前的源码快照与范围

- 当前`sounds.json`包含65个事件。`sounds/animals`有5份、`sounds/voidranger`有7份、`sounds/combat`有26份OGG；事件会复用文件，65个事件不等于65份独立素材，也不是最终重制数。
- 原素材来源混合：动物/虚卒采用网站素材及剪辑；26类命途/韧性音效有本地合成脚本`tools/generate_combat_audio.py`；构装守卫仍显式使用原版铁傀儡攻击/受伤/死亡/脚步、紫水晶和铁砧等声音。正式盘点须同时查注册表、sounds.json、播放代码和原素材记录，不能只数sounds目录。
- 覆盖五种原创动物、四种虚卒和构装守卫的现有声音，以及九命途被动/主动、两类韧性反馈。武器工具拖尾、星轨信标/列车传送、遗迹/试炼台和UI等自有机制也逐项审查：已有声音列入重制清单，缺失声音提出新增候选；不默认给每个点击、每次普攻或每个静态方块强加声音。
- 不替换Minecraft全局音效、不改其他模组资源、不新增配音或背景音乐。共享原版声音只能在本模组对应播放点替换，不能覆盖minecraft命名空间影响全游戏。
- 动物保持用户此前确认的“叫声、受伤、死亡可共用本物种叫声”规则，不强制拆三套表演。自然动物保留动物感，不能再做成电子合成叫声；怪物、能量与机械装置允许合成音色。

#### 声音设计要求

- 每条命途建立一致音色：存护为厚重晶金共振、毁灭为裂火低频冲击、巡猎为锐利破风与星矢尾音、智识为精确扫描/计算脉冲、同谐为短和声与共鸣、虚无为低沉蚀解与收束、丰饶为自然生长/柔和生命脉动、记忆为清脆冰晶与延迟回声、欢愉为错拍彩色敲击。和声/节奏是短音效元素，不生成长段背景音乐。
- 同途被动与主动共享听觉主题，仍有强弱层级和独立事件；普通命中短促，主动施放、释放、真实命中与结束按实际阶段安排。丰饶主动正常触发被动时保留两者事实，混音避免叠成同一段重复轰鸣，不屏蔽实际触发。
- 四虚卒通过声纹/节奏区分，守卫体现重型构装与星脉核心；危险前摇/释放提示优先于装饰声。声音不能比真实命中提前制造命中假象，未打中不播放受击确认。
- 代表样本优先0.2–3秒有效声音；模型可生成2–6秒候选后裁切。持续声仅在确有需求时单列循环/结束点，循环须检查接缝，不直接把一次性爆发无限重播。
- 要求单一事件、干净近录感、无语音/旁白/背景音乐/持续底噪，起音清楚、尾音可控；对每条素材人工试听，不能只靠提示词保证。保留自然动物的身体感，不用重混响掩盖生成缺陷。
- 每个高频事件建议2–4个合格变体避免机械重复，低频事件不强凑数量。以合格率选择模型；生成候选与最终采用分开标注。

#### 制作、接入与归档要求

- 原始WAV、最终剪辑稿、提示词、模型/版本/来源、seed与采样参数、处理步骤和许可依据建立对应记录；按既有素材分类归档，不另建多个阶段文件夹。生成音效不按Freesound素材虚构作者，旧外部素材仍保留真实出处。
- 做裁切、短淡入淡出、必要去直流/降噪/均衡与音量匹配，保留动态；不能只统一峰值就宣称听感等响。建议最终峰值留约1dB余量，拒绝削波、截断尾音、空白长头或明显拼接声。
- 世界中需要方向/距离定位的声音输出单声道OGG Vorbis；UI/明确的非定位声音按设计决定声道。保留无损制作源，不把改扩展名当作格式转换。采样率与质量按素材测试统一，不强制把所有文件无意义上采样。
- 优先维持已有SoundEvent ID与字幕映射，审计复用关系；确需新增事件才补注册/中英字幕。单次事实只由一个权威入口发声，避免本地预测和服务端广播重叠；处理距离、类别音量、并发、限频及状态结束。普攻印记不默认每击额外播放大音效。
- 接入后再退役已无引用的旧运行时文件，保证回溯记录和采用的源稿仍在；不让资源清理误删仍被多事件共用的文件。

### 版本内容六：命途遗境群系与资源扩展

**提出日期：2026-11-02。** 用户希望继续增加群系、方块、材料和食物。用户已认可下列三个群系及资源方向，并要求补充一种兼具食材与装饰用途的海带状海洋植物；具体生成密度、配方和数值在阶段6.0确定。本阶段尚未制作资源或调整世界生成。三个候选各自有可辨认的地形、可获取的资源和实用去处，不增加新的强制装备等级。

#### 现有基础

命途遗境已有七个群系：晴穹草甸、星辉林地、静潮泽地、星砾高地、星潮海域、澄沙海滩和地下星脉洞窟。已有九种共享矿物、五种原创动物、四种虚卒，以及星薯、静潮稻、林息豆和晨露莓等食物资源。新增群系应继续接入现有维度，而不是另建维度或取代原有区域。

#### 候选一：霜岚针林（寒冷林地）

- **景观：** 冷蓝绿色的针叶树林、覆盖薄雪的缓坡、碎石与林间空地；与暖色、阔叶感的星辉林地拉开区别。雪层使用实际方块与可读的地形，不承诺新增全维度天气或动态光照。
- **方块：** 霜杉原木、去皮原木、木板与原版常见木制建筑组合；霜杉树叶、霜藓地表块。先核对完整木材家族清单，树苗应可种植并长成，不把不可获取的自然方块当作建材。
- **植被与材料：** 矮生霜铃草、灌木状霜莓丛；霜莓既是食物原料，也可作为装饰性植株资源。现有鹿、岩羊等是否适合生成由阶段0核对，避免凭印象复制全部动物。
- **食物：** 霜莓（可直接食用）和霜莓派（由莓果与已有食材制作）。饱食度和饱和度在阶段0结合现有食品确定，首轮不承诺额外战斗增益。

#### 候选二：赭晶荒丘（干燥丘陵）

- **景观：** 深赭与灰金色层状丘陵、风蚀岩柱、裸露地表和稀疏耐旱植物。地形重点为层理与高低起伏，避免变成另一片星砾高地；岩柱应可通行且不造成大面积悬空。
- **方块：** 赭砂、赭纹岩及其平滑、砖块、楼梯、台阶、墙等建筑变体；自然块与加工块都可正常获取，纹理符合Minecraft像素风格。
- **植被与材料：** 耐旱的赭叶灌木、零散晶砂簇；采集晶砂簇获得晶砂粒，可用于染色风格的装饰方块或灯具配方。晶砂粒定位为建造材料，不追加新的装备矿级或强制养成材料。
- **食物：** 日籽荚是该地特色野生作物，成熟后收获日籽与种子；日籽可烘烤，或与已有食材制作日籽饼。耕作、各生长阶段和掉落规则需单独确认并验证。

#### 候选三：星澜浅礁（暖色浅海）

- **景观：** 面积有限的浅海与礁石，透过水面能看见蓝绿、乳白色块构成的礁体；它是星潮海域中的另一种海洋群系，仍保留现有深海和海沟。海床与海岸过渡要自然，玩家能够游入和离开。
- **方块：** 星澜礁石、孔纹礁石、礁石砖及常用建筑变体；是否需要水下生存条件按具体方块确定，放置后不能无缘无故消失。
- **植被与材料：** 礁藻和海扇状水生植被；礁藻可采集为藻叶，用于食物，也可制作可再生的装饰方块。另新增暂定名“星澜海带”的高挑海带状水生植物，自海床向上生长，自然分布于星澜浅礁和现有星潮海域的适合深度，以疏密和高度变化丰富海底景观；可采集、重新种植并作为食材，也可直接用于水下装饰。具体名称、生成密度、可生长高度及与原版海带的差异在阶段6.0确定；明确水源、支撑、生长、破坏和掉落规则。
- **食物：** 烘烤藻片，以及使用藻叶、静潮稻与已有食材制作的礁藻饭团。星澜海带也可作为食材，具体食用方式与礁藻食谱避免重复；主打探索和食物多样性，不引入强制水下呼吸机制。
- **生物：** 首轮优先复用现有适宜水域的生态；若需要原创水生动物，作为单独候选经用户确认后再建模，不自动扩大范围。

#### 通用设计和兼容要求

1. **自然生成：** 新群系要在不同种子中能被实际发现，明确温度/湿度、海陆/深度参数与周边过渡；测试原七群系仍能出现，不能让浅礁替代全部深海。先用多种子采样确定比例，再调整权重。
2. **既有系统接入：** 审核共享九种矿物、四虚卒的陆地刷怪规则、合适的原创动物、普通遗迹与遗器决斗场是否覆盖三个新群系；不能重新引入水面漂浮刷怪。海底生物和怪物规则按真实环境逐项确认。
3. **档案与导航：** 若新群系获得首次发现记录，同时更新服务端存储/同步、P界面行旅档案、进度、指南、中英文名称和`/starrail dimension locate region`；检查玩家进入新群系及定位后显示一致。
4. **方块与食物：** 配齐采集工具、战利品、合成/烧制、创造物品栏、可持续来源与中英文；新植物检查自然生成、放置条件、破坏掉落，作物各阶段紧贴耕地。建筑变体数量在资源清单中逐项列出。
5. **素材工作流：** 方块和物品贴图遵循项目内`minecraft-texture-workflow`，分类存放原稿；不假定动物、方块互动或护甲穿戴需要新增声音。新植物模型和资源须进行游戏内验收。
6. **存档与性能：** 世界生成变更只对尚未生成的新区块生效；针对已有1.27测试世界和新世界分别核对，不擅自迁移或重生成既有区块。注意群系边界、海洋/地表与洞穴分层，避免因修改共享噪声破坏现有地形。

#### 厨具与原料循环

- **共用料理台**处理炖煮、蒸制和煎制。首轮使用可重复使用的料理锅与煎盘，蒸制配方共用料理锅。料理台记录原料、容器、剩余时间和产物，服务端结算，满槽时暂停出货。界面列出所需厨具和材料。自动化为后续扩展项。
- **现有设备**继续承担工作台组装、熔炉烘烤、烟熏炉烤肉。冷调在工作台使用现成起泡水或奶霜底。饮品和汤品分别归还瓶、杯或碗，星绒羊乳使用后返还空桶。
- **本地基础食材**包括谷粉（玉米或泽米磨制）、谷面包（谷粉烘烤）、谷糖（玉米甜浆浓缩）、泽纹禽蛋（泽纹羽禽在命途遗境产出，现有蛋类用途保留）、星绒羊乳（星绒岩羊可反复采集）、谷花蜜（金风谷原蜂巢）和烘香褐果粉（暮橙果坳可再生褐果）。霜纹鲑从镜霜雪原融水池获取，碧汊萝根在荷洲种植。
- **共用中间料**包括起泡水（命途泉水与赤泉熔台可再生的泉矿料）、奶霜底（星绒羊乳、谷糖、镜霜冰）、琼脂（星澜海带煮制）、日籽油（日籽温萃）和果木香料（果园枝条烘干）。镜霜冰从雪原冻池取冰并可补水再冻，命途泉水从本地水源装取。这些中间料与饼胚均在 30 道成品之外。
- **厨房也能在本地起步。** 台体与燃料用命途遗境的木板、岩石与星炭，料理锅和煎盘用曦铁锭，木签和碗用本地木材，杯和玻璃瓶用澄溪砂熔制的玻璃。桶、工作台、熔炉和烟熏炉按需补齐本地材料配方。允许这些通用容器和设备沿用原版物品形态。7.0 需核对从本地木石到厨具的工具、采矿和燃料路径。
- **数值定位**分日常小食、主食、丰盛料理和饮品。基础数值按饱食、饱和度、制作成本、份量和容器区分。少数需要多道加工工序或跨群系取材的料理加入短时特殊效果，首轮候选见下表。
- **世界生成**先在六处生态各留一个气候区，再用多种子采样验证十个已有群系的覆盖。优先复用动物和共享矿物，维持虚卒陆地生成规则。群系同步进档案、首次发现进度、定位和双语指南。自然资源的验收在新区块进行。

## 三、技术与视觉边界

- 实施前先参考[视觉特效类型与 Forge 实现参考](../系统设计/视觉特效类型与Forge实现参考.md)，按具体效果选择粒子、网格/拖尾、shader、泛光、后处理、贴花或其他方案；不能把“技术上可能”写成“源码中已有”。
- 服务端保留伤害、命中、方块破坏等玩法权威；客户端特效仅表现已发生或已确认的事件。需要多人展示时明确事件发送范围、频率、过期时间和远距离行为。
- “材质自发光”“轮廓外泛光”“屏幕颜色/空间扰动”“实际动态光照”分别验收，不互相替代。避免为小效果无必要地启用全屏处理。
- 保留已有的基础/增强战斗表现与预览入口。每项新效果须定义关闭、不可用或粒子档位受限时的合理表现；项目的着色器包兼容不作为自动扩大范围的要求，用户提出时再纳入专门验收。
- 不把旧的效果目录当作必须实现清单；动态光照、复杂物理模拟和全局体积雾等高成本方向只有在有明确需求、可行性验证和性能预算时再单列阶段。
