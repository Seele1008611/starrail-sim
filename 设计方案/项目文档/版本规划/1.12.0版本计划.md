# 1.12.0 版本计划：遗器决斗场筛选与兼容

日期：2026-10-12。状态：1.12.0 已正式发布；用户确认整合包实机测试通过。1.11.0 已发布；本版主线是让遗器挑战在整合包中仍保持快速、可控：候选限制为原版普通敌对生物，并提供筛选诊断工具。多人游戏仍未验证。

## 一、版本目标

1. 仅从原版普通敌对生物中抽取遗器决斗场敌人，不召唤生物模组添加的怪物。
2. 保持三波、每波四只以及按发起者命途等级确定精英和奖励星级的现有规则；成功通关后将遗器奖励数量调整为随机1～3件。
3. 硬性排除苦力怕、恼鬼、幻翼、已知 Boss 和危险或无法安全生成的原版实体；数据包标签只能调整原版怪物的筛选。
4. 让管理员能查看某个实体为何入选或被排除，缩短整合包内的排查时间。
5. 保持服务端权威处理实体选择、波次、击杀和奖励。多人游戏没有测试条件时，不将其写成已通过。

## 二、开工基线与当前实现

开工前 `RelicTrialBattleService` 只把 `MobCategory.MONSTER` 作为候选，并用实体 ID 名称特征直接排除风险实体；奖励只保存一件。本轮已调整为有优先级的筛选阶段，并把候选判断、存档奖励和诊断入口接入代码。

- 当前候选强制限定 `minecraft` 命名空间和 `MobCategory.MONSTER`；`arena_allowed` 只能覆盖原版怪物的名称风险判断，不能加入模组生物或非敌对生物。
- 远程分类支持 `arena_ranged`、常见 ID 特征和 `RangedAttackMob`；诊断命令能查看筛选结论及原因。
- 每场成功奖励数量为1～3件，数量按等概率生成。每件独立生成星级、部位和词条；整组奖励在开战时存入方块实体，并兼容旧版单件奖励存档。
- 当前基础生命160、宽2.5格、高3.5格的限制维持不变；召唤前仍检查生成位置、地面支撑、碰撞和最终属性。未通过初始化的候选会跳过，不直接加入世界。

当前安全兜底阈值是基础最大生命值160、宽度2.5格、高度3.5格。它们是生成安全与挑战强度的限制，不是通用的 Boss 判定；不同模组可能有未注册为 `MONSTER` 的普通敌人，也可能有缺少 Boss 标签但强度过高的实体。

候选判断已读取三个实体类型标签，但最新规则明确：无论是否命中 `arena_allowed`，都不能将模组命名空间生物或非敌对生物加入候选池。

## 三、实体筛选规则提案

### 筛选顺序

1. **硬性排除：**Forge `forge:bosses` 中的实体，以及原版苦力怕、恼鬼、幻翼、末影龙、凋灵、监守者、远古守卫者和掠夺兽不进入候选池。`arena_allowed` 不能解除硬性排除。
2. **整合包排除标签：**`starrail_sim:arena_excluded` 优先于允许标签。整合包可以用它排除任何已知会破坏场地、脱离战斗或造成异常的实体。
3. **命名空间限制：**除 `minecraft` 命名空间外的实体一律排除；模组生物不参与随机挑战。该限制优先于允许标签。
4. **默认候选：**仅从原版 `MobCategory.MONSTER` 中选择，并继续使用保守的名称特征作为初筛。确认安全的原版怪物可用允许标签覆盖名称判断；不能用标签加入非敌对实体。
5. **远程分类：**优先使用实体类型的 `arena_ranged` 标签；实现阶段核对实体是否能可靠识别 `RangedAttackMob`，并将其用于自动分类。自定义投射物且无法自动识别的实体由整合包标签标记。实体不会因为“看起来像远程”而绕过前三层排除规则。

### 数据标签

| 标签 | 用途 | 优先级 |
| --- | --- | --- |
| `starrail_sim:arena_excluded` | 排除特定实体 | 高于 `arena_allowed`；硬性 Boss 排除同样不可覆盖 |
| `starrail_sim:arena_allowed` | 将确认安全的原版敌对生物加入候选，可覆盖名称猜测 | 不能加入模组生物/非敌对生物，也不能覆盖硬性排除、排除标签及运行时安全检查 |
| `starrail_sim:arena_ranged` | 将实体归入远程候选池 | 只影响波次类别，不改变是否允许入池 |

服务器可通过数据包为这些实体类型标签追加整合包内容。文件放在 `data/starrail_sim/tags/entity_types/` 下，例如 `arena_allowed.json`：

```json
{
  "replace": false,
  "values": ["minecraft:witch"]
}
```

整合包数据包仍可为三个标签追加实体 ID，但候选限制只允许标签调整原版敌对生物；模组实体即使出现在 `arena_allowed` 中也会被拒绝。

### 生命与体型限制

- 默认保留160点基础生命、2.5格宽、3.5格高阈值，避免本次兼容改动意外把大型或高血量强敌放进普通池。
- 三项限制通过 Forge 服务端配置开放，配置段为 `relicTrial`（单人存档位于世界 `serverconfig/starrail_sim-server.toml`；专用服务器修改对应世界的 `serverconfig` 文件）。配置项为 `maxMobHealth`、`maxMobWidth`、`maxMobHeight`，单位依次为生命值、方块宽度和方块高度：

```toml
[relicTrial]
maxMobHealth = 160.0
maxMobWidth = 2.5
maxMobHeight = 3.5
```

提高阈值可能让更强或更大的生物进入普通/精英挑战，Forge Boss、硬性排除名单仍不可绕过。
- 白名单只解决“类别/名称无法识别”的问题，不能单独放行超出配置安全限制的实体。管理员可先用诊断命令确认实体属性，再按整合包实际情况调整阈值。
- 通过 `finalizeSpawn` 后再次做实体类型、属性和场地检查。发生异常时跳过该候选并尝试下一种；一波的四只全部成功准备后再加入世界，避免半波生成。

## 四、筛选诊断

权限等级2及以上的管理员可用以下只读诊断命令：

```text
/starrail arena pool [all|normal|ranged] [page]
/starrail arena inspect <namespace:entity_id>
```

- `pool` 显示候选总数、普通/远程数量和少量实体 ID 样例；数量过多时分页，避免刷屏。
- `inspect` 输出类别、是否有 Forge Boss 标记、是否命中本模组标签、当前服务端上限、被检查实体的基础生命与体型，以及最终判断和原因，例如“允许标签”“排除标签”“类别不匹配”“超过生命值上限”。
- 诊断不生成实体、不启动战斗、不消耗奖励或材料；结果以服务端实际加载的注册表与数据标签为准。
- 标签路径、优先级、排查命令、服务端阈值配置及常见筛选原因已写入本计划与开发记录。

## 五、保留的玩法规则

- 决斗场仍为三波、每波四只。命途等级决定精英数量与强化倍率；本版不以加入 Boss 替代普通敌人。
- 每次成功通关随机掉落1～3件遗器，数量按1、2、3件等概率；全部来自本场选择的套装。每件遗器分别随机部位、星级和自身词条，星级仍按发起者开场时锁定的命途等级规则生成。本版实机验收通过，等概率规则作为1.12.0定稿。
- 奖励数量、每件遗器的随机结果和发起者命途等级都在开战时锁定并随终端保存；重进世界或服务器重启不得重新抽取。胜利时一次性结算整组奖励，失败或取消不掉落；新开一场才重新抽取，避免重试刷取和重复领奖。
- 保持现有地面掉落形式和失败清理规则；不改变单件遗器的生成规则与其他材料经济。
- 默认候选不足时允许从通过筛选的实体中重复抽取；某个实体类型初始化或场地生成失败时继续尝试池中其他类型。只有完整四只无法安全生成时才报告该波失败，不减少波次数。
- 精英仍是本场生成的临时强化实体，不修改模组全局注册属性。只统计本场实体，不把场外怪或其他装置的怪物算进波次。

## 六、验收计划

### 纯 Forge 基线

- 确认原版僵尸、骷髅、蜘蛛等安全敌人仍能被选中；三波各生成四只。
- 确认苦力怕、末影龙、凋灵、监守者、掠夺兽、远古守卫者和带 `forge:bosses` 标记的实体不会被白名单加入。
- 确认取消、召唤失败、敌人死亡和完成奖励只影响当前场次，不误计附近生物。

### 整合包兼容回归

- 在包含其他生物模组的整合包中，用 `/starrail arena pool all` 确认候选池只显示 `minecraft:` 实体。
- 用 `/starrail arena inspect namespace:entity_id` 检查模组怪物应显示“只允许原版实体”；即使命中 `arena_allowed` 也不得入池。
- 确认原版苦力怕、恼鬼、幻翼以及 Boss 排除名单中的原版生物不会出现；普通原版僵尸、骷髅、蜘蛛等仍可正常挑战。
- 观察原版敌人的生成、寻路、攻击、精英属性倍率、离场/死亡清理及奖励结算；确认挑战节奏快捷且不会出现瞬移脱场。

### 命途等级与奖励回归

- 在1、5、7级分别完成一场，核对敌人数量、精英比例、伤害/生命倍率和每件奖励的星级仍按现有规则执行。
- 确认每场胜利掉落1～3件且全部属于所选套装，件数与每件遗器的星级、部位、词条均符合锁定规则；失败或取消不掉落。
- 在开战后保存退出并重进，确认奖励数量及所有遗器结果不变；确认胜利只能结算一组奖励，场外/其他场次实体死亡时不推进本场，也不发奖励。
- 不把未经整合包测试的结果写成整合包兼容保证。多人状态与多人奖励仍标注未验证；后续有条件时再单独验收。

3. [x] 加入只读候选池、单实体诊断和分页，并显示当前筛选阈值；权限与游戏内输出待实机核对。

## 八、发布边界

- 用户已确认整合包实机验收通过；发布归档会保留本次实际验证范围，不扩大为对所有整合包或多人游戏的兼容保证。
- 候选池不会选择任何生物模组添加的实体，因此不依赖跨模组 Boss 识别；仍通过 Forge Boss 标签和原版硬性排除避免强敌进入挑战。
- 多人游戏目前缺少测试条件，1.12.0发布记录继续写明多人游戏未验证。
