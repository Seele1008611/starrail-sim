# 1.10.0 版本计划：遗器与位面饰品

日期：2026-10-10，套装效果及成长、强化与分解经济数值于2026-10-11确认。状态：1.10.0已于2026-10-12正式发布。用户确认遗器和决斗场整体实机测试大致通过；仅整合包怪物筛选与多人游戏暂时无法测试。当前正式版为1.10.0。

用户已明确：遗器分外圈四件和内圈两件，先查原作逻辑，再制定方案；用户正在准备图片。此前“先做四槽、饰品后续再做”的建议由本计划替代。**1.10.0从开始就设计六槽和两套独立套装计数。**

本次用户确认：数值防御/防御%分别映射数值护甲/护甲%；治疗量加成映射现有治疗效果；移除速度、元素伤害、能量恢复词条，护甲韧性与治疗效果加入副属性池。获取采用可选套装的波次决斗场；加入遗失晶块、遗器残骸、自塑尘脂、变量骰子、干涉密钥，以及五星合成/定向主副属性合成。干涉密钥用于指定四种副属性类型；其合成成本已确认为500遗器残骸。

## 一、调研结论：原作基础规则

这里只整理公开可核对的游戏规则，不声称取得原作内部源代码或私有随机算法。官方平台HoYoWiki用于核对套装说明；玩家资料用于补充属性与强化观察。概率权重、最新全部套装和全部高级养成功能不在本次基础规则调研的完整性承诺中。

### 1. 六个部位与套装计数

| 分类 | 部位 | 套装规则 |
| --- | --- | --- |
| 外圈：隧洞遗器 | 头部、手部、躯干、脚部 | 同套达到2件生效两件套；达到4件时同时生效两件套与四件套 |
| 内圈：位面饰品 | 位面球、连结绳 | 同套两件生效两件套，与外圈独立计数 |

外圈可4件同套，也可A套2件+B套2件；后者同时生效两个两件套。四件套中的两件效果只计算一次。外圈3件同套只达到两件效果，内圈不同套各1件没有两件效果；内外圈不能凑在一起激活套装。[HoYoWiki遗器套装库](https://wiki.hoyolab.com/pc/hsr/aggregate/artifact?crawler=Googlebot)、[Prydwen遗器基础规则](https://www.prydwen.gg/star-rail/guides/relics/)。

### 2. 主属性、副属性与强化

每件有1条主属性、最多4条互不重复的副属性。头部固定数值生命、手部固定数值攻击；其余部位主属性来自各自候选池。主属性的成长由品质及等级决定；副属性初始化和强化存在随机性。同一属性不能同时作为主、副属性，但数值生命与生命百分比属于不同属性ID，可同时存在。[Prydwen属性观察与数值表](https://www.prydwen.gg/star-rail/guides/relic-stats/)。

| 原作品质 | 强化上限 | 初始副属性条数 |
| --- | ---: | ---: |
| 2星 | +6 | 0 |
| 3星 | +9 | 1～2 |
| 4星 | +12 | 2～3 |
| 5星 | +15 | 3～4 |

每升3级发生一次副属性成长：不足4条时新增1条，已满4条时随机提升其中1条。五星对应+3、+6、+9、+12、+15；“五次成长”不等于五次强化已有词条，初始3条时第一次用于补第四条。[Prydwen遗器品质表](https://www.prydwen.gg/star-rail/guides/relics/)、[副属性升级次数说明](https://www.prydwen.gg/star-rail/guides/relic-stats/)。

原作另有定向合成及满级重掷等高级功能，基础强化规则不能概括成“所有情况下永久不能调整”。例如变量骰子可重新分配满级五星遗器副属性升级次数及数值；本版纳入自塑尘脂定向主属性合成、干涉密钥定向四种副属性类型，以及变量骰子满级五星重掷。[变量骰子游戏道具说明](https://starrail.honeyhunterworld.com/variable-dice-item/?lang=CN)。

### 3. 原作主属性候选池（调研对照，不作为本mod掉落池）

| 部位 | 原作主属性 |
| --- | --- |
| 头部 | 数值生命 |
| 手部 | 数值攻击 |
| 躯干 | 生命%、攻击%、防御%、暴击率%、暴击伤害%、治疗量加成%、效果命中% |
| 脚部 | 生命%、攻击%、防御%、速度 |
| 位面球 | 生命%、攻击%、防御%、七种元素中的某一种伤害加成 |
| 连结绳 | 生命%、攻击%、防御%、击破特攻%、能量恢复效率% |

副属性公共池：数值生命/攻击/防御，生命%/攻击%/防御%，速度、暴击率%、暴击伤害%、效果命中%、效果抵抗%、击破特攻%。原作的元素伤害、能量恢复、治疗量加成不属于这份基础副属性池。[Prydwen部位属性表](https://www.prydwen.gg/star-rail/guides/relics/)。

### 4. 套装有条件效果

套装不只有固定属性，还可能要求当前暴击率、速度、生命或某次行动达到条件。例如HoYoWiki的太空封印站说明有速度门槛，停转的萨尔索图有暴击率门槛；因此界面需要区分“件数齐了”和“附加条件已满足”。原作回合与行动类型不直接等于Minecraft秒数和普通攻击。[HoYoWiki角色页中的套装说明](https://wiki.hoyolab.com/pc/hsr/entry/28?lang=zh-cn)。

## 二、本版目标与范围

形成完整循环：**选择套装 → 决斗场波次挑战 → 获得遗器/饰品 → 六槽装备与套装搭配 → 晶块强化 → 分解重复装备 → 残骸合成/尘脂定向合成 → 满级五星可用变量骰子重掷 → 再挑战。**

必须完成：六槽、独立内外圈、二至五星遗器、主副属性、套装选择装置、决斗场及波次挑战、命途等级对应星级、强化、套装、锁定、两种分解、遗器残骸与遗失晶块、自塑尘脂、干涉密钥、五星合成及定向主/副属性合成、变量骰子与满级五星重掷、服务器结算、存档与属性来源显示、指南。

首批已确认支持2～5星，强化上限分别为+6/+9/+12/+15，内圈与外圈均适用。二星初始无副属性，+3和+6各新增1条，满级共2条；不会为了凑满4条而额外生成词条。首批暂按3套外圈、2套内圈估算，具体名单以用户图片和效果确认表为准，不把这些数量作为用户已批准的最终限制。六槽全开不等于首版要覆盖原作全部套装。

暂缓：智能装配、多套预设、新维度和新怪物。首版决斗场使用现有生物与主世界结构。速度、元素伤害和能量恢复不进入本版遗器词条及套装加成。

## 三、原作规则在本mod中的适配

### 1. 属性语义

| 原作属性 | 本mod处理 | 状态 |
| --- | --- | --- |
| 数值生命、生命% | 最大生命的数值/比例修正 | 已确认 |
| 数值攻击、攻击% | 原版攻击力数值/比例修正，并覆盖现有远程结算 | 已确认 |
| 数值防御 | 数值护甲值 | 已确认 |
| 防御% | 护甲值% | 已确认 |
| 暴击率/暴击伤害/效果命中/效果抵抗/击破特攻 | 对应现有自定义属性 | 已确认，遵守1.9.0上限 |
| 治疗量加成 | 本mod现有治疗效果 | 已确认，沿用现有作用逻辑 |

速度、元素伤害、能量恢复效率从本mod的主副属性候选池中删除，不生成、不显示无效词条。原作对照表保留用于说明适配来源；套装中涉及这些效果的条款另行改写确认，不能仍然提供被删去的属性。治疗词条统一显示“治疗效果”，不新增另一套治疗属性或改变既有治疗规则。

### 2. 本mod主属性池与副属性池

| 部位 | 主属性池 |
| --- | --- |
| 头部 | 数值生命（固定） |
| 手部 | 数值攻击（固定） |
| 躯干 | 生命%、攻击%、护甲%、暴击率%、暴击伤害%、效果命中%、治疗效果% |
| 脚部 | 生命%、攻击%、护甲% |
| 位面球 | 生命%、攻击%、护甲% |
| 连结绳 | 生命%、攻击%、护甲%、击破特攻% |

护甲韧性是否增加到球/绳主属性池尚未确认，本版确认池先不加入；用户明确要求的护甲韧性与治疗效果进入副属性池。

副属性公共池：

- 数值生命、生命%；数值攻击、攻击%；数值护甲、护甲%。
- 暴击率%、暴击伤害%、效果命中%、效果抵抗%、击破特攻%。
- 护甲韧性：提供数值护甲韧性与护甲韧性%，两者为不同词条ID，成长数值见已确认的独立数值表。
- 治疗效果%。

副属性最多4条，不重复同一词条ID、不与主属性ID相同。数值与百分比属性仍允许同时存在；数值护甲韧性与韧性%并存同样适用。新增副属性属于本mod适配规则，界面使用实际属性名称。

### 3. 数值与结算边界

独立数值已由用户确认，见[1.10.0遗器属性成长与强化数值表](../系统设计/1.10.0遗器属性成长与强化数值表.md)，包含品质成长公式、主副属性数值与权重、每级经验、材料返还、变量骰子规则和现有成长组合。同步到HTML和游戏前仍需确认决斗场奖励与难度；当前HTML演示值不能直接当成正式平衡数据。

- 不搬用原作数百生命、数百攻击的绝对值；Minecraft玩家基础生命20、攻击1、护甲2、韧性1，需制作独立的品质×等级成长表。
- 首批数值表要用空手、普通武器、下界合金装备、七级命途、满行迹、光锥及满极境组合检查，不能只对裸玩家调数值。
- 保持1.9.0命途与极境攻击力的合并规则；遗器采用稳定AttributeModifier提供额外修正，不调用setBaseValue，不修改指令或存档基值。
- 明确遗器比例加成与现有命途/光锥的加法和乘法关系。实现前给出数值例子与确认表；UI展示主副属性来源，最终值与/attribute get一致。
- 暴击率、效果命中、效果抵抗上限100%，不转化溢出；暴击伤害、击破特攻、治疗效果保持1,000,000%上限。
- 百分比词条不重复写“按百分点”，但系统帮助中保留比例修正与概率直接相加的区别。
- 增减最大生命不得反复切装刷治疗、护盾或丰饶践行度。生命超过新上限时只裁剪，增加上限不自动满血；裁剪不算敌对伤害。

## 四、装备与存档

### 1. 六个装备槽

沿用项目必需的Curios，新增六个命名专属槽，每槽1件；光锥槽保持现状。建议命名relic_head、relic_hands、relic_body、relic_feet、planar_sphere、link_rope，统一使用本mod校验和标签。

遗器与原版盔甲、光锥同时生效；不是穿在原版盔甲格中的防具，不提供耐久消耗或盔甲模型。不同部位不能跨槽装备，位面球不能塞入连结绳槽；装在背包、快捷栏或错误Curios槽不生效。

装备物品保存在Curios真实库存中，专属遗器页面只是同一库存的操作入口，不能另存一套副本。装备替换、卸下、背包满、死亡掉落、keepInventory、重登和切维度按实际库存处理，禁止复制或凭空删除。

### 2. 每件独立物品

最大堆叠1。使用NBT保存：数据版本、套装ID、部位、星级、等级、经验、主属性ID、最多4条副属性及成长记录、锁定状态、物品实例ID。成长记录区分初始/补充词条的基础值与后续强化增量，另存重掷次数、待选择结果及操作版本。

一套物品的图像和名称是定义数据，同部位的不同掉落拥有不同词条，不能每次开界面重新随机。强化结果、等级和经验立即随物品保存；变量骰子依据成长记录重掷已有词条的强化分配，候选结果也随物品保存，关闭界面或重登不能重新抽取。

坏数据必须校验星级/等级/词条池/主副互斥/重复词条/数值范围；缺字段按版本迁移，未知套装显示可读提示且不生效，不让旧存档崩溃。

### 3. 属性与套装刷新

服务器根据六槽内容汇总，稳定修正ID按槽位/效果确定；装备变化、强化和登录重新计算，未变化不反复加修正。离线/卸装清理失效修正，属性模板保留默认值，绝不再次引入1.9.0的登录基值覆盖问题。

套装按外圈、内圈分别计数，所有命途均可装备。命途切换不删除装备，也不按命途封锁通用套装。触发效果由独立服务记录冷却，换装不反复刷新一次性奖励；卸下后移除该套装授予的状态，保留其他系统的同类效果。

条件增益应采用明确的计算依据，避免“增益提高属性→跨门槛→增益失效”的循环；需要区分持续条件与触发时快照。近战与远程、直接伤害/持续伤害/附加伤害必须有归属标记，防止套装附伤递归触发自己。

### 2. 获取方式：套装选择决斗场

遗器主要来源改为独立小型决斗场，不再以九命途遗迹首次宝箱/重复监守者奖励作为本版接入口。既有遗迹继续提供原有材料与钥印循环，行迹材料30%掉率、30秒重复挑战冷却不变。

**流程：进入决斗场 → 与中央装置交互 → 选择外圈/内圈套装 → 查看命途等级对应奖励和挑战预览 → 开始 → 清完各波敌人 → 击杀最后一只 → 掉落所选套装遗器。**

#### 场地与中央装置

- 主世界小型封闭场地，中央装置兼作套装选择、开始挑战和场次状态入口；外圈及内圈套装均可选择。
- HTML建筑参考采用25×25格总占地、2格厚围墙、21×21格室内净空；墙体高7格，四角3×3塔楼高9格，顶部开放。
- 北墙中央留5格宽、4格高门洞；下方设置5扇深色橡木栅栏门，逐扇打开后可通过，关闭时阻挡普通地面怪物。内部放置3×3中央装置台座、四向召唤点和南侧安全交互区。地坪用磨制安山岩，墙体用石砖，塔楼/立柱用深板岩砖，地面轨道用暗海晶石，照明用海晶灯与末地烛；HTML施工清单用磁石作中央装置的原版示意核心。
- 建造顺序参考：铺设25×25基础地坪与墙基 → 砌墙并留出门洞 → 安装栅栏门 → 叠四角塔楼 → 安装灯具和中央台座。首版建议用可放置/生成的固定结构样板验证，不依赖新维度或自然生成；尺寸与入口可在实机中调整。
- 每场固定3波、每波4只，共12只敌对生物。使用现有生物，不新增专属怪物；按命途等级安排近战、远程和精英单位，难度与奖励档在开场时锁定。具体配置见下方提案。
- 套装选择不受当前命途限制，玩家可以刷与未来搭配有关的套装；无命途玩家可查看和管理装备，建议踏上命途后才能开始挑战。
- 初版同一装置只运行一场，活动中不可改套装、重复开启或叠加生成；完成/失败后允许重新选套装并重复挑战。

#### 波次与难度（提案）

难度只按发起者开始挑战时的当前命途等级决定，不动态读取队伍中最高等级，也不根据装备临时升档。普通单位沿用原版属性；精英单位从同一批现有敌对生物中选取，以临时生命值和攻击力倍率区分，并有清楚的名称/外观提示。不增加专属怪物、特殊AI或场地破坏机制。每波始终4只，清完后短暂停顿再生成下一波。

| 命途等级 | 难度档 | 第1波 | 第2波 | 第3波 | 精英单位倍率（生命 / 攻击） |
| --- | --- | --- | --- | --- | --- |
| 1～2级 | 入门 | 4普通 | 3普通 + 1远程 | 2普通 + 2远程 | 无 |
| 3～4级 | 进阶 | 4普通 | 2普通 + 1远程 + 1精英 | 1普通 + 1远程 + 2精英 | ×1.5 / ×1.2 |
| 5～6级 | 高阶 | 2普通 + 1远程 + 1精英 | 1普通 + 1远程 + 2精英 | 1普通 + 3精英 | ×2.0 / ×1.3 |
| 7级 | 极境 | 1普通 + 1远程 + 2精英 | 1普通 + 3精英 | 4精英 | ×2.5 / ×1.4 |

普通单位优先从适合封闭场地的近战生物中选，远程位使用骷髅或掠夺者一类的现有远程敌人；不使用会炸毁场地的苦力怕。精英只是同种生物的强化版本，不额外占用名额。此倍率是首轮平衡起点，需通过一次完整的1级、5级和7级实机挑战检查击杀时长、死亡风险与药水/护盾消耗，再决定是否调整；中间等级按对应档执行。

#### 整合包模组生物兼容（提案）

决斗场不依赖具体生物Mod，也不把所有注册实体无筛选地加入战斗。Forge 的实体类型注册表可以读取当前整合包已加载的实体类型；首轮候选池以 `MobCategory.MONSTER` 为基础，混入通过安全筛选的原版与模组普通敌对生物。[Forge 注册表文档](https://docs.minecraftforge.net/en/1.20.1/concepts/registries/)说明了注册对象按注册表统一管理；1.20.1 的 [MobCategory API](https://mcstreetguy.github.io/ForgeJavaDocs/1.20.1-latest/net/minecraft/world/entity/MobCategory.html)包含 `MONSTER` 分类。

- 默认排除原版末影龙、凋灵、监守者、苦力怕，以及带有BOSS标记、超出建议生命值/体型上限、不能在场地安全生成或初始化失败的实体。生命值和体型仅作兜底筛选，不能单独作为BOSS判定。
- 通过服务器配置和整合包数据包可追加的实体类型标签提供 `starrail_sim:arena_excluded`、`starrail_sim:arena_ranged`、`starrail_sim:arena_allowed` 名单；Forge 支持为实体类型使用数据包标签。[Forge 标签文档](https://docs.minecraftforge.net/en/1.20.1/resources/server/tags/) 玩家无需每次挑战时管理实体ID。排除名单优先级最高；白名单可将已验证的普通怪物加入候选池，但不能绕过BOSS硬排除。
- 近战候选从合格普通敌对生物池抽取；远程位优先识别 `RangedAttackMob`，并允许通过标签标记使用自定义投射物的模组怪物。远程池不足时从普通池补位，保证仍为每波4只。
- “精英”是本场生成的临时强化实例，不改写模组全局属性。对远程投射物也要按本场归属处理伤害倍率；无法可靠识别攻击来源或有场地破坏/异常传送等特殊机制的实体不进入默认池。
- 每只召唤实体记录本场实例和发起者，波次只统计本场实体，挑战结束/取消只清理本场剩余怪物；模组怪物不能被其他场次误计或通过死亡事件重复发奖。候选池不足时允许重复抽取已通过筛选的普通怪，不降低每波数量。

兼容边界：没有一个所有生物Mod都遵守的通用“这是BOSS”标志，因此不能承诺自动识别每个模组的BOSS。默认黑名单、特征筛选和整合包白/黑名单组合能覆盖常见情况；特殊实体仍需整合包配置排除。具体属性阈值先作为服务器配置项，不在首轮写死成跨整合包通用常数。

#### 星级按当前命途等级决定

已确认原则：包含二星遗器，一级最多三星，五级及以上保证五星。以下概率为奖励提案，保证每次完整通关获得1件所选套装遗器；同一场的星级在开场时按当前等级分布锁定，失败不发奖，重试视为新场次重新抽取：

| 开始挑战时当前命途等级 | 每次通关遗器星级（建议） |
| --- | --- |
| 未踏上命途 | 不开始挑战 |
| 1级 | 2星50%、3星50% |
| 2级 | 3星80%、4星20% |
| 3级 | 3星40%、4星60% |
| 4级 | 4星80%、5星20% |
| 5～7级 | 5星100% |

读取的是发起者当前命途等级，不取九命途中历史最高等级。场次开始保存套装、发起者、等级档、已抽定的遗器星级与战斗难度；中途切命途/升级/重登不改变本场档位，也不重新抽取奖励。重复开场才使用新的当前等级。

#### 掉落与成功结算

- 建议每次通关保证1件所选套装中的遗器，外圈在四部位中抽取，内圈在两部位中抽取；初版部位等概率，主副属性权重单独配置。数量与概率可配置但必须让UI预览一致。
- 最后一波最后一个有效敌人由合法参战玩家击杀时，服务器在其死亡位置生成真实遗器掉落，套装不再随机抽成另一套；不额外直接发背包第二份。
- 先生成并保存一次性奖励结果，再标记已结算；死亡事件重复、保存重进、区块加载都不能重复抽奖/掉落。
- 非死亡移除、区块卸载和暂时找不到实体不能被当作清波或通关。最后一个敌人由环境或非参战玩家击杀时不发通关奖励，提示本场未达成，清理后可重新挑战；避免留下永久忙碌场次。
- 默认每场发起者1份奖励；帮打不额外复制奖励。同一装置并发点击、掉落归属、他人拾取保护需服务端处理。多人个人奖励模式后续再扩展，不能读取帮打者等级抬高星级。

#### 中断、失败与重试

- 波次按本场登记的敌人UUID推进，不将附近普通怪、宠物或其他决斗场怪算进去。召唤失败不先消耗波次。
- 参战者死亡、主动退出或离场超时判失败，无通关掉落；建议离场宽限10秒，避免边缘短暂移动立即失败。
- 保存退出/区块卸载暂停场次，不计离线时间为清波；加载后恢复登记状态，无法可靠恢复的场次取消、清理残留并提示重试，不发成功奖。
- 清理只针对本场生成实体，不批量清除附近普通怪或玩家建筑。异常状态应允许装置恢复空闲，不会反复补怪、卡在一波或永远不能再开。

### 3. 强化、两种分解与定向合成

遗器经验与玩家经验等级分开。品质决定等级上限；主属性按表增长，跨多个3级节点时逐个处理，补词条与提升已有词条不能漏算或重复算。随机结果在服务器保存，客户端展示变化。

#### 五种材料的职责

| 材料 | 获取 | 用途 |
| --- | --- | --- |
| 遗失晶块 | 分解遗器 | 提供遗器强化经验 |
| 遗器残骸 | 选择五星遗器的残骸分解 | 合成五星遗器、自塑尘脂、变量骰子 |
| 自塑尘脂 | 消耗遗器残骸合成 | 在合成五星遗器时指定主属性 |
| 变量骰子 | 消耗遗器残骸合成，成本见下表 | 重掷+15五星遗器的副属性强化分配与增量 |
| 干涉密钥 | 消耗较多遗器残骸合成，成本见下表 | 合成五星遗器时指定四种副属性类型；数值档位仍随机 |

二星、三星、四星分解为遗失晶块；五星分解时明确二选一：遗失晶块或遗器残骸。不能同时领取两份基础分解收益。锁定、已装备遗器不能分解/作为消耗；先卸下或解锁。批量分解五星时选择统一模式并展示总收益，确认后再结算。

#### 合成流程

- 普通合成：选择已开放套装、部位，消耗遗器残骸，获得1件+0五星遗器；主属性在该部位合法池中随机，副属性按五星规则生成。
- 主属性定向合成：选择套装、部位和主属性，消耗普通合成所需残骸及1个自塑尘脂；主属性确定，副属性仍随机。
- 副属性定向合成：使用1个干涉密钥，从合法词条中指定4种互不重复的副属性类型；定向成品在+0时生成这4条指定词条，词条数值档位仍按现有概率随机，+3至+15强化落点仍随机。可不使用尘脂，此时主属性随机；同时使用尘脂与干涉密钥时，可一起指定合法主属性和四种副属性类型。
- 副属性选择必须排除与主属性相同的属性ID。若主属性随机，服务端从未被四种指定副属性占用的合法主属性中抽取；头部/手部固定主属性不能被选入副属性。
- 头部/手部主属性固定，直接用普通合成；不消耗尘脂重复指定固定主属性。
- 不能选择本版不存在的速度、元素伤害或能量恢复词条；不因接口字段存在而开放无效选项。
- 自塑尘脂和干涉密钥均为定向合成的额外材料，不替代普通残骸成本；未具备全部材料时不先扣任何一种资源。强化、分解、合成均为一次服务端库存事务，防止连续点击和旧请求重复消费/发货。

#### 材料经济数值（沿用此前核对方案）

| 项目 | 建议基础数值 |
| --- | --- |
| 1个遗失晶块 | 100遗器经验 |
| +0二星分解为晶块 | 1个（与三星同为最低整数收益） |
| +0三星分解为晶块 | 1个 |
| +0四星分解为晶块 | 3个 |
| +0五星分解为晶块 | 5个 |
| 五星选择分解为残骸 | 10个遗器残骸 |
| 普通五星合成 | 100个遗器残骸 |
| 合成1个自塑尘脂 | 200个遗器残骸 |
| 合成1个变量骰子 | 300个遗器残骸（本mod成本提案） |
| 合成1个干涉密钥 | 500个遗器残骸（用户已确认） |
| 定向五星合成 | 100个遗器残骸+1个自塑尘脂 |
| 定向四种副属性类型的五星合成 | 100个遗器残骸+1个干涉密钥 |
| 同时定向主属性和四种副属性类型 | 100个遗器残骸+1个自塑尘脂+1个干涉密钥 |
| 每次有效重掷 | 1个变量骰子，保留旧结果也不返还 |

已强化遗器选择晶块模式时，建议返还基础晶块加上投入强化经验的80%，新增晶块数向下取整：`基础晶块数 + floor(投入经验 × 0.8 / 100)`。投入经验包含当前等级间的进度，不包含物品自身基础分解价值，禁止把返还奖励再记成投入经验。

五星选择残骸模式时，固定10残骸，不另返已投强化经验；界面明确显示将放弃的经验。强化过的遗器更适合晶块模式，未强化重复五星更适合残骸模式。满级返还结果已按80%折算并由用户确认，详见独立数值表。

各等级升级经验已另列于[属性成长与强化数值表](../系统设计/1.10.0遗器属性成长与强化数值表.md)；不能用玩家经验条代替。分解→合成→再分解必须净消耗材料，晶块与残骸不提供免费互换。五种材料贴图已完成，不混用九命途行迹材料。

### 4. 变量骰子：满级五星副属性重掷

变量骰子纳入本版，外圈遗器和内圈饰品均支持。仅+15五星可操作，二至四星及未满级五星不可使用；不开放副属性种类定向。

- 保持套装、部位、星级、等级、经验、主属性和四条副属性的种类不变；保留各条初始/补充时的基础值，重新随机分配已有强化次数及每次增量。
- 初始3条的五星在+3补第四条，剩余4次为强化；初始4条的五星有5次强化。重掷沿用该物品实际次数，不把补词条节点变成额外强化，也不把上次重掷后的总值当作新的基础值叠加。
- 消耗1个骰子生成1份候选结果，逐条展示旧值、新值、变化及强化次数，玩家选择“保留原结果”或“采用新结果”。保留原结果仍消耗本次骰子；之后再次重掷需另付1个。
- 建议操作前卸下装备并解锁，界面明确说明；候选待确认期间该物品不能装备、强化、分解、合成消耗或再次重掷。最终确认后解除操作限制，重新装备时刷新属性来源。
- 服务器先校验物品实例、版本、资格、词条记录与材料，再在同一次库存事务中扣骰子并保存候选；重复请求不重复扣除或生成结果。校验失败不扣材料。
- 关闭界面、断线或保存重进后继续显示同一候选及原结果；返回页面仍可二选一。重开界面不能免费刷新候选，不默认覆盖原结果；保存恢复需同时保留骰子扣除与候选状态。
- 重掷不提供经验、不提高等级、不改变分解的基础价值与投入经验记录；不新增返还骰子或残骸的渠道。

变量骰子使用规则进入本版范围；上述残骸合成来源与300残骸成本为本mod适配方案，不代表原作配方，沿用此前核对的材料经济表。

## 九、验收清单

- 六槽部位限制、替换/卸下/背包满、普通盔甲与光锥共存。
- 外圈4件同时生效2+4；外圈2+2分别生效；内圈2件独立，内外不混计；重复修正不叠加。
- 同品质等级主属性一致；随机词条无重复/主副冲突；固定值与百分比按不同ID处理。
- 强化跨3级节点、上限、补第四条与提升已有条、材料不足、锁定材料、结果保存。
- 二星初始0条，+3/+6各新增1条，+6共2条且不可继续升级；内外圈均可掉落、装备、强化及分解。
- 变量骰子只用于+15五星；初始3/4条分别保留4/5次强化总数，四条种类与基础值不变，增量不反复叠加。
- 新旧结果可选择，保留旧结果仍扣1个骰子；重进恢复同一候选，材料不足/无效请求不扣除，重复点击只扣一次，待确认物品不能转入其他操作。
- 换装与最大生命变化不会刷血/护盾/践行度；伤害加成适用于定义中的近战与远程，不递归。
- 指令修改基础属性后换装/重登不覆盖；显示与服务端一致；卸下清除本系统修正。
- 决斗场套装选择、内外圈奖励、波次清场、最后击杀掉落正确；一级不掉四/五星，五级以上每次必掉五星。
- 开始锁定等级档，途中切命途/升级/重登不抬高奖励或重抽；同场只结算一次，非参战者/环境末击及非死亡移除不误发奖。
- 死亡/退出/离场超时、区块卸载和重登能恢复或取消场次，装置最终可再挑战；残留怪只按本场清理。
- 主副属性不生成速度/元素/能量，护甲韧性和治疗效果副词条确实生效且显示正确。
- 五星晶块/残骸二选一、经验折算、尘脂/干涉密钥制作、普通与定向主副属性五星合成正确；定向副属性只锁定词条类型，不锁定数值档位或强化落点。
- 固定主属性不浪费尘脂、材料不足不部分扣除、并发点击不复制；分解/合成循环无材料套利。
- 死亡/keepInventory/重生/重登/切维度遵循实际库存，不产生双份装备。
- 无命途也能管理遗器；命途切换保留装备但重新计算条件效果。
- 小窗口、GUI缩放、长数值、中文/英文、滚动与提示不挡操作。
- 整合包怪物筛选与多人游戏暂时无法测试；不声称这两项已验证。
