# 1.4.0 规划与验收记录

> 状态：1.4.0 已于 2026-10-06 发布。五个客户端页面的改版、动效与分辨率适配通过玩家最终手动验收；发行 JAR 离线构建成功。试炼规则和奖励未纳入本版。完整结果见 [验收清单](1.4.0UI最终手动验收.md) 与 [发行归档](../../releases/1.4.0.md)。

## 版本主题

打磨命途试炼的完整体验，并重做主要界面的视觉层次与分辨率适配。延续原版 Minecraft 的操作习惯和《崩坏：星穹铁道》的克制科幻风格；先完成设计与验收标准，再逐项决定实现内容。

### 设计边界

- 保留已经通过测试的寻迹、凭证、初始试炼、自动踏上命途和晋阶规则。没有明确缺陷时不改玩法判定与奖励数值。
- 不增加新的命途、遗迹大类、复杂战斗机制或多人承诺；本版优先完善已有内容。
- UI 先制作 HTML 视觉稿并审阅，再实现。HTML 样稿用于确认层级和布局，不替代游戏内不同分辨率验收。
- 仅测试本版实际改动涉及的内容，并对关键流程做必要回归；不重复没有改动的已通过项目。

## 工作方向一：命途试炼流程打磨

沿着当前玩家流程逐步核对提示和状态反馈：

`选择命途 → 确认开始寻迹 → 获取锚点 → 找到对应遗迹并打开宝箱 → 使用匹配凭证 → 完成试炼并自动踏上命途 → 继续积累实践度与晋阶`

计划先审查，再决定修复范围：

- 命途界面与命途指南是否准确说明寻迹、凭证要求、目标、时限、失败重试和试炼成功后的自动结果。
- 寻迹中、坐标已找到、寻迹失败、凭证不匹配、试炼进行中、超时和完成等状态，是否都给出清楚且不互相矛盾的反馈。
- 十种遗迹的宝箱内容、命途凭证与指南说明是否一致。先形成对照清单；如需调整奖励，先提交数量和获取概率方案供审阅，不直接改掉落。
- 确认普通遗迹自然生成、变体寻迹、凭证消耗和晋阶反馈的既有边界仍然清晰。

本方向默认是说明、信息呈现和确切缺陷修正，不预设增加新试炼或改变既有数值。

## 工作方向二：主要 UI 视觉与自适应布局

当前界面使用至少 800×450 的共用逻辑画布，并包含紧凑布局、分栏、正文滚动和长文本适配；内容面板宽高上限为 1100×600，超宽及较高窗口居中布局。最终验收检查内容拥挤、留白、导航层级和实际点击位置。

### 计划覆盖范围

- 角色详情
- 属性页面
- 光锥页面
- 命途页面
- 命途指南
- 与命途寻迹有关的常驻坐标/状态提示（只在确认需要调整后纳入）

### 视觉方向

- 建立清楚的标题、分区、卡片、正文和次要说明层级，让玩家更快找到当前状态与主要操作。
- 保留统一的面板、边框、按钮和字体规则；命途色彩与纹样作为小范围强调，避免每个页面像不同模组拼在一起。
- 优先使用已有图标、纹理和原版字体资源；若需新增美术资源，先在视觉稿展示并单独确认清单。
- 控制背景装饰和动效，不遮挡文字、图标、物品格和鼠标提示；维持 Minecraft 可读性与输入反馈。

### 自适应目标

- 以 Minecraft 的 GUI 缩放后可用宽高计算布局，并分别设计宽屏、常规和紧凑布局；窄屏需要重排导航与内容，不能挤压成难读的窄栏。
- 长内容统一使用鼠标滚轮连续浏览与滚动条，保留栏目切换；不再使用上一页、下一页按钮拆分同一栏目正文。按钮和关键状态不能被裁切，也不能互相覆盖。
- 窗口尺寸或 GUI 缩放变化后，当前页面仍保持可操作；中英文长文本都要检查换行和溢出。
- 设计稿和实测记录标明物理分辨率、GUI 缩放值及游戏实际 GUI 尺寸，避免只用一个截图判断适配。

### UI 验收标准

- 主要页面布局一致、信息层级清楚，九条命途可辨认但不依赖颜色单独区分。
- 小窗口、常见 16:9 和较宽/较窄比例下均无文字裁切、按钮重叠、控件出界或无法触达的内容。
- 改变 GUI 缩放或窗口大小后，导航、分页/滚动、物品交互、鼠标提示和关闭操作仍可用。
- 中文和英文页面分别检查；页面关键信息完整、可读，且与实际玩法状态一致。

## 建议实施阶段

1. **现状盘点**：对照 1.3.0 正式版，列出现有试炼信息反馈和各页面的已知布局问题；只记可复现问题，不先改代码。
2. **HTML 视觉稿**：按用户补充的原作 UI 视频先制作可交互的原作参考稿，审阅构图与动效后，再把命途页和命途指南作为模组稿的代表页面，展示共用组件与宽屏/紧凑布局。
3. **审阅与冻结**：确认视觉方向、响应式规则、需要修改的页面及奖励是否真的要调整。
4. **分批实现**：先调整共享 UI 样式与窄屏导航，再逐页迁移，确保每批结果可单独观察。
5. **定向验收**：按记录的 GUI 尺寸、缩放和窗口比例测试布局，并手测本次涉及的寻迹—凭证—试炼状态反馈。

## 暂不纳入

- 新增命途或扩展到新的 Minecraft 基础版本。
- 未审阅的奖励重平衡、凭证规则改动和试炼目标改写。
- 多人流程承诺。多人支持范围尚未确定，另行讨论后再列入版本计划。
- 仅因 Mod 小版本变化而安排旧存档升级专项测试；跨 Minecraft 基础版本时再规划兼容性验证。
