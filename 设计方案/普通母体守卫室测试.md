# 1.2.0 守卫室原型与验收记录

实现日期：2026-10-02。普通母体与九种命途变体均已接入守卫机制。普通母体自然生成和生存流程已由玩家验收；九种变体的机制与奖励映射检查已完成，存护变体另通过玩家实战验收。保护范围复测见文末 2026-10-03 记录。

## 创建测试样本

建议使用开启作弊的新创造存档。在附近区块加载完成、周围没有其他遗迹的位置执行：

```mcfunction
/difficulty normal
/starrail ruin place ordinary ~ 200 ~
```

这里 `~` 使用当前 X/Z，避免把遗迹放到未加载的 `0 0` 区域。锚点 Y=200 时，完整结构处于合法建筑高度范围。命令仍会检查区块、占用与遗迹间距；若失败，请按提示换空地。等待放置完成后，按输出的实际锚点 X/Z 飞到主殿。

### 定位自然生成的普通母体

自然生成验收请在主世界的新区块附近（推荐新建测试存档）执行：

```mcfunction
/starrail ruin locate ordinary
```

命令按距离逐个检查遗迹自然生成候选点，只在结构记录确认内部变体为普通母体时返回锚点和传送指令；存护、毁灭等其他九种变体会跳过。搜索范围是当前位置周围八个结构间距区段，且会逐步加载候选区块，因此可能生成一些原本未加载的区块；命令不会强制放置遗迹。成功后按提示传送，等结构区块加载完成，再执行 `/starrail ruin guard_status` 检查守卫登记。该命令仅限主世界及有权限的测试玩家使用。

自然生成现已固定为普通母体；九种命途版本由寻迹系统放置。修改只对新生成区块生效，旧区块中已生成的命途变体不会自动替换。若测试区域此前已被定位命令扫描过，请先传送到未探索区域（建议距旧测试点至少 20,000 格）再运行定位命令。

若搜索结束仍未命中，结尾会显示已检查区块数、有效遗迹起点数、遗迹结构片数、跳过的其他变体数和区块请求失败数；请保留这条结果，便于区分“附近没有生成遗迹”和定位筛选未识别结构。

如需停止后续扫描，执行：

```mcfunction
/starrail ruin locate ordinary cancel
```

停止扫描后，已经提交给 Minecraft 的当前候选区块请求仍可能完成并保存。如果八个区段内没有找到普通母体，命令会结束并提示换一片区域重新搜索。

宝箱相对锚点是 `(0,10,-21)`，监守者初始脚部是 `(-2,8,-10)`，门洞位于 `Z=-18`、`X=-2…2`、`Y=8…12`。

靠近遗迹后执行只读命令：

```mcfunction
/starrail ruin guard_status
```

该命令报告水平 160 格内最近的已登记守卫室、绑定 UUID、奖励状态和门格处理进度。

## 分步验收

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 检查主殿、门、箱子与监守者 | 与 HTML 布局一致，只有一只命名的原版监守者；门为 25 格铁栏杆 |
| 2 | 绕到宝箱室直接右键宝箱 | 提示先击败本座守卫，不打开容器 |
| 3 | 尝试破坏箱子与门、旁边放箱子、用爆炸破坏 | 未击败时箱子与门受保护，不允许合并成大箱 |
| 4 | 箱子下方接漏斗并等待 | 击败前没有任何遗迹奖励可提取；漏斗本身无需禁止放置 |
| 5 | 退出重进；远离再返回；观察超过一分钟 | 未击败状态与绑定 UUID 保留，不重复刷守卫，也不因卸载/空闲解锁 |
| 6 | 切到生存并击败守卫 | 使用原版战斗能力，死亡确认后开门、提示解锁，可正常领取原战利品 |
| 7 | 再次退出重进、远离再返回 | 保持已击败与解锁状态，不补守卫，不刷新奖励 |
| 8 | 开空箱子再等待、再重新载入 | 箱子保持取空，战利品表不会重复绑定；获胜后允许破坏/自动化取物 |
| 9 | 用另一座新样本切到和平再切回普通 | 和平清除不算击败，不发奖励；切回普通后补回单个守卫 |
| 10 | 生存模式尝试挖穿宝箱室侧墙、后墙、地面或顶面，再试挖遗迹其他普通石英墙 | 宝箱室六面外壳不能破坏，遗迹其他普通方块仍可破坏；未击败守卫仍不能开启宝箱 |
| 11 | 创造模式破坏门栅与宝箱室外壳；另用新样本测试破坏宝箱后再击败守卫 | 创造模式能破坏受保护方块；若守卫仍未击败，切回生存依旧不能获得奖励；击败守卫后缺失的宝箱会恢复并绑定对应战利品表 |

可以用创造模式检查和改建结构，再用生存完成战斗。未击败时受保护方块的爆炸防护仍生效。原版监守者的击退与音波攻击保留，入口通过性和实战体验需要游戏内确认。

## 数据与兼容

- 世界内新增按维度保存的 `starrail_sim_ruin_guards` 数据，记录锚点、监守者 UUID、击败状态、奖励绑定状态及开门进度。
- 新普通母体使用独立的 `ordinary_guard.json.gz`；旧结构片缺少 `Guarded` 标记时继续读取原 `ordinary.json.gz`，不自动修改已有遗迹。
- 击败前宝箱不绑定奖励表，阻止挖墙与漏斗提前取得奖励。奖励沿用 `chests/ruin_ordinary`，不改原战利品分布。
- 生存模式下，门、宝箱和宝箱室六面外壳在守卫未击败前受保护；外壳相对锚点位于 X=-12/12、Y=7/24、Z=-26/-18 六个面，密室外的普通遗迹方块仍可破坏。创造模式可破坏这些受保护方块。
- 固定名称与持久标记用于阻止监守者空闲钻地消失，不改其属性、装备、AI 或技能。
- 本原型不承诺跨崩溃时刻的实体文件与世界数据原子保存；正常退出重进属于本次验收范围。

### 本次修复

最初测试发现守卫约数秒便钻地消失，随后补刷，导致 UUID 不稳定。原因是直接创建实体时漏执行原版出生初始化，`DIG_COOLDOWN` 记忆没有建立。修复为调用原版 `finalizeSpawn`；加载早期原型标记守卫时补齐缺失的原版冷却记忆。固定名称与持久标记继续保留，不增加 buff 或修改战斗属性。

### 验证范围

以上验证针对普通母体的命令放置样本与机制状态。生存完整战斗和自然生成样本已由玩家手测通过。低入口通过性、旧版存档升级、独立服务端及多人仍需专门验收。伤害命令死亡测试不替代生存战斗体验验收。

## 玩家验收补充（2026-10-03）

- 玩家反馈命令放置样本的生存实战测试通过；当时自然生成普通母体仍待验证（后续结果见本节末尾），旧版存档升级、独立服务端及多人仍未验收。
- 旧版测试中，玩家用 `/locate structure starrail_sim:ordinary_floating_ruin` 找到智识变体：青金石装饰、蓝色玻璃和演算内饰，未出现守卫。这是旧代码曾让自然生成随机选择十种蓝图造成的；不能据此判定守卫登记失效。
- `/locate structure` 只按结构注册名定位，不筛选内部变体。当前代码已改为自然生成只用普通母体；普通母体使用绿色海晶石装饰，新版主殿有低入口与后方铁栅门。九种命途版本由寻迹系统放置。只有未探索新区块会使用此更新规则，旧区块中的结构不会自动替换。

- 首次手测在多个相距数千格的位置均未命中。修正版诊断显示 289/289 个候选区块都存在有效遗迹起点及遗迹结构片，但全部为其他命途变体、区块请求无失败。原因是自然生成曾随机抽取普通母体与九种命途变体，与“普通母体自然生成、命途变体由寻迹放置”的规划不符。现已固定自然生成使用普通母体；旧区块不自动替换，修复后需在未探索新区块验证（此项已于下文通过）。

### 宝箱室保护与创造模式破坏（2026-10-03，复测通过）

- 旧版保护只覆盖宝箱和门格，遗迹其他石英方块可在生存模式破坏；即使挖穿进入密室，未击败守卫时宝箱交互仍被取消，且没有战利品表，因此不能取得凭证。
- 已调整代码：未击败守卫时，生存模式还会保护宝箱室六面外壳，范围为相对锚点 X=-12/12、Y=7/24、Z=-26/-18 六个面；密室外的普通遗迹方块仍可破坏。爆炸也会过滤这些外壳方块。
- 创造模式的方块破坏不再受门、宝箱和密室外壳保护影响。创造模式仍不能在守卫未击败时打开宝箱；若测试中创造模式破坏宝箱，击败守卫后系统应补回宝箱并绑定战利品表。
- 隔离客户端复测通过：欢愉变体锚点 `(16000, 200, 4000)`；生存模式对宝箱室边界石英砖 `(15988, 209, 3979)` 持续挖掘后，方块仍在。创造模式破坏门栅 `(16000, 209, 3982)` 成功；击败前右键宝箱收到锁定提示；创造模式拆除宝箱 `(16000, 210, 3979)` 后，击败守卫时宝箱恢复。
- 恢复后的宝箱 NBT 战利品表为 `starrail_sim:chests/ruin_elation`；守卫状态为已击败、奖励已解锁、门格 `25/25`。该验证确认破坏宝箱不会绕过战斗领取奖励，并且胜利后能恢复正确变体的宝箱。
- 当时的隔离客户端测试没有正向验证密室外普通遗迹方块在生存模式下可破坏；随后由玩家另行验证通过，详见下方补充记录。此前 2026-10-02 记录中“创造破坏后箱子仍存在”描述的是旧版行为，不代表本次变更后的行为。
- 测试仅在独立 QA 存档中进行，没有修改其他存档；守卫由测试命令击败，因此本轮验证的是保护与恢复机制，不代替自然战斗体验测试。

### 普通遗迹方块生存破坏正向验证（2026-10-03）

- 玩家在隔离存档 `Variant_Guard_QA_20261003` 的普通母体新样本中手测，锚点为 `(0, 200, 10000)`；此前位于 `(0, 200, 0)` 的位置因 400 格间距检查被拒绝，没有在该处放置结构。
