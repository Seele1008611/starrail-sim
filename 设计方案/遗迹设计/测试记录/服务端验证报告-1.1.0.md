# StarRail Sim 1.1.0 服务端验证记录

- 日期：2026-10-01
- 环境：Minecraft 1.20.1、Forge 47.4.13、Java 17；Curios 5.14.1
- 测试包：`starrail_sim-1.1.0.jar`
- 测试包 SHA-256：`2F53072D409F58E8176E8B553C23D2E060302383C528CF5AB1F42F1AFD50BE2B`
- 新世界：`starrail_worldgen_test`，seed `20261001`，开启结构生成

## 结果

- 专用服务端正常完成启动并进入 `Done`；`/starrail ruin` 与 `/starrail path` 命令均已注册，Curios 成功加载。
- `/locate structure starrail_sim:ordinary_floating_ruin` 找到候选锚点 `X=-576, Z=176`。将附近区块载入后，区块 NBT 中确认存在遗迹结构起始记录及宝箱；宝箱坐标 `(-568, 236, 163)`，战利品表为 `starrail_sim:chests/ruin_elation`。因此确认这次是实际写入新世界的自然生成，不只是 locate 返回候选坐标。
- 结构集限制为主世界，生成阶段为 `surface_structures`；结构放置代码将遗迹底缘设在至少 `Y=151`，实测宝箱位于 `Y=236`。
- 结构集使用 `random_spread`，`spacing=64`、`separation=25`。随机偏移范围最多为 38 个区块，两个相邻区域的候选锚点最小间隔为 26 个区块，即 416 格；超过 400 格要求。寻迹放置另外使用持久化锚点数据，以水平距离 400 格做拒绝检查。
- 首次冷态 locate 用时约 31.6 秒；区块已生成后的重复查询用时 0 毫秒。首次冷态扫描产生一次服务器落后警告，属于新地形计算负载；不是重复查询的常态耗时。
- 测试结束时移除 42 个强制加载区块，执行 `save-all flush` 并正常停止服务端；日志确认主世界、下界和末地均完成保存。`latest.log` 无 ERROR/FATAL。`debug.log` 中有 Windows WMI/Netty Java 反射探测警告，但没有阻止服务端启动或关停。

## 结论

本次 1.1.0 候选包的专用服务端加载、命令注册、主世界自然生成、浮空高度、宝箱战利品表及 400 格遗迹间距配置均通过静态配置与运行数据核对。测试世界与临时服务端已在验证后清理。
